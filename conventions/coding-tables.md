**编号真源仍是 [coding.md](coding.md) §3.5。** 编码轮默认只开 coding.md §0；扫 §1 / §2 / 重构条件时再开本页。

## 1. 设计模式：场景 → 运用

按**你正在做的事**匹配，不要先想模式名。多行都像时取消最重的那条（Factory 重于 switch；Adapter 重于再抄 Client）。  
产品类名不进本表。当前产品的对照在该仓 `.idev/pack/`。

| # | 场景信号（看到 / 正在做） | 运用 | 不要 |
|---|--------------------------|------|------|
| P1 | 同一字面量、展开规则或校验出现第 3 次 | **静态工厂**，入参非法立刻抛 | 每处 `if` + 配置默认值；两行 `currentX` 再包一层 |
| P2 | 创建方式互斥（要来源 vs 按 ID 不设来源） | **两个工厂**，名字说出差异 | 一个 `of(..., null)` 两种语义 |
| P3 | 要换下游协议，调用方不该知道 SDK / Feign | **Adapter**，公开接口挡住 | Controller / 页面 `new XxxClient`；再袋一层同名字段 |
| P4 | 追加「通过后做什么」，主流程不该改 | **多例 SPI / Strategy** | 换整个 Service；为复用垂直叠基类 |
| P5 | 按类型选算法，已有 ≥2 分支且还会增 | **一处 Strategy 或经典 switch** | 页面和 Controller 各写一份；为 1 个实现抽 `IXxx` |
| P6 | 只有一种实现 | **具体类型** | `IXxx`、Abstract Factory、「预留扩展点」 |
| P7 | 给所有业务请求加身份头 / 鉴权，不改 URL | **一条 Decorator**（拦截器） | 第二套 HTTP 客户端；拦截器里按 URL 猜业务 query |
| P8 | 编排 / 管道里「一步调用」 | **Command**（已有步骤类型） | 在 Action 里再解析平台或抄请求上下文 |
| P9 | 身份多种来源依次试 | **已有 Chain**，不要再写一条 | 产品仓第二套 SSO 解析 |
| P10 | 入站转发下游 | **已有 Proxy** | 产品仓第二套网关 |
| P11 | 回放要原请求 | **已有 Memento**（快照） | 回放再猜默认身份 / 配置 |
| P12 | 翻页直到结束 | **Template 跟类型走** | 每个 list 手写 `while`；页码起点对不齐 |
| P13 | 真树（分类 / 菜单）要走子节点 | **Composite** 只用于真树 | 给扁平列表硬套 Composite |
| P14 | 不可变查询字段多、有不变量 | **Builder**（已有 Lombok 才用） | 2 个字段也上 Builder；无 lombok 硬加 |
| P15 | 缺值也当成功往下走 | **禁止** Null Object / 空省略 | `if (x) 带上`；返回 `{}` / `[]` 假装成功 |
| P16 | 两条通道职责不同（query vs 头、HTTP vs 快照） | **保持两条**，不要合成 | Facade / 拦截器按 URL 自动塞查询字段 |
| P17 | 「看起来重复」但省略规则相反 | **不是重复** | 为少写几次调用去做 URL 分类器 |

文件名按**做什么**取，不堆 `StrategyFactoryImpl`。零命中 P1–P17 → 写直白代码。

## 2. Clean Code：气味 → 纠正

编码每写一处、Review 逐条扫。命中 = 当轮改。

| # | 气味信号 | 纠正 |
|---|---------|------|
| C1 | 函数能用「并且」说出两个变更理由 | 拆开。工厂不要同时「展开来源」和「按 ID 不设来源」 |
| C2 | `if (有值) 带上; else 省略/默认` | 必要约束改为立刻抛错 / 400。禁止猜配置默认值、空对象 |
| C3 | 两行函数只转一手再 `export`（`currentX` → `withX`） | 删包装，调用方直接 `requireX`，或只留一个会失败的入口 |
| C4 | 入参名与出参名相同但语义不同 | 入参改名。禁止页面传出参列表名 |
| C5 | 注释仍写「遗留 / 只接头 / 以后」，代码已不是这样 | 改注释或删。产品仓不写第二份契约长文 |
| C6 | 未使用的 import / 方法 / 字段 / 导出 / 注释掉的代码 | 当场删。禁止「以后用」 |
| C7 | `catch` 后 `return []` / `{}` / `false` 吞掉失败 | 该失败就抛或 4xx/5xx。读路径「一行脏数据留空」只适用于**已规定**的列表行，不是入口校验 |
| C8 | 布尔参数切换两种创建 | 改成两个命名工厂 |
| C9 | 嵌套超过两层 `if` | 卫语句提前返回 |
| C10 | 同一魔法字符串出现第 2 次 | 收到工厂或已有常量。不要新开「工具类」只为拼字符串 |
| C11 | Controller / Mapping / 页面在做角色推断、健康度、就绪 | 搬回类型方法。Mapping 只做形状 |
| C12 | 名字是 `util` / `helper` / `manager` / `data` / `tmp` | 按职责改名。做不出名字 = 职责不清，先拆 |
| C13 | 函数既校验又补默认 | 只校验。默认只允许写在 `setup` / `DEFAULTS` 的**显式配置**，禁止请求期猜 |
| C14 | Review 只写「能跑 / 自测绿」 | 必须有 §1 命中行和 §2 已扫。只记账未改 = 拒过 |
| C15 | 公开 API 形状与契约字段不一致 | 跟 Service 同名。不要为「更好懂」发明第二套 UI 词 |

清晰 = 读代码能说出失败条件与合法字面量。  
明确 = 名字与契约同一字符串，两种创建两条路。  
简洁 = 没有包装、没有预置模式、没有过期注释、没有未引用符号。

## 2.4 量化阈值（可测量硬线）

§2 是气味判断（要读代码），本节是**可测量的粗筛线**：超线只是"停下来看"的信号，命中后仍按 §2 判定并译成 `C#` 记账，**不另起严重度码表**（守 §3.5）。粗筛线本身不是拒过理由——能说清为何这段必须长/深，就写进 `review.md`；说不清就是真命中。

| 指标 | 硬线 | 测量方法 | 超线 → 落编号 |
|------|------|----------|---------------|
| 函数长度 | ≤ 20 行（含空行/注释） | 单函数实际行数 | 多为「并且」职责 → **C1** 拆开 |
| 嵌套深度 | ≤ 2 层（沿用 idev，比 20 行更硬） | `if`/`for`/`while`/`try` 最大嵌套层数 | **C9** 卫语句提前返回 |
| 参数数量 | ≤ 3 个 | 函数签名参数数（不含 this/receiver） | 多为多职责或缺值对象 → **C1**；互斥创建 → **C8** |
| 圈复杂度 | ≤ 10 | 独立分支路径数（`if/case/&&/||/catch` +1） | 拆函数 / 提策略 → **C1** / **P5** |
| 重复代码 | 第 3 次即 0 容忍 | 同一逻辑出现次数 | **C10**（字面量）/ **P1**（构造）/ §3 R5 提取 |

**嵌套以 C9（≤2 层）为准，不采纳 aisel 的 ≤3。** 两者冲突时 idev 更严的线优先。  
函数临界（21–25 行）且单一职责、无嵌套超标：允许，`review.md` 写一句为何不拆。**没有理由的超线 = C# 命中，当轮改。**

Java 圈复杂度看 Qodana / IDE Problems 报告的方法复杂度；前端看 eslint `complexity` 规则（若仓内已配）。**未配工具不硬造**——人工数分支即可，别为量这条新引一套扫描器（守 §3.7）。

## 3. 重构（Fowler：满足条件 + 经验）

定义：**在保持可观察行为不变的前提下，改进内部结构。**  
目标是让下一步改动更容易，不是为了「看起来更面向对象」。本页 §1/§2 管「写成什么样」；本节管「何时、在什么护栏下改结构」。

思想来源：Martin Fowler《Refactoring》（含 Kent Beck「两顶帽子」与 Rule of Three）。不要把全书手法目录抄进产品仓；手法服务气味，气味见表 §2。

### 3.1 满足条件（同时成立才戴「重构帽」）

缺任一条 → **不准**宣称在重构：先补条件，或改成显式的「加功能 / 修缺陷」轮次。

| # | 条件 | 怎么判定 | 不满足时 |
|---|------|----------|----------|
| R1 | **有自检护栏** | 本轮触及面有可自动跑、自己断言结果的测试（单测 / 契约测 / 已有 verify case）；每步后能快速重跑 | 先补最小护栏再动结构；无护栏的大范围整理 = 拒过 |
| R2 | **行为目标不变** | 对外契约、返回、副作用、错误语义本轮不故意改；只动结构与命名 | 需要改行为 → 换「加功能帽」，先写/改测试再实现 |
| R3 | **两顶帽子不混戴** | 同一提交/同一小步：要么只重构，要么只加功能/修 bug，不穿插 | 拆成两轮：先重构到易改，再做行为变更 |
| R4 | **小步且步步绿** | 一次一个手法级改动（抽函数、移字段、改名…）；每步后测试仍绿 | 步子太大就回退拆步；红灯时不准叠下一步重构 |
| R5 | **由变更驱动** | 因要加功能、修 bug、需要理解代码、或 Rule of Three 第三次重复而改 | 「闲得发慌顺手美化」、无消费方的预抽公共 = 不做 |
| R6 | **先理解再动** | 能说出这段现行行为与失败条件；看不懂先读/补测，不靠重构来猜 | 先表征行为（测/日志/对照契约），再结构 |

截止日期紧且 R1 不成立 → 只做最小必要改动，把重构列为后续项；**禁止**无护栏的大爆炸整理。

### 3.2 何时做 / 何时不做

| 做（经验） | 不做 |
|------------|------|
| **预备式重构**：先让「改动变容易」，再做那个容易的行为改动（Beck） | 在烂设计上硬堆功能，下一步更难 |
| **Rule of Three**：同一逻辑第三次出现再提取（与文首 YAGNI 一致） | 第一次就上抽象 / 框架「以备将来」 |
| 修 bug：先写能复现的失败测试，再必要时重构暴露点，再修 | 未复现就大范围「清理」 |
| Code Review / 自审发现 §2 气味，且本轮就要改这处 | 气味在不动的模块里，只为评分去改 |
| 营地规则：离开时比来时略干净（触及面内） | 顺手重构 `arch.yaml` 未 `include` 的文件 |
| 性能：先测量，再只动热点 | 无数据的「优化式重构」 |

程序能跑且长期不会改 → **不必**重构。重构服务变化，不服务完美。

### 3.3 经验对照（接到本页 §1 / §2）

| 经验 | 落到本页 | 备注 |
|------|----------|------|
| 两顶帽子 | R3；念头表「顺便调结构再加功能」 | review 须写本轮戴的是哪顶帽子 |
| 测试是前提 | R1；出门清单 §3 | 不要求全仓完美覆盖，要求**触及面**可红可绿 |
| Rule of Three | 文首 YAGNI；P1；R5 | 与「第三次才抽」同一裁决，禁止提前 SPI |
| 预备式重构 | 加功能前先扫 §2，小步消挡路气味 | 预备重构仍须 R1–R4 |
| 气味 → 手法 | §2 命中当轮改；典型对应：C1→抽函数/拆职责；C3→内联包装；C9→卫语句/抽方法；C10→常量/工厂；C12→改名/搬移 | 不背手法名录；不会做的手法用 IDE 安全重命名/抽取 |
| 营地规则 | 只动 `include: true` 触及面 | 与 deliver `code` 范围一致 |
| 重构不修行为 bug | 修 bug 换加功能帽；重构只保现有行为（含既有缺陷语义时先用测试钉住） | 既有错误要改行为时，先钉测试再改 |
| 性能与重构分离 | 先正确清晰，热点证明后再优化 | 「更快」不是戴重构帽的理由 |

### 3.4 重构出门（写进 `review.md`）

- [ ] 写明动机（预备哪次行为改动 / 哪条 §2 气味 / Rule of Three）
- [ ] R1–R6 均满足；写了护栏是什么（测类名或 verify case）
- [ ] 本轮未混加功能；若有行为变更，已拆开描述
- [ ] 步步绿；最终 Problems / `qodana.starter` 或 `lint-fix` 无本轮黄条

## 3.6 提升向（执法之外）

本页是**护栏**，不教现代语法课。要补「语法特性 / 模式选型 / 重构手法」时，另开学习向 Skill（与本页并行，不替代门禁），例如本机已装的 jabrena/plinth 系列：`141-java-refactoring-with-modern-features`、`123-java-design-patterns`、`121-java-object-oriented-design`。  
学习产出若要落地到交付，仍须过 §0–§3 与 `check-feature code`。

**禁止把学习向语法当交付默认：** compiler=8 的仓不得因装了 plinth `141-java-refactoring-with-modern-features` 就写入 `record` / `var` / text block / `List.of`。学习 Skill 只开在「明确升级语言级别」的票里；日常 code 以 [java.md](java.md) 语言级别为准。

## 3.8 增强扫描（外挂 Skill，仍回写本页编号）

本页 §1/§2/§3 仍是**执法真源**。下面 Skill 只加强「怎么扫」；命中必须译成 `P#` / `C#` / `R#` 写入 `review.md`，禁止另起严重度码表替代编号。

### 规程（`code` 阶段写完自测前）

1. 跑 `bash ~/.cursor/skills/idev/scripts/coding-scan.sh <repo根>`，按输出打开指南。
2. **必开**：本页 §1/§2；（有结构调整再开 §3）。入口决策仍看 [coding.md](coding.md) §0。
3. **必开**：`code-review-and-quality` 五轴（正确性 / 可读性 / 架构 / 安全 / 性能）。
4. **按栈打开** `code-review-skill` 指南（compiler=8 Java → `reference/java8.md`；Vue → `vue.md`；Go → `go.md`）+ `common-bugs-checklist.md`。
5. 触及身份 / 输入 / 出站 / 密钥 → 再开 `security-and-hardening`；Java 可叠 plinth `124-java-secure-coding`。
6. 测试已绿、只想减复杂度 → `code-simplification`（行为不变；仍须满足 §3 R1–R6）。
7. 跑 Problems / `qodana.starter` 或前端 `lint-fix`；仓内若有 Checkstyle/PMD/SpotBugs 一并跑（§3.7）。
8. `review.md` 写清：五轴结果、栈指南名、增强扫描是否已跑；气味/场景仍用本页编号。

### 严重度（外挂标注 → 本页动作）

| 外挂标注 | 本页动作 |
|----------|----------|
| blocking / 🔴 | 当轮必须改；对应 `C#`/`P#`；未改 = `code` 拒过。`review.report` 记入 `I*`「待签收」，本步不改 |
| important / 🟡 | 当轮改或写明基线外 UNRELATED；不可只记账。`review.report` 同上，记入 `I*` |
| nit / suggestion / 🟢💡 | 可记「已扫无 must」；不准冒充零扫描 |
