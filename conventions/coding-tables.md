## 1. 设计模式：场景 → 运用

按**你正在做的事**匹配，不要先想模式名。多行都像时取消最重的那条（Factory 重于 switch；Adapter 重于再抄 Client）。  
产品类名不进本表。当前产品的对照在该仓 `.idev/pack/`。

| # | 场景信号（看到 / 正在做） | 运用 | 不要 |
|---|--------------------------|------|------|
| P1 | 同一字面量、展开规则或校验出现第 3 次 | **静态工厂**，入参非法立刻抛 | 每处 `if` + 配置默认值；两行 `currentX` 再包一层 |
| P2 | 创建方式互斥（要来源 vs 按 ID 不设来源） | **两个工厂**，名字说出差异 | 一个 `of(..., null)` 两种语义 |
| P3 | 要换下游协议，调用方不该知道 SDK / Feign | **Adapter**，公开接口挡住 | Controller / 页面 `new XxxClient`；再袋一层同名字段 |
| P4 | 追加「通过后做什么」，主流程不该改 | **多例 SPI / Strategy** | 换整个 Service；为复用垂直叠基类 |
| P5 | 按类型选算法，已有 ≥2 分支且还会增 | **一处 Strategy 或经典 switch**（Java：多例 SPI / 经典 `switch`；Go：表驱动 `map[Kind]func`；Vue/TS：对象字面量查表 + `computed`） | 页面和 Controller 各写一份；为 1 个实现抽 `IXxx` |
| P6 | 只有一种实现 | **具体类型** | `IXxx`、Abstract Factory、「预留扩展点」 |
| P7 | 给所有业务请求加身份头 / 鉴权，不改 URL | **一条 Decorator**（拦截器） | 第二套 HTTP 客户端；拦截器里按 URL 猜业务 query |
| P8 | 编排 / 管道里「一步调用」 | **Command**（已有步骤类型） | 在 Action 里再解析平台或抄请求上下文 |
| P9 | 身份多种来源依次试 | **已有 Chain**，不要再写一条 | 产品仓第二套 SSO 解析 |
| P10 | 入站转发下游 | **已有 Proxy** | 产品仓第二套网关 |
| P11 | 回放要原请求 | **已有 Memento**（快照） | 回放再猜默认身份 / 配置 |
| P12 | 翻页直到结束 | **Template 跟类型走** | 每个 list 手写 `while`；页码起点对不齐 |
| P13 | 真树（分类 / 菜单）要走子节点 | **Composite** 只用于真树 | 给扁平列表硬套 Composite |
| P14 | 不可变查询字段多、有不变量 | **Builder**（已有 Lombok 才用） | 2 个字段也上 Builder；无 lombok 硬加 |
| P15 | 缺值也当成功往下走 | **禁止** Null Object / 空省略。返回端：查无结果按契约返回业务空集或抛错，禁返回 null；传入端：契约不给 null 合法席位，可选缺参走 P2 工厂 | `if (x) 带上`；返回 `{}` / `[]` 假装成功 |
| P16 | 两条通道职责不同（query vs 头、HTTP vs 快照） | **保持两条**，不要合成 | Facade / 拦截器按 URL 自动塞查询字段 |
| P17 | 「看起来重复」但省略规则相反 | **不是重复** | 为少写几次调用去做 URL 分类器 |
| P18 | 布尔业务规则长成巨型条件方法，或被上移应用层留下纯数据对象 | **Specification**：谓词形式的显式 VALUE OBJECT，可组合 | 规则内联进被约束对象；挪出领域层 |
| P19 | 组合 / 推导操作的参数、返回类型拖入外来概念 | **闭合操作**：返回类型与参数类型（含实现者）相同，优先 VALUE OBJECT；凑不成全闭合时，多出的类型须是基本类型 / 基础库类 | 为消除依赖把接口削成只剩基本类型 |

文件名按**做什么**取，不堆 `StrategyFactoryImpl`。零命中 P1–P19 → 写直白代码。

## 2. Clean Code：气味 → 纠正

编码每写一处、Review 逐条扫。命中 = 当轮改。

| # | 气味信号 | 纠正 |
|---|---------|------|
| C1 | 函数能用「并且」说出两个变更理由 | 拆开。工厂不要同时「展开来源」和「按 ID 不设来源」 |
| C2 | `if (有值) 带上; else 省略/默认`; `case/default` 把未列值当合法缺省 | 必要约束改为立刻抛错 / 400；`default` 只承载显式合法缺省，否则报未知值。禁止猜配置默认值、空对象 |
| C3 | 两行函数只转一手再 `export`（`currentX` → `withX`） | 删包装，调用方直接 `requireX`，或只留一个会失败的入口 |
| C4 | 入参名与出参名相同但语义不同 | 入参改名。禁止页面传出参列表名 |
| C5 | 注释仍写「遗留 / 只接头 / 以后」，代码已不是这样；注释里写署名 / 修改人 / 历史记录 / 条目编号 | 改注释或删。产品仓不写第二份契约长文；元数据 git 已有，注释不重复 |
| C6 | 未使用的 import / 方法 / 字段 / 导出 / 注释掉的代码；生产符号（函数 / 类 / 方法）仅被测试引用、无生产调用路径 | 当场删。禁止「以后用」；仅测试引用的投机符号连同其测试一并删——测试辅助 / fixture 及断言直接触达的目标除外 |
| C7 | `catch` 后 `return []` / `{}` / `false` 吞掉失败 | 该失败就抛或 4xx/5xx。读路径「一行脏数据留空」只适用于**已规定**的列表行，不是入口校验 |
| C8 | 布尔参数切换两种创建 | 改成两个命名工厂 |
| C9 | 嵌套超过两层 `if` | 卫语句提前返回 |
| C10 | 同一魔法字符串出现第 2 次 | 收到工厂或已有常量。不要新开「工具类」只为拼字符串 |
| C11 | Controller / Mapping / 页面在做角色推断、健康度、就绪 | 搬回类型方法。Mapping 只做形状 |
| C12 | 名字是 `util` / `helper` / `manager` / `data` / `tmp` | 按职责改名。做不出名字 = 职责不清，先拆 |
| C13 | 函数既校验又补默认 | 只校验。默认只允许写在 `setup` / `DEFAULTS` 的**显式配置**，禁止请求期猜 |
| C14 | Review 只写「能跑 / 自测绿」 | 必须有 §1 命中行和 §2 已扫。只记账未改 = 拒过 |
| C15 | 公开 API 形状与契约字段不一致 | 跟 Service 同名。不要为「更好懂」发明第二套 UI 词 |
| C16 | 跨环境代码用某环境独有特性，或为适配差异扩散出平台分支 | 只用各目标环境共同支持的子集，不靠扩大平台差异适配 |
| C17 | 环境差异散布成函数体内条件分支（含条件编译） | 收拢为类型 / 构造期选择或独立实现文件，每条分支可测 |
| C18 | 跨进程 / 系统交换数据直接依赖内存布局（指针、字段顺序、对齐、字节序） | 用显式定义的交换格式；字节序与版本写进格式 |
| C19 | 资源获取与释放不在同一抽象层次，释放散落多处；状态修改与复原不同层 | 同层成对：由获取方释放，或显式移交所有权；释放必须显式（close/release），且覆盖所有路径（含异常 / 提前返回），不依赖 GC/finalizer 隐式清理；do/undo 同层，复原正确性用等式或测试证明能回到原状态 |
| C20 | 迭代 / 递归的收敛依赖隐式状态变化，说不出「每步严格变小」 | 写每步严格变小的论证（进度度量写在注释或测试）；写不出就改结构化遍历，不用裸 while 猜收敛 |
| C21 | 效果函数（落库 / 发布 / 写状态）里夹带业务计算；或查询函数（返回值）夹带可观察副作用（发通知 / 写日志 / 改共享状态） | 拆纯函数：计算进纯函数可单测，效果函数只留一行副作用（赋值 / 发布 / 落库）；命令/查询分离：方法要么是查询（返回值、不改状态、可安全重复调用），要么是命令（改状态、不返回值），不能既返回值又改状态；查询函数夹带可观察副作用（发通知 / 写日志 / 改共享状态）时拆成查询（返回值、无副作用）+ 修改（副作用、不返回值），缓存等不可观察副作用豁免 |
| C22 | `a.getB().getC().doSomething()` 跨对象链式取值 | 直接协作者提供服务方法，让对象自己干活，不让调用方替它挖内部；确需穿层，按纯数据结构对待并显式声明 |
| C23 | 多步调用，后步依赖前步留下的隐式状态才能正确 | 每步产出显式化，作下一步入参；顺序约定写进契约，先看签名就知道必须什么顺序、传什么 |
| C24 | 一个函数里业务概念语句与语法 / 协议语句混排 | 按层级拆函数：高层说业务，低层说语法，读高层函数像读目录 |
| C25 | 领域概念以裸 `string` / `number` 传播（金额、ID、电话、日期范围）；同生共死字段在 ≥2 处签名反复出现 | 判据「删一项、其余失义」成立 → 建领域类型 / 值对象，校验、归一、格式进类型；概念不建双轨（T5） |
| C26 | 测试体写成剧本：多方向塞一个测试；五行 setup 只为一个断言；断言消息读不出输入与期望 | 一测一方向；最小声明，一行验证胜过五行 setup；命名 `Test_<函数>_<情形>`（不被调用，可长而具体）；错误消息含 Input/Expected/Actual；用最简输入覆盖同一分支 |
| C27 | 继承只为复用代码而非 is-a 行为多态；层级超两层；子类覆写丢弃 / 弱化基类已实现行为，或覆写收窄前置条件、放大返回 | 复用走组合 / 依赖 / 聚集；is-a 成立才继承且子类必须能完整实现父类行为；覆写守约：前置条件只能更宽松、返回只能更窄；层级 ≤2；尽量不覆写基类已实现方法 |
| C28 | 测试套件头重脚轻：端到端 / 全链路测试堆成冰筒，单元测试反而最少；全量慢、随机挂、没人敢常跑 | 按金字塔配比：下层比上层多一个数量级；端到端只留低两位数核心场景，测场景而非逐条故事；失败自上而下定位，护栏修到最低层可快速重跑 |
| C29 | 脆弱测试被容忍：随机失败重跑即过、被注释 / 跳过 / 长期红灯，团队习惯性忽略 | 随机失败当轮处理：要么修稳，要么移出套件并记录处理，用更小范围测试取代；被习惯性忽略的红灯比没有测试更糟 |
| C30 | 过度 mock：mock 协作对象的行为实现，断言绑定内部交互细节，一重构就碎 | 打桩优先：stub 供状态 / 应答，不验交互；mock 只验对外副作用（请求是否被正确发出） |
| C31 | 密钥 / 凭证硬编码或与被保护数据同库、全体服务共享一套凭证；敏感信息（密码、凭证、个人数据）明文进日志；自研加密算法 / 哈希 / 安全协议 | 密钥独立于代码与数据存放（密钥库 / 环境注入），每服务自己的凭证，泄露只撤销受影响一组；先定哪些数据可入日志，落盘前剔除敏感字段；只用平台内建 / 公认加密实现（实现不好的加密比没有更糟） |
| C32 | 构造器 / 初始化中调用可覆写（可被子类 override 的 virtual）方法，子类字段未初始化即执行子类版本，读到默认值（0 / null / 空） | 初始化期间只调 `final` / `private` / 本类明确不可覆写的行为；确需初始化逻辑，抽到 `final` 方法或显式 `init` 流程，不在构造器里触碰子类可覆写行为 |
| C33 | 复杂循环（累积器 / 游标 / 状态机 / 多步状态）说不出「每轮保持什么为真」（循环不变式） | 先写出循环不变式（注释或测试断言），必要时连同前置 / 后置条件；写不出就简化循环、拆函数，或改用结构化遍历 / 现成算法，不靠裸 while 猜正确性 |
| C34 | 循环变量被闭包 / goroutine / defer 捕获，读到的不是当轮值（而是循环结束后的终值） | 循环体内显式拷贝循环变量（`dir := dir`）或把循环变量作参数传入；不把循环变量地址塞进稍后执行的函数值 |
| C35 | 表达式依赖运算符隐式优先级 / 求值顺序，读代码需查表才能确定含义；同一表达式里多次读写同一变量且顺序未定义 | 加括号或拆临时变量，让求值顺序显式；副作用与读取分离（先读后写或先写后读，不混在同一表达式） |
| C36 | 条件 / 布尔上下文里把赋值 `=` 写成比较 `==`（或反之），编译器不报错但语义相反 | 显式比较；确需「赋值并判断」时拆成两步或显式 `(x = y) != 0`；常量放比较左侧让误写编译期暴露 |
| C37 | 整数运算可能溢出（signed 溢出未定义 / 静默回绕），累加、乘法、下标、长度计算无边界检查 | 用更大类型 / 显式溢出语义 / 边界检查；对不可信输入先校验范围再运算；不靠静默回绕当正确 |
| C38 | 库 / 模块代码自行终止进程（`os.Exit` / `log.Fatal` / `System.exit` / `process.exit`），或把 panic / 异常当普通控制流（用 panic 替代 return error） | 库函数 / 公有 API 把失败作为 error / 异常向上传播，终止只发生在入口（main / 顶层命令）；panic 只用于不可恢复的 bug，recover 只恢复本包可预期的 panic 值，其余继续 panic |
| C39 | 持有资源 / 身份 / 锁的类型被按值复制（文件句柄、连接、互斥锁、goroutine 状态），导致双重释放 / 状态不同步 / 锁失效 | 持有资源 / 身份 / 锁的类型用引用 / 指针语义，禁止按值复制（或显式标记不可复制）；值语义类型（内置类型 / 不可变结构）才可安全复制。判断「能否安全复制」依据类型的本质（是否持有外部资源 / 身份），不依据方法是否修改接收者 |

清晰 = 读代码能说出失败条件与合法字面量。  
明确 = 名字与契约同一字符串，两种创建两条路。  
简洁 = 没有包装、没有预置模式、没有过期注释、没有未引用符号。

## 2.4 量化阈值（可测量硬线）

§2 是气味判断（要读代码），本节是**可测量的粗筛线**：超线只是"停下来看"的信号，命中后仍按 §2 判定并译成 `C#` 记账，**不另起严重度码表**（守 §3.5）。粗筛线本身不是拒过理由——能说清为何这段必须长/深，就写进 `review.md`；说不清就是真命中。  
前五行审**单个函数**，其后各行审**本轮 diff**（变更级，接 [coding.md](coding.md) 文首底线与规范总则），测量与判定同一套。

| 指标 | 硬线 | 测量方法 | 超线 → 落编号 |
|------|------|----------|---------------|
| 函数长度 | ≤ 20 行（含空行/注释） | 单函数实际行数 | 多为「并且」职责 → **C1** 拆开 |
| 嵌套深度 | ≤ 2 层（沿用 idev，比 20 行更硬） | `if`/`for`/`while`/`try` 最大嵌套层数 | **C9** 卫语句提前返回 |
| 参数数量 | ≤ 3 个 | 函数签名参数数（不含 this/receiver） | 多为多职责或缺值对象 → **C1**；互斥创建 → **C8** |
| 圈复杂度 | ≤ 10 | 独立分支路径数（`if/case/&&/||/catch` +1） | 拆函数 / 提策略 → **C1** / **P5** |
| 重复代码 | 第 3 次即 0 容忍 | 同一逻辑出现次数 | **C10**（字面量）/ **P1**（构造）/ §3 R5 提取 |
| 净增行数 | 说得出换来什么（消重 / 收拢 / 新基线行为） | `git diff --stat` / 票内 diff 汇总 | 多为包装 / 预置模式 / 未引用 → **T1** / **C3** / **C6** |
| 单文件长度 | ≤ 400 行（含空行/注释） | 该文件行数 | 多职责堆在一个文件 → **C12** / **C1** |
| 本轮新增文件 | 每个新文件一种职责，且被本轮基线 item 用到 | `git diff --stat` 里新增的文件 | 预置、无引用 → **T1** / **C6** |
| 本轮触及文件 | 每个文件说得出为何必须动 | diff 文件列表 | 说不出的列入 UNRELATED，不准顺手改 → **C12** |
| 单文件变更理由 | = 1（一个文件只为一种理由改） | 本轮触及文件按变更理由分组 | 一文件多理由 → **C12**（职责）/ **C1**（拆轮次） |

**嵌套以 C9（≤2 层）为准，不采纳 aisel 的 ≤3。** 两者冲突时 idev 更严的线优先。  
函数临界（21–25 行）且单一职责、无嵌套超标：允许，`review.md` 写一句为何不拆。**没有理由的超线 = C# 命中，当轮改。**

Java 圈复杂度看 Qodana / IDE Problems 报告的方法复杂度；前端看 eslint `complexity` 规则（若仓内已配）。**未配工具不硬造**——人工数分支即可，别为量这条新引一套扫描器（守 §3.7）。

## 3. 重构（Fowler：满足条件 + 经验）

定义：**在保持可观察行为不变的前提下，改进内部结构。**  
目标是让下一步改动更容易，不是为了「看起来更面向对象」。本页 §1/§2 管「写成什么样」；本节管「何时、在什么护栏下改结构」。

思想来源：Martin Fowler《Refactoring》（含 Kent Beck「两顶帽子」与 Rule of Three）。不要把全书手法目录抄进产品仓；手法服务气味，气味见表 §2。

### 3.1 满足条件（同时成立才戴「重构帽」）

缺任一条 → **不准**宣称在重构：先补条件，或改成显式的「加功能 / 修缺陷」轮次。

| # | 条件 | 怎么判定 | 不满足时 |
|---|------|----------|----------|
| R1 | **有自检护栏** | 本轮触及面有可自动跑、自己断言结果的测试（单测 / 契约测 / 已有 verify case）；每步后能快速重跑 | 先补最小护栏再动结构；护栏补不进（类进不了测试用具、依赖难伪装）时，先经接缝手法保守解依赖（保持行为、签名保持、不顺带清理）再特征测试，解依赖步按无护栏小步从简从保守；无护栏的大范围整理 = 拒过 |
| R2 | **行为目标不变** | 对外契约、返回、副作用、错误语义本轮不故意改；只动结构与命名 | 需要改行为 → 换「加功能帽」，先写/改测试再实现 |
| R3 | **两顶帽子不混戴** | 同一提交/同一小步：要么只重构，要么只加功能/修 bug，不穿插 | 拆成两轮：先重构到易改，再做行为变更 |
| R4 | **小步且步步绿** | 一次一个手法级改动（抽函数、移字段、改名…）；每步后测试仍绿 | 步子太大就回退拆步；红灯时不准叠下一步重构 |
| R5 | **由变更驱动** | 因要加功能、修 bug、需要理解代码、或 Rule of Three 第三次重复而改 | 「闲得发慌顺手美化」、无消费方的预抽公共 = 不做 |
| R6 | **先理解再动** | 能说出这段现行行为与失败条件；看不懂先读/补测，不靠重构来猜 | 先表征行为（测/日志/对照契约），再结构 |
| R7 | **会停会退** | 目标是让系统更易理解，达成即停，不为「探索真善美」深挖；对语义保持无把握即停：已改善部分可交付，无改善即撤销全部。失控时回退到最近全绿点，小步重来，每步全绿（重做远快于首次） | 无把握仍硬推；红灯叠下一步；失控后不回退硬修 |

截止日期紧且 R1 不成立 → 只做最小必要改动，把重构列为后续项；**禁止**无护栏的大爆炸整理。

### 3.2 何时做 / 何时不做

| 做（经验） | 不做 |
|------------|------|
| **预备式重构**：先让「改动变容易」，再做那个容易的行为改动（Beck） | 在烂设计上硬堆功能，下一步更难 |
| **Rule of Three**：同一逻辑第三次出现再提取（与文首 YAGNI 一致） | 第一次就上抽象 / 框架「以备将来」 |
| 修 bug：先写能复现的失败测试，再必要时重构暴露点，再修 | 未复现就大范围「清理」 |
| Code Review / 自审发现 §2 气味，且本轮就要改这处 | 气味在不动的模块里，只为评分去改 |
| 营地规则：离开时比来时略干净（触及面内） | 顺手重构 `arch.yaml` 未 `include` 的文件 |
| 性能：先测量，再只动热点 | 无数据的「优化式重构」 |
| 代码无法大部分运作：先封装成组件隔离，再逐组件决定重构或重写（重写走念头表「重写」行：先测试钉旧行为） | 代码根本不能正常运作（无行为基线可保）就宣称「重构」它 |

程序能跑且长期不会改 → **不必**重构。重构服务变化，不服务完美。

### 3.3 经验对照（接到本页 §1 / §2）

| 经验 | 落到本页 | 备注 |
|------|----------|------|
| 两顶帽子 | R3；念头表「顺便调结构再加功能」 | review 须写本轮戴的是哪顶帽子 |
| 测试是前提 | R1；出门清单 §3 | 不要求全仓完美覆盖，要求**触及面**可红可绿 |
| Rule of Three | 文首 YAGNI；P1；R5 | 与「第三次才抽」同一裁决，禁止提前 SPI |
| 预备式重构 | 加功能前先扫 §2，小步消挡路气味 | 预备重构仍须 R1–R4 |
| 气味 → 手法 | §2 命中当轮改；典型对应：C1→抽函数/拆职责；C3→内联包装；C9→卫语句/抽方法；C10→常量/工厂；C12→改名/搬移 | 不背手法名录；不会做的手法用 IDE 安全重命名/抽取 |
| 营地规则 | 只动 `include: true` 触及面 | 与 deliver `code` 范围一致 |
| 重构不修行为 bug | 修 bug 换加功能帽；重构只保现有行为（含既有缺陷语义时先用测试钉住） | 既有错误要改行为时，先钉测试再改 |
| 性能与重构分离 | 先正确清晰，热点证明后再优化 | 「更快」不是戴重构帽的理由 |
