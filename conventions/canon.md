# CANON：编码与架构执行规范（Agent 版）

关键词按 RFC 2119：**MUST**=必须，**MUST NOT**=禁止，**SHOULD**=默认应做，偏离须在记录里写理由。
本页是**规范，不是建议**。人类读者请看每条的 `WHY`，Agent 只需执行 `TRIGGER → DO → RECORD`。

## 0. 定位与优先级

- 层级：产品仓契约 > 本页 (T/A) > [coding.md](coding.md) (P/C/R) > 个人偏好。冲突时按此顺序取胜。
- 本页是 P/C/R 的上游：**先用本页判断“该不该做这件事、做在哪一层”，再用 P/C/R 决定“这一行怎么写”。**
- 编号真源：`T1`–`T14`（原则）、`A1`–`A8`（架构出门）、`F1`–`F7`（失败模式）只认本页。MUST NOT 另造码表或严重度。
- 证据规则不被本页替代：AI 输出与文档不可信，见 [evidence.md](evidence.md)。
- 本页不是门禁脚本。`check-feature` 不检查它；执行由 Agent 自觉、`review.md` 记账、人签字核对。

## 1. 何时加载 / 怎么用（执行协议）

**加载条件（满足任一即读 §3 命中表）：**
1. 当前阶段是 `arch`；
2. 你的计划或 diff 出现 §2 的任何**可观察信号**；
3. 你产生了 §3 触发表里的“念头”；
4. 被要求做 Review。

**协议（按序执行，不得跳步）：**
1. **DECLARE**：用一句话写出本轮变化及类型：`structure`（只改结构）/ `behavior`（改可观察行为）/ `both`（禁止，拆成两轮）。
2. **SCAN**：用 §2 信号扫 diff/计划，用 §3 扫念头。每命中一条，记下 `T#`。
3. **DO**：按命中条的 `DO` 做完，再继续写下一处。零命中则写最直白的实现，MUST NOT 为对称、美观或“以后可能用”添加抽象。
4. **RECORD**：按 §7 模板写入 `review.md`（或 `arch` 说明）。零命中也要写“已扫，无命中”。
5. **DESCEND**：命中后仍需按 [coding.md](coding.md) §0 用 P/C/R 落到具体代码纠正。

**停止条件**：命中条写了 `ESCALATE` 时，MUST 停止实现并按该条处理（自动唤起 grilling 或标 `UNPROVEN`），MUST NOT 自行拍板。

## 3. 规则（T1–T14）

每条格式：`TRIGGER` 触发 · `DO` 必须做 · `DON'T` 禁止 · `RECORD` 记什么 · `ESCALATE` 何时停 · `WHY` 一句话。

### T1 先砍偶然复杂度
- **TRIGGER**：§2 中新增层 / 服务 / 配置 / 抽象；念头“拆一下”“做成通用”“加个开关”“先留好扩展点”。
- **DO**：写出本质问题一句话；列出这次新增的每个抽象/配置及其**现有的**使用方；使用方 <1 则删除该抽象。
- **DON'T**：为未来需求预置扩展点；为“显得架构好”加层。
- **RECORD**：`T1: 本质问题=…；新增抽象=…；现有使用方=…；已删=…`
- **ESCALATE**：确有 2 个以上真实使用方但方案仍复杂 → 走 grilling。
- **WHY**：复杂度是唯一的敌人；每个新层都在借债。

### T2 概念完整性：先读后写
- **TRIGGER**：进入不熟悉的模块；念头“我按更好的方式写”“大家都这么写”。
- **DO**：写之前读该模块 ≥3 个已有实现，抽取它的命名、分层、错误处理、测试风格并沿用；确需偏离，写一句理由。
- **DON'T**：引入新风格；“顺便”重写一个更漂亮的版本。
- **RECORD**：`T2: 已沿用=…；偏离=…（理由）`
- **WHY**：系统应像一个人设计的；局部正确、全局漂移是 AI 的常见病。

### T3 深模块：接口小、内部厚
- **TRIGGER**：新增 interface/类；函数只转一手；暴露内部结构当 API。
- **DO**：公开面最小；对外抛出的异常类型与当前抽象对应，底层异常翻译成高层异常并保留 cause，不泄露下游异常类型与错误码；调用方不必知道内部步骤顺序或下游协议；只有 1 种实现就写具体类型。
- **DON'T**：浅包装（改名转发）；`IXxx` 只有 1 个实现（对应 P6）；为测试暴露内部。
- **RECORD**：`T3: 公开面=…；隐藏的细节=…`
- **WHY**：信息隐藏让变化被限制在模块内。

### T4 依赖规则与边界
- **TRIGGER**：业务类 import 框架 / ORM / SDK / DTO；跨模块直接读对方内部；新增依赖。
- **DO**：画出依赖方向（`A → B` 表示 A 依赖 B），业务核心 MUST NOT 依赖框架与协议；跨上下文只走显式契约（接口 / 消息 / API）；新增依赖写清收益、替换成本、失败时怎么办。权限提升走最小授权边界：只借必要权限完成单一动作，动作后立即恢复；提权/降权路径与审计点写进契约。高风险 / 破坏性特权操作默认由独立第二方批准（MPA）；紧急 breakglass 必须限定入口、独立授权、告警与审计，不能成为常规通道。跨信任域 / 远端调用必须写清主体、组、租户或服务身份的映射与授权范围；本地 root、管理员或服务特权不得自动等同于远端特权，无法安全映射时按远端最小权限执行或直接拒绝。不可信输入 / 外部协议 / 文件格式解析默认隔离到内存安全解析器或沙箱；确需非内存安全语言或未隔离解析器时，写明理由并使用安全库、边界检查与最小权限。依赖不止是 import：被调用方所需的值由权责方持有或提供方法，不假设调用方持有的常量 / 配置 / 上限（grep import 抓不到的语义依赖，调用方显式获取）。
- **DON'T**：Controller 里写业务；领域对象带 HTTP/ORM 注解；两个上下文共享一张表当接口。
- **RECORD**：`T4: 依赖方向=…；新增依赖=…（收益/替换成本/失败处理）`
- **WHY**：变化快的依赖变化慢的，反之即腐烂。

### T5 统一语言，命名即设计
- **TRIGGER**：同一概念多个名字；名字含 `util/helper/manager/data`；新增字段/接口名。
- **DO**：代码、契约、页面、文档用**同一字符串**；先在仓内 grep 现有词；做不出名字 = 职责不清，先拆再命名。命名不止概念名：布尔条件不自解释时提炼为肯定式谓词函数；同一边界值 / 中间计算使用前先命名；函数名须从调用点可判断行为（含变换方向与是否改原值）。名带量纲与约定：单位 / 关键属性入名（`_ms`、`plaintext_` 标未加密）；边界词区分闭开（`min_`/`max_`/`first`/`last` 闭区间，`begin`/`end` 半开）；布尔肯定式（`is_`/`has_`）；成本不误导（`get*` 暗示轻量、`size()` 暗示 O(1)）。
- **DON'T**：为“更好懂”发明第二套词；猜 API / 字段名（MUST 读源码或契约，见 evidence.md）。
- **RECORD**：`T5: 词表=概念→名字；已 grep=…`
- **WHY**：命名是最便宜、最持久的设计。

### T6 护栏先行，小步可逆，两顶帽子
- **TRIGGER**：改结构；触及面无测试；一个变更里既重构又加功能。
- **DO**：先补触及面测试钉住现有行为并转绿；每步可绿可回退；`structure` 与 `behavior` 分轮；断言取自契约或用户现象；高风险解析面（不可信输入 / 外部协议 / 文件格式 / 用户提交数据）在常规触及面测试外提供持续 fuzz / sanitizer 证据，缺陷修复后保留回归样本；触及共享可变状态时，断言须含期望效果与「无多余效果」（未改的字段/表仍原样）。
- **DON'T**：无测试大改；结构与行为混做；从实现反推断言（自证式测试）。
- **RECORD**：`T6: 本轮帽子=structure|behavior；护栏=测试名/verify case；回退方式=…`
- **ESCALATE**：无法补护栏 → 缩小步子；仍不行则停并标 `UNPROVEN`。
- **WHY**：没有护栏的改动不可信，也不可逆。

### T7 DRY 是知识单一来源
- **TRIGGER**：相同代码 / 字面量 / 校验第 2、3 次出现；念头“复制一份改改”“合成一个”。
- **DO**：先问“这两处变化的原因是否相同”；相同才抽，且第 3 次才抽；相反或不同的规则保持两份；跨服务 / 跨上下文边界默认容忍重复——共享库 / 共享客户端会把一次升级变成多服务联动发版，耦合比重复更贵。
- **DON'T**：为少写几行合并语义相反的逻辑；第 2 次就上通用框架。
- **RECORD**：`T7: 重复点=…；变化原因相同?=是/否；处理=抽/保留`
- **WHY**：过早抽象比重复更贵。

### T8 快速失败，禁静默兜底
- **TRIGGER**：`catch` 后返回空值 / `false`；缺值当成功；请求期补默认值；念头“别影响主流程”。
- **DO**：非法输入立刻抛错或返回 4xx；合法输入变体容差（不因格式 / 大小写 / 空白差异脆断），输出只发规范、无歧义的 canonical 形式——宽收只针对合法变体，不猜非法 / 缺失输入；失败的方法调用应使对象保持在被调用之前的状态（失败原子性）——先校验后修改，或先做临时拷贝；`catch` 只处理你能处理的；默认值只写在显式配置里；确需降级，写明范围、日志与指标。
- **DON'T**：吞异常；返回 `{}`/`[]` 假装成功；请求期猜默认值。
- **RECORD**：`T8: 失败条件=…；降级(如有)=范围/日志/指标`
- **WHY**：静默兜底把错误推迟成更难查的错误。

### T9 先正确清晰，再度量再优化
- **TRIGGER**：任何“更快”“优化”“减少调用”的动机。
- **DO**：先选对数据结构与算法；写出基线数字、目标、测量方法；优化后再测并记录；优化亦小步进行，每步重测，无提升即撤销该步。测量方法须可信：先预热、运行足够长时间以触发运行时优化（JIT/缓存等）；比较相对而非绝对数字；优先用剖析器定位热点，不为微基准自证。测量计划还须声明覆盖范围、采样盲区、观察者开销、样本量与结论边界，不把结论外推到未测路径或被测量机制排除的路径。累计优化投入以系统预期寿命内可省的运行成本为上限；一次性短命任务不做优化。
- **DON'T**：无基线的优化；用复杂度换假想的性能。
- **RECORD**：`T9: 基线=…；目标=…；方法边界=…；结果=…`（无数字则不优化）
- **WHY**：直觉常错，度量才可信。

### T10 数据系统是权衡
- **TRIGGER**：cache / 索引 / 副本 / 队列 / 异步 / 重试 / 跨服务事务 / 并发。
- **DO**：写清五项——① 真相之源（哪个存储为准）② 派生与副本（如何生成、何时过期）③ 失败语义（重试是否幂等、顺序、至少/至多一次；消息链路另写消费拓扑＝点对点｜发布-订购，谁消费、消费几次）④ 一致性等级（强 / 最终，谁能容忍多久）⑤ Schema 演进（如何兼容旧数据）。真相之源为持久数据时，还须写恢复目标：可接受丢失窗口 / 恢复时长，并给出最近状态的端到端恢复演练结果。副本不等于恢复，备份策略由恢复场景驱动且须能加载回应用；关键数据采用软删除、带外校验等纵深防御，未演练的恢复路径不得当作已具备。cache 写回 / 异步持久化必须写清对外可见点、持久化点、崩溃窗口与 flush/sync 语义，不把「写入缓存」冒充「已持久化」。并发相同计算合并（single-flight）：同一 key 的在途计算只执行一次，等待者复用结果；须定义等待上限、失败传播、取消语义与结果复用边界。跨系统事务的并发编辑须明确离线并发策略：乐观（版本号/修改时戳）还是悲观（独占锁），并写清冲突时的失败语义（回滚重试 / 提示谁在何时改过）。跨网络写操作须定义超时后的不确定结果：超时不等于远端失败；操作要有幂等键或补偿语义；可能双写时用 lease / fencing / 世代号隔离旧主或旧副本，恢复后定义冲突检测、合并或补偿路径。已决定引入并发后：并发控制代码与业务逻辑分离放置；共享可变数据与锁绑定封装；临界区最小化；先让单线程版本测试通过再引入线程；资源水位控制须有迟滞区间（高/低水位或等价机制），避免单阈值在临界值附近反复扩缩、淘汰或换入换出；引入共享资源排队、调度或淘汰策略时，写明准入顺序、公平性目标、饥饿上限、优先级反转场景与缓解方式（老化、优先级继承 / 捐赠、组级配额、按释放潜力排序），并给出等待时长与队列深度等观测指标；多把锁 / 多资源按固定、一致的次序获取（锁排序），消除循环等待；确需不同次序时写清理由与死锁风险。条件等待写在循环里：唤醒只代表可运行，唤醒后重查条件；阻塞返回或条件抢占失败后，重验资源标识 / 关键字段仍匹配，不匹配则重来；中断、事件循环回调、信号处理等不可阻塞上下文不得睡眠或等锁，只能标记 / 入队并交给可阻塞上下文。共享服务按客户 / 租户写清准入与配额，超限先隔离或降级该客户，不把噪邻扩散到其他客户。组合负载均衡、自动扩缩容、限流 / 丢弃负载、自动重试等自动控制时，写清控制器之间的反馈环和交互指标：失败 / 被拒绝请求不得被当作低成本成功；观测与告警覆盖控制器交集；显式设置资源上下限、保留容量、停止与人工接管开关。
- **DON'T**：双写不管一致性；无幂等的重试；无失效策略的缓存；隐式分布式事务；无界重试。
- **RECORD**：`T10: 真相之源=…；派生=…；失败语义=…；一致性=…；演进=…；恢复=…（丢失窗口/时长/演练）`
- **ESCALATE**：任一项答不出 → 标 `UNPROVEN`，走 grilling，MUST NOT 上线。
- **WHY**：数据系统的问题几乎都出在这五项没想清。

### T11 可运维性是架构特性
- **TRIGGER**：新增上线路径 / 构建打包 / 定时任务 / 外部依赖调用 / 降级。
- **DO**：交付前具备：指标、结构化日志、告警条件、回滚路径、降级开关、灰度发布；先选简单方案。用户可见路径须定义 SLI / SLO（测量窗口、目标值与用户视角）、错误预算及预算耗尽动作，并覆盖延迟、流量、错误、饱和四类信号；分页告警须对应用户症状且有明确动作，低价值噪声转工单或日志。交付产物须可复现：同一源码 / 配置 / 工具版本产出相同产物，构建不依赖构建机本地库或外部服务，配置与产物同版本发布。大规模集群或高风险变更默认分批灰度发布（先小批、观察稳定再扩批），回滚只作用于已发布批次；灰度用于 A/B 对照时写明对照组与判定指标。发布链路写清配置按代码评审 / 测试、制品 provenance 与部署校验、上线后验证；紧急绕过走受控 breakglass。安全漏洞发布：修复与公开披露同轮；发布物相对一个已验证基线只叠加安全修复，不带无关变更；预通知走保密通道并写明影响版本、严重度 / CVE、修复与回滚路径。跨服务 / 跨进程调用链用同一关联标识贯穿并写入结构化日志，格式标准化、从第一版就带上——事后难加装，问题出现才知需要。外部依赖调用必带超时与连接池上限，超时或下游挂时快速失败、返回码可区分正常 / 业务错 / 下游不可用——慢响应是最坏的故障模式，无界等待会把下游故障拖垮整条调用链。自动重试须区分可重试 / 不可重试 / 过载专用错误，只在紧邻上游层重试，使用随机指数退避加 jitter，并限制单请求与全局重试预算；跨服务调用链传播 deadline，进入下一阶段前检查剩余时间，整体注定失败时向上返回失败并向下传播 cancellation，停止无谓下游工作。下游失败达阈值就熔断：停止调用、同步链路快速失败降级、异步作业排队稍后重试，恢复靠试探而非立即放行；连接池按下游独立，一个下游拖不垮其它下游。多副本下游写清客户端负载均衡与后端健康 / 容量反馈，使用确定性子集，慢 / 错误后端自动摘除并试探恢复。外部 HTTP/下游调用默认走持久连接与连接池复用，不逐请求新建连接；确需短连接（如一次性脚本、明确不重用的对端）写理由。CLI/日志只输出调用方请求或真正需要的信息：错误走 stderr 不污染 stdout，信息只对偏离期望详加说明，确认提示只在有理由怀疑答案是「不」时出现，长时间操作给进度条而非逐行噪声。
- **DON'T**：只交功能不交观测；无回滚方案就上线；外部调用不设超时与资源上限；所有下游共享一个连接池。
- **RECORD**：`T11: SLI/SLO=…；错误预算=…；指标=…；日志=…；告警=…；重试=…；构建=…（可复现/同版本）；回滚=…；降级=…；制品来源=…；安全发布=…（披露/基线/无关变更/预通知）`
- **WHY**：无法观测与回滚的系统，故障时无法恢复。

### T12 架构 = 有记录的权衡
- **TRIGGER**：任何方案选择、依赖引入、边界变更、契约变更。
- **DO**：记录决策、**至少一个被拒方案**、放弃了什么、后果、触发重审的条件；能写成可运行检查的约束写成检查（测试、脚本、lint）；决策变了，文档同轮更新。
- **DON'T**：只写结论；靠口头约定守架构；文档与代码分叉。
- **RECORD**：`T12: 决策=…；被拒=…；放弃=…；重审条件=…；检查=…`
- **WHY**：没有权衡记录的方案，下次只能重做一遍推理。

### T13 契约语义变即换名
- **TRIGGER**：修改对外 API / 消息 / 字段的语义但保留原名；念头“改个语义，名字不动”。
- **DO**：语义变了就换名（新接口 / 新字段名 / 升版本号），旧名保留原语义直到下线，调用方迁移写进计划；内部重构不改对外语义则不改名。
- **DON'T**：复用旧名掩盖不兼容变更；语义变更不写进契约文档。
- **RECORD**：`T13: 变更=…；新名/版本=…；旧名下线=…`
- **WHY**：名字是调用方依赖的契约；换名让不兼容在编译 / 启动期暴露，沿用旧名把它变成运行期事故。

### T14 可变性默认纯值
- **TRIGGER**：引入可变状态（var / 可写字段 / 全局 map / 缓存写）；念头「改一个共享变量省得传参」。
- **DO**：默认写纯函数，值进值出。确需对外暴露可变引用（返回可变域 / 接受可变参数 / 存储外部传入的可变引用）时，先做保护性拷贝，拷贝在参数校验之前，拷贝后由本类独占，防别名篡改。引入可变状态只认两个准入理由：① 共享同一实体（跨线程 / 请求 / 多消费方必须看到同一份），② 度量出瓶颈（有数字）。二者都无，就把状态做成局部值或显式传入。引入时在类型名或注释上标明可变与理由。可变状态的初始化位置即其生命周期：在创建点 / 外层作用域初始化一次则跨调用持久，在方法体 / 内层作用域每次初始化则每次调用重置——持久状态初始化放在创建点，不在每次调用里重设。时钟 / 随机数 / 环境变量等非确定源不在函数体内直取（`time()` / `rand()`），显式传参（如 `Count(now)`）：测试可控输入，非确定收口到调用点。跨生命周期引用显式设计：长生命周期对象默认不持有短生命周期对象引用；优先值拷贝、句柄、弱引用或独立生命周期域，并配套可回收性验证。
- **DON'T**：无理由引入可变状态；为省一个返回值改公共状态；「先 mutable 以后再改」。
- **RECORD**：`T14: 可变=是/否；准入理由=共享实体|度量瓶颈|无；若共享=谁看到同一份，若瓶颈=基线数字`
- **ESCALATE**：说不出准入理由 → 删可变状态重写为纯值。
- **WHY**：可变状态让每次调用都依赖历史，测试与并发推理成本随可变点数上升；纯值让正确性局部成立。

补充启发（不编号，审查时使用）：曳光弹（先打通最薄的一条真实链路再铺开）；Conway 定律（组织边界会长进系统边界，加 Agent/人不等于加速，先订死接口再并行）；破窗（发现坏味道当轮改或明确记账）；YAGNI；现实近似（对现实世界的一致性本就是近似——账面库存≠货架实物，能容忍最终一致就不付强一致的价；不自研分布式一致性存储 / 协调系统，用现成工具或放弃一致性）。
