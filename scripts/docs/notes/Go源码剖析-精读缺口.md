## 一、精读范围

全书 10 章读完，全文主区间如下（行号指 `Go源码剖析-全文.txt`，PDF 页号随注）：

- **一、准备**（L104–L106）：本书目标——剖析运行时内部机制，了解程序运行状态，「写出更好的代码，无论是规避 GC 潜在问题，还是为了节约内存，亦或提升运行性能」。
- **二、引导**（L132–L170）：编译产物含运行时与用户逻辑；用 GDB 逆向找真正入口（`rt0_linux_amd64.s` → `asm_amd64.s` → `runtime·rt0_go`），而非一头栽进源码目录。
- **三、初始化**（L250–L397）：`args`/`osinit`/`schedinit` 依次初始化命令行参数、CPU 核数、调度器与内存/GC 现场。
- **四、内存分配**（L482–L836）：三级结构（mcache/mcentral/mheap）、微小对象组合、逃逸分析（L833–L836「Zero Garbage」避免堆分配减小 GC 压力）。
- **五、垃圾回收**（L1748–L1948）：并发标记清扫、写屏障、GOGC 阈值、辅助回收。
- **六、并发调度**（L2998–L3176）：G/M/P 模型、GOMAXPROCS（L3164「运行期用 runtime.GOMAXPROCS 修改 P 数量需付出极大代价」）、任务窃取。
- **七、通道**（L5908）：`Don't communicate by sharing memory, share memory by communicating.`（CSP）。
- **八、延迟**（L6612–L6613）：`defer` 最大优势是出错仍保证回收资源执行，「但如果对性能有要求，且错误能被控制，那么还是直接执行比较好」。
- **九、析构**（L7383 前）：`SetFinalizer` 设置对象析构函数。
- **十、缓存池**（L7383–L7576）：`sync.Pool` 对象缓存池，「避免分配大量临时对象对垃圾回收造成的压力」，private/share 双缓存 + 借调 + GC 清理。

## 四、重点候选裁定（防后人重复发现）

1. **通道消息传递优于共享内存不另立。** T10（并发控制与业务逻辑分离）/ T14（可变性默认纯值）已承载，Go语言实战 6.5 已裁定。
2. **竞态 / 共享变量 / 锁 / 通道不另立。** T10 / T14 已承载。
3. **逃逸分析 /「Zero Garbage」减少堆分配不另立。** T9（先正确清晰，再度量再优化）已承载；属 Go 编译器优化与 GC 压力权衡的具体技术。
4. **defer 有成本、性能敏感处直接执行不另立。** T9 已承载（无基线不优化）；属 Go 语言特性事实。
5. **运行期改 GOMAXPROCS 代价大不另立。** T9 已承载；属 Go 调度器实现事实。
6. **对象缓存池（sync.Pool）复用减少 GC 压力不另立。** T11（连接池复用）/ C19（显式释放）已承载；属 Go 标准库特性。
7. **了解运行时机制写出更好代码不另立。** 元原则，是 T2/T9 的「为什么」，不是独立可执行规则。
8. **逆向找入口而非盲读源码不另立。** T2（进入不熟悉模块先读）已承载；属读码方法。
