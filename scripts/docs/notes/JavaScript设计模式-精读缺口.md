### 3. 语言机制不落真源

接口检查的三种实现（注释法/属性法/鸭式辨型）、私有成员的各种模拟（下划线约定/闭包）、类式继承与原型式继承的 `extend`/`clone`/`augment` 实现、掺元类 mixin、命名空间对象、分支技术（branching）、事件捕获与冒泡，均为 JavaScript 面向对象语言机制或历史库实现，不构成可执行的工程缺口。

## 三、真缺口

**零缺口。** 本书 11 种具体设计模式已由 P1/P2/P3/P4/P7/P8/P9/P10/P13/P16 与 T4/T9/T10/T11 承载；面向对象基础（接口、封装、继承、单体、链式调用）已由 T1/T3/T4/T5、P6/P19、C3/C22/C27 承载；其余为 JavaScript 语言机制与类式继承实现，不落真源。

## 四、重点候选裁定（防后人重复发现）

1. **11 种设计模式不新增条目。** P1–P19 已按「场景信号 → 运用 → 不要」覆盖工厂/适配器/装饰者/命令/职责链/代理/组合/门面/观察者/桥接；再为本书逐条立模式名会与 P 表重复，且违反「不要先想模式名，按正在做的事匹配」。
2. **接口检查（注释法/属性法/鸭式辨型）不另立。** 属 JavaScript 动态语言技巧；其“不猜 API、先读契约”的风险由 F2（幻觉依赖）与 T5（统一语言）承载。
3. **私有成员的模拟（下划线/闭包）不另立。** 现代 ES 已提供 `#` 私有字段；其“隐藏内部实现”的要求由 T3/T4 承载。
4. **类式继承 / 原型式继承 / mixin 的具体实现不另立。** “组合优于继承”由 C27 承载；具体 `extend`/`clone`/`augment` 是历史库实现。
5. **单体模式 / 命名空间对象不另立。** 现代模块系统已替代命名空间；其“边界与公开面”由 T3/T4/T5 承载。
6. **享元 / 延迟实例化等优化手段不预设。** 由 T9（无基线不优化）承载，不把具体优化模式固化成默认。

## 五、不建议落的内容

- 11 种设计模式的类式继承实现代码（`extend`/`clone`/`augment`/`Interface` 等）：历史库细节，不进真源。
- 接口检查三法、私有成员模拟、命名空间对象、分支技术的逐条实现：JavaScript 语言机制。
- 事件捕获与冒泡、方法链式调用的具体写法：语言教程。
- 书中具体案例（Web 日历、工具提示、性能分析器、动画库订阅）：只作理解材料。
