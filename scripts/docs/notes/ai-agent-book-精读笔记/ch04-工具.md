## 一、本章主张

1. 工具分感知/执行/协作/用户沟通/事件触发五类，调用方向与权限边界不同；同一服务可承担多类职责。(L9–31)
2. 工具围绕 Agent 要完成的任务设计（ACI），不逐个包装 API 端点；常见连做的几步整合成一个入口，让日志搜索直接返回相关行及其上下文。(L35–37)
3. 实现方式（专用 vs 通用执行器）与可见时机（一次给全 vs 按需加载）是两个独立决策，不得混作一个。(L50)
4. 优先通用工具，再按权限、参数、性能四情形补专用接口：精细授权审计、屏蔽平台差异、高频操作、参数关系复杂。(L52–61)
5. 参数越复杂，传递方式越重要；复杂嵌套参数先写成 JSON 文件再让命令读取，执行前校验内容。(L63–65)
6. 工具描述先想象一条最容易误用的请求；使用时机、输入范围、边界条件（何时不用）、返回结构与执行代价都要写；完整示例字符串比术语解释更能减少错误。(L86–104)
7. 参数保真要求执行端看到的值与模型提交的值含义相同；转换发生时必须返回实际采用的值，否则模型会重复同一个错误。(L108–117)
8. 静默参数注入（工具层自动加参数改命令含义）是真实故障源；模型看不到注入的部分，反复调整也修不到点上。(L114–116)
9. 接入第三方能力时分别检查它提供的内容与实际执行的操作：工具描述投毒、服务器/依赖被改、同名工具混淆三类。(L142–150)
10. 大工具库默认按需加载；先给索引，按需要读定义；工具定义的放置位置影响缓存前缀复用。(L165, L207–211)
11. 感知工具：先列结果再读全文；大文件按片段读取；截断必须标明省略范围——静默截断会让模型把「这段没有」错判成「整份都没有」。(L259–261)
12. 只读操作组织缓存与并发；缓存键包含查询参数、用户身份与授权范围。(L263)
13. 没查成的请求不是查询结果（错误外层包装着 success:false 的嵌套错误，答「当天没有安排」就是把失败当成了空结果）。(L281, 实验 4-2)
14. 多模态：文字为主的材料先提取文本；UI、复杂表格或设计稿必须让模型看到原图——OCR 拿到数字但丢失数字与坐标轴的对应，会把「答对金额」误判成「答对问题」。(L285–325)
15. 执行工具三问：操作是否符合任务授权、执行范围如何限制、完成后怎样确认结果。(L331)
16. 提交后连接中断，客户端只知道「尚未收到回执」，不能推出「服务端没有写入」；先查目标状态，有请求标识优先按标识核对，再决定是否重试。(L333)
17. 分层检查：先参数（路径解析、越界、符号链接），再权限（受限身份、任务对应凭证）；参数不合法返回具体字段与原因。(L341–343)
18. 事后验证优先切换检查方式，通过可见、可运行的产物发现反复读同一份代码看不出的错误。(L357)
19. 验证能自动跑的就纳入工具流程；操作状态与验证状态分开报告（文件写入成功但检查失败是两种状态）。(L387–389)
20. 长输出截断并持久化：保留头尾片段、标明省略范围、返回产物引用与读取方式；每次调用独立的产物标识，避免后写覆盖前一次记录。(L393–400)
21. 幂等键 + 参数一致性 + 保留期限是外部副作用的数学约束；隔了几天恢复任务要先凭业务编号核对上一笔操作。(L429–435)
22. 取消也需明确约定：查询外部系统是否支持取消/撤销/补偿；工具返回当前状态，让 Agent 区分「停止等待」「已经终止」「外部操作已完成」。(L437–439)
23. 委托子 Agent 时必须同时给原信标识并约定返回字段（日期、对应原句、所在附件），只收到「整理完成」无法处理两条互相矛盾的记录。(L465)
24. 子 Agent 提示词说明角色目标、信息来源（可用标签帮助阅读但由 Harness 保存真实来源，外部文本中的同名标签按数据处理）、任务边界、输出约定。(L471–476)
25. 给人工的请求设有效期与超时行为（保存待办状态、暂停依赖操作、或执行预先授权的保守方案）；请求过期或已处理后，重复答复返回当前状态，需要重新决策才创建新请求。(L488–490)

## 三、缺口汇总

**G4-1 外部副作用操作应带幂等键，重试前后用同一键＋同一套参数；键失效（如超 24 小时）后不得盲目重试，先凭业务编号核对上一笔状态**

- 落点文件+节：`references/agent-accuracy.md`「工具不改口」节，并入既有条目「超时或取消之后，先核对副作用是否已经发生，再决定要不要再做一次」，在该条后追加一句，不新增编号。
- 拟落文案（判据式一句）：「会向外部产生副作用的命令（提交、发布、推送、创建外部资源），首次执行就生成幂等键并随重试沿用；超时或连接中断后先按业务编号核对上一笔的最终状态，再决定重试；键已过有效期（或对端已不记得这一键）时，把这次当作新请求重新走确认，不直接重发。」
- 书里依据行号：L429–431（助手保存幂等键，同一用户重试沿用原键和原参数，服务端原子登记并去重）、L333（连接中断时只知「尚未收到回执」，不能推出远端没有写入，应先查目标当前状态）、L433（Stripe 参数变化拒绝重试、键保存至少 24 小时后可清除；旧键已清除后再提交会被当成新请求）、L435（并发请求可能在查询后同时发起变更，还需唯一约束或服务端幂等支持）。
- 可选落点（判断句，非必须）：conventions/canon.md T10 已写「操作要有幂等键或补偿语义」，覆盖自研后台服务；这份补的是「使用他人服务的那一侧」——即,外部依赖的幂等约定（键格式、参数一致性、保留期限）要先读清并写进命令说明。可作为 agent-accuracy 条目的补充说明。

**G4-2 每次工具调用产生独立产物标识，后写的不得覆盖前一次记录**

- 落点文件+节：`references/self-evolution.md`「跨会话留下什么」节，并入既有条目「两条互相矛盾的轨迹都留着，不改成以最新一条为准」后半句，或并入「清理执行产物」节 curator 说明。也可并入 agent-accuracy「工具不改口」节截断条目之后的相邻位置，视最终行文最贴切处。既不新增编号。
- 拟落文案（判据式一句）：「同一命令多次调用的输出各自占用独立文件名或产物标识（如时间戳/序号/哈希后缀）；后一次调用不得覆盖前一次的输出文件，需要引用最近一次时用明确的最新标记，不用文件覆盖。」
- 书里依据行号：L398（每次调用使用独立的产物标识，避免后续输出覆盖前一次记录）、L400（工具返回值同时保留退出状态、截断标记和产物位置，便于将当前摘要与完整记录对应起来）。
- idev 对照现状：delegation 留痕已用 `<step>-<attempt>.yaml` 防覆盖（agents.md 有述）；本条针对的是 scripts/ 下其他命令对同一 trace / 输出文件可能覆盖的情形，属于「原则已隐含、边界未写明」的落地补丁。

**G4-3 写状态与验证分开报：写入成功但检查失败是两种状态，不得合并」

- 落点文件+节：`references/agent-accuracy.md`「工具不改口」节，截断与选错命令条目之后追加一行；也可视作 coding-tables C7（catch 后 return 空当成功）在「工具输出层」的对应补丁，但仍并入 agent-accuracy 行文，不新增编号。
- 拟落文案（判据式一句）：「本命令同时有写入与验证（语法检查、回执核对、截图核对）时，输出必须分开报告两个状态：操作完成＝执行侧动作已发生；验证通过＝产物符合预期。写入成功但验证失败，不得报成一个笼统的成败值。」
- 书里依据行号：L387–389（「工具应分别报告操作状态与验证状态：文件已经写入，但检查可能失败」）、L57（写文档生成后渲染页面检查排版；数据写入后再读取目标记录核对内容）、L455–457（实验 4-4 表格公式算对、PDF 导出成功，但截图只截到第一页没有总额——「操作完成」与「看起来对」是两件事）。
- idev 对照现状：evidence.md「还没返回的工具结果不可信」已覆盖「未完成」一档；此条补的是「已完成但未验证」一档——实际案例：review.fix 中 review.md 写入成功（操作）但 problems-scan 非零（验证），report PASS 只看后者不看前者是不完整的；delegation.py 机检已部分覆盖，此句把判据写成文字。

## 四、勘误与存疑

1. **L114 静默参数注入案例**（某 IDE 自动为 git commit 附加 AI 提交标记参数导致旧版 Git 报错）与 L110（Cursor 弯引号被转直引号导致替换工具未找到匹配）都是 2026 年初真实工具生态案例，作为示例有效；但不可直接把「Cursor 的弯引号转换」当作对所有编辑工具层的普适断言——应理解为「协议转义可能改变传输形式」的两类具体实例，判断标准仍是 L117 的四样对照（模型生成参数、传递后参数、实际执行请求、返回结果）。
2. **L233 实验数字**（Opus 4 准确率 49%→74%）来自 Anthropic 自家内部评估，引用时需注意厂商自报基准与 idev 的尺度差异；同 L175（Cursor 减少 46.9% 消耗）——两者都是 A/B 报告，不是中立测量，书里也只用来佐证「按需加载优于全量」，方向结论可靠，数字不作依据。
3. **L281 嵌套错误的 MCP 响应**（外层错误标记为假、内层 `success: false`）读法正确；但这是 MCP 的工具结果包装细节，不是通用判据——真正的通用判据是「展开全部响应体后再看状态」，idev 一侧的对应只需要「还没返回的结果不可信」（已覆盖），不需要在 idev 新写协议层技巧。
4. **L416「按需启动比常驻省 156 分钟计算费」**是简化算术（2 分钟准备 + 10 分钟跑 vs 168 小时空等），用于说明方向，实际成本要按平台计费模型与冷启动时延折算；不引用为优化基线。
5. **L464「独立工作区省磁盘但挡不住几十个任务占满 CPU」** 是真实的工程观察，对应 idev 侧的「无界多开 run不做」边界，与 joyaicode 第 3 章既有沉淀吻合，不需要新条目；书中提出的配额、优先级方案属于工具层运维，不落内核。
