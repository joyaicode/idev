# 《深入理解 AI Agent》第 7 章「Agent 的评估」精读笔记
> 源：/tmp/ai-agent-book/book/chapter7.md，共 880 行。多Agent精读批。

## 一、本章主张

1. 评估对象必须是「模型 + Harness」组成的完整 Agent，同一模型换工具或反馈流程即产生不同结果，单评模型不评 Harness 无工程意义 (L9, L11)。
2. 对比与消融应融入日常开发：每轮明确改动内容、其余条件不变、重复测量，才能区分真实改进与偶然成功 (L7)。
3. 评估是模型升级的回归检查：公开基准进步而业务任务退化只有自建任务集能暴露，应「为未来的模型开发产品」——提前备好评估集，模型切换成为可反复执行的工程决策 (L15, L620)。
4. 任务定义须四件分离：工单 / 用户场景（用户知道什么、怎样回应）/ 初始状态（两侧各自的操作）/ 评分标准（含 reward_basis 指定哪些检查计分）(L27–L46)。
5. 模拟用户要有事实锚定：回应依据工具查到的环境状态而非顺着客服说，否则对话看似顺利而故障仍在 (L40)。
6. 双控环境（两侧各持一部分状态变更权）才能测出协调能力：客服改后台、用户改设备，验收要沿两侧交互追 (L66)。
7. 最终分数相同的轨迹暴露不同的过程问题，须把最终分数展开为具体改进点（如核对映射、用新证据修正判断）(L74)。
8. Pass@k（k 次至少一次成功，探索型）与 Pass^k（k 次全部成功，业务可靠性）是两种不同的产品语义，p=0.6 时 Pass@5≈99% 而 Pass^5≈7.8%；禁止把不同任务的一次性成绩直接平方当 Pass^k (L84, L94, L99–103, L109)。
9. 允许回答「信息不足」时必须先定分母：答对/已答（85%）还是答对/全题（68%）回答不同的问题 (L115–L117)。
10. 有写入副作用的评估须先恢复初始状态、记录所有尝试；重试恢复后的结果要与原始失败分开记 (L123)。
11. 验证器设计要看「反例能不能过关」：只查第一笔会放过全批通过的越权者，只查后两笔会放过什么都没做者；验证范围应从用户授权反查 (L191)。
12. 时间敏感任务的验收须有带时间戳的完整回放，否则漏报的窗口根本数不出来 (L211)。
13. 验收应以独立取得的证据为准：Agent 的完成报告只用于定位检查对象，得分由实际运行产物 / 读取状态 / 核对来源决定 (L189)。
14. 能程序核验的优先写成程序检查，LLM-as-a-Judge 只留给开放式质量；两者可在同一回答混用 (L281)。
15. 评判模型必须先校准已知偏差：长度偏差、位置偏差用控制样本与交换测试发现 (L291, L519)。
16. Rubric 四准则：专家指导 / 全面覆盖（含陷阱）/ 按重要性加权（含一票否决）/ 判据自包含；边界案例决定评分能否处理真实对话 (L293–L315)。
17. 幻觉（编造可核验事实）单独一票否决，触发即总分置零 (L313)。
18. 同源模型评判有古德哈特风险：Agent 学会评分器文风而事实错误照旧，重要发布前用多模型家族独立评分 + 人工复核 (L353–L355)。
19. 失败归因找「最早使任务偏离目标的决策」，最后出现的报错往往是后果；归因记录要区分直接错误、原因假设、后续症状 (L382, L400)。
20. 最终状态与最终答复分别验收：业务系统保留的是动作产生的状态，用户收到的是答复，两类错误（执行错误 vs 转述错误）用独立评分项分开 (L404–L406)。
21. 生产级 Agent 积累轨迹前缀回归任务往往比增加端到端回归更重要：固定出错前上下文、直接检验该处决策、运行成本低 (L469)。
22. 前缀回归的核心是「可接受动作集合」：依当时可见证据判分，不把只有事后才知道的信息写进标准答案 (L469, L493)。
23. 看到成绩下降先检查评测系统（初始化 / 资源 / 验证器 / 条件变化），再调整 Agent (L711)。
24. 成本按完成任务计量（含失败尝试的分子），两次单独测得的优化比例不能直接相加 (L589, L604)。
25. 统计上配对分析优于总分比较：逐题记「都成 / 只 A / 只 B / 都败」，净增相同的两份报告里退步题的分布完全不同 (L659)。

## 三、缺口汇总

**G1 验证器自身的反例自检**（plan-schema.md「case 可信度四查」末尾补一问）
- 拟落文案：四查之外补第 5 问「这条断言放过什么：写出能骗过该断言的最省事行为（如全批通过、只动一个字段、只报完成不执行），写不出反例的断言说明只覆盖了正路径」。挂靠四查第 2 条（断言覆盖完整结果），不新增编号。
- 书里依据：L191（只查第一笔，全批通过的助手也满分；只查后两笔，什么都没做也过关）、L669（两条轨迹同分却跳过了身份核验，先查评分器读了什么）。

**G2 前缀用例与端到端用例的判分口径分离**（rootcause-guards.md「决策步」节补一句）
- 拟落文案：决策步的 accept/forbid 只依 before 里当时可见的证据判；把只有事后才知道的信息写进 accept（如「改 L1002 而非 L1001」），check 拒绝时打 WARN 同 prefix 缺席同级。
- 书里依据：L493（出题人只接受修改某一条线路=把事后信息写进标准答案；前缀题必须以当时可见证据判分）、L469（动作类别与业务语义对应清楚，避免同义标签当行为差异）。

**G3 失败轨迹回流时的「反事实配对」信令**（self-evolution.md「学习信号」节的四件之外补第五件）
- 拟落文案：从失败轨迹提学习信号时，除四件外再记一条「同条件下原先能过的情形有没有被反例」（复用书 L659 配对思想：净改善可能掩盖同批退步）；写不出反例对照的，只记失败本身，不下「变好/变坏」结论。落点 self-evolution.md「学习信号」，与既有「通过件数变多时…同时看违规、回退和未证明」并入同一段，不新起节。
- 书里依据：L659（B 保住 70 又多对 3 题，与 B 对 23 错 20 题，总分同为 70→73，后者有 20 道退步题值得逐题排查）、L622（新模型简单任务更好、复杂编排降 5 个百分点，按任务迁移）。

## 四、勘误与存疑

1. L107 的组合计数「Pass@2 样本估计 9/10」：把「五次里任取两张」当作独立运行的估计在概念上混了组合数与概率，书中自己也点明「回答的是另一个问题」——工程上只需记住两种指标回答不同问题，不必用这个卡片配对法。
2. L374（TTS 评分实验）承认评审「没有逐字指出听到了什么」——多模态 judge 的可信度低于文本 judge，书未展开；对 idev 无影响（不建 judge）。
3. L559 RE-Bench「2 小时 Agent 4 倍于人类、32 小时反超」引用的是单次对照，样本与任务分布未披露置信区间，作方向性参考即可。
4. 与 idev 场景无关而留书：τ²-bench/AppWorld/GAIA 等基准构造细节、用户模拟器设计、Elo/BT 排名、多模态 judge、具身环境与域随机化（L827–851）、A/B 平台与 GrowthBook、预算-能力曲线。
5. L319 提到蒸馏 judge 模型「用第八章的监督微调方法」——跨章承诺在第八章兑现，本章无独立可执行判据。
