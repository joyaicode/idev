## 一、本章主张

1. 多 Agent 的前提是答得上「新增的成员带来什么」：新的证据、新的搜索路径、新的专业判断，或并行缩短等待（L47-49）。
2. 反馈的信息增量优先于并行与隔离收益：审核者要看生成时尚未获得的证据（测试结果、截图、外部材料）（L49-66）。
3. 以调校好的单 Agent 为基线：质量提升或时间节省盖不住通信、重复计算与维护成本，就不扩大协作规模（L82）。
4. 辩论在同预算思考 token 下对正确率无优势，只用于展开分歧、检查假设、补反面论据；追正确率优先加可核验证据与独立检查（L285-287）。
5. 转述会放大错误（传话游戏）：交接记录要留结论、适用条件和来源，分清已确认与推断（L570-572）。
6. 同质趋同：同一模型的五份一致意见可能只是同一错误重复五次，增加审核数要同步增加证据与视角差异（L576-578）。
7. 提议者—审核者循环的基本要求是独立证据与可定位的修复条件；审核者要指出哪个要求未满足、怎样验证修复（L255, L263-267）。
8. 无外部反馈的自我修订会把对的改错；验证器是循环的关键瓶颈（L225, L255）。
9. 过早终止三型：部分完成宣称全部完成、一条路失败就放弃整步、局部成功遗漏后续步骤——完成条件要落到可检查结果（L219-223）。
10. Manager 规划错误会让多个执行者沿错拆分返工；瓶颈在规划时把更强信息与预算给 Manager（L323）。
11. 交接消息带产物引用（位置、版本、用途）而非全文；大表落共享文件、消息只带引用（L144, L175）。
12. 收尾要原子且幂等：第一个验证通过者原子登记、取消其余、等确认或超时；同事件重复投递沿用已有处理结果（L327-348）。
13. 并行同时修改共享文件要乐观锁或独立工作副本；跨文件语义一致性（图号↔引用）要在合并点检查（L558-566）。
14. 循环失控要有总预算、并发、派生深度、轮数、超时；失败与取消前已发生的消耗也要记账（L592-594）。
15. 整场实验的权限范围要能一次回答：全体成员可达资源合起来是否在获准范围内、越界能否一次停整场（L598）。
16. 理解债与认知投降：Agent 交付越快，人越要能解释关键行为、保持独立提问，否则欠账持续扩大（L602-608）。
17. 角色差异只在知识、流程、风格时优先 Skill 加载（保缓存前缀）；涉及权限、工具隔离、审批职责时才独立 Agent/角色切换（L99）。
18. 子 Agent 完成后交结构化摘要与交付结果，试错记录留在专属工作区，供诊断不进协调上下文（L152）。
19. LongHorizon 的 MEA 外层把长任务连续性落在已核实状态上：执行上下文可刷新，仍能依目标、完成证据、未解决事项续跑（L237-239）。
20. 去中心化减少对中心点可用性的依赖；但接手成员自己卡住仍要靠持久任务状态、超时与接管（L459）。
21. 交接链防原地循环：结合任务状态、产物版本、未解决问题与重复次数判断有无进展，卡住就限次上报负责人（L491）。
22. 职责争议与目标冲突要先约定目标优先级、资源所有权、可执行范围；规则解决不了的由运行时暂停并交负责人裁决（L584-586）。
23. 失败三分类（系统设计/协作偏差/任务验证）指向「验证标准与实际要求错位」这一类硬伤：编译器检查不了走法是否合规（L544-550）。
24. 汇总要找出各判断之间的联系，而不是并列几份意见（L305）。
25. 上下文是否共享、谁有权要求返工是两个可独立选择的维度（L13）。

## 三、缺口汇总

1. **轮末消耗总账**
   - 落点：references/agents.md「这一层是什么 / 不是什么」末尾或 agents-playbook 的波次说明，加一句
   - 拟落文案：「同一波分片被取消或失败时，已跑完的片的留痕和耗时仍进 delegation timeline——预算按「曾发生」计，不按「被采用」计。」
   - 书里依据：L592-594（成员数量与轮数相互放大；失败与取消前已经发生的消耗也要记录）+ L68（协作组多花的 token 与结果一并算进成本）
   - 说明：agents.md L343 已写「缺了就没有耗时视图」，但只针对一次委派的 started/finished；**波次中途取消/失败片的消耗要不要留痕**没有明说。落点是补一句留痕纪律，不是新机制。

## 四、勘误与存疑

- 实验10-1 的数字矛盾要小心引用：30 项任务 Skill 组过 15 项、切换组过 2 项，但书里明说服务商两侧缓存命中都报零（L113），「缓存节省」的论证在该次实验里未被测到，只是协议推演。
- Anthropic 266 vs 21 漏洞（L68）不能直接归因协作：书里自己承认协作组用了约 4 倍 token，差异混入计算投入。
- Tran & Kiela 论文标题即立场（单 Agent 在等预算下不输多 Agent，L285-287）——与「多 Agent 优于单 Agent」的流行叙事相反；引用数字时注意其仅在多跳推理任务上成立。
- LongHorizon 的提升数字（51.8→80.7 等）伴随 2.3~3.6 倍 token 成本（L241），收益并非纯优化；且基线是「同一后端+无 MEA 外层」的对照，非生产调优后的基线。
- Navier–Stokes 一节（L72-74）的"找到反例"表述与克雷所公告的评定流程之间的关系，书里标注为待评状态；引用时应保持书里的克制措辞。
- OS 类比（表10-2）是启发不是同构：书里明写"上下文摘要会改变信息表示，而内存换页保留字节"（参考答案第11题），fork/kill 的语义映射到 Agent 停在组织层，实现层各不相同。
- 与 idev 无关的部分：语音狼人杀实验、Vending-Bench、斯坦福小镇、Agentopia、Moltbook、Pinchwork/RentAHuman（社会模拟与市场）、Kimi Agent Swarm 规模叙事、CalBench 日历代理——agents.md L105 已明确留在书里。
