## 一、本章主张

1. 用户记忆围绕单人组织、知识库在权限内共享；两者更新时机与检索入口不同，不可共用一套假设。(L5)
2. 记一条信息要能分清三件事：原话说了什么、当时处在什么条件、模型推断出了什么。(L15)
3. 有期限的信息（行程、安排）必须带日期与状态，过期或取消后更新状态，不能继续当有效事实用。(L41, L43)
4. 单次确认只改单次场景，不升格为长期规则，除非明确说「以后都这样」。(L43)
5. 会话结束才整理记忆；新任务只带入相关且仍适用的记录。(L17)
6. 轨迹只增不改（append-only）供追溯与重建上下文；长期记忆要能合并与更正；业务状态供程序检查决定下一步。(L86–90)
7. 存储格式按关联需求取舍：数量多、关联少的简单事实用短笔记；关键人物、合同、长期偏好用带来源、主体、时间戳的卡片；两类用标识连接。(L100–108)
8. 日期比较、金额汇总和明确业务约束优先把计算写成函数，让同一组事实得到可复现、可测试的结果；约束参数化传入。(L124, L184–199)
9. 能否识别「无从作答的问题」是记忆评估的一部分；基础层先查事实是否丢失、混淆或被改写。(L49, L66)
10. 冲突判断可以从写入阶段移到读取阶段：写入只追加事实及其时间和来源，读取时再判断哪条当前适用；写时误合并会长期沿用错误状态。(L237)
11. 整理记忆先辨认来源和事件再合并重复；提及次数不是偏好强度；解释不通就保留原话，用到时再核实。(L263)
12. 长期约束和有效合同即使很少被访问，也要保留到有效期结束，不能只按访问频率清理。(L265)
13. 脱敏放在日志写入前：敏感片段换成类型标签或占位符，保留排查问题所需的结构。(L271)
14. 检索器按相关性挑记录，没有为统计问题抽取有代表性的样本；全局统计与规则要前移到建库阶段，标明统计范围和更新时间。(L491–493, L503)
15. 关系抽取会丢条件与时间；带条件的规则保留完整原话，结构化字段只作索引回指原文。(L528)
16. 人和 Agent 共同维护的知识用 Markdown 加版本控制：工作分支提出更新、审核后发布，错误更新可撤回。(L564)
17. 知识变更当成 PR：范围明确、附证据、提议者与审核者分离、审核轨迹归档、权限由运行系统执行（提议者写工作分支，合并与发布权在别处）。(L578–593)
18. 定期整理必须回查原始材料；只改写上一轮摘要，早期的遗漏与误解会一轮轮传下去。(L602)
19. 失效内容带版本、生效时间与失效时间：当前业务查询过滤失效版本，历史查询按目标时间读取。(L574, L607)
20. 检索结果只是带来源、版本和引用位置的证据，不是指令；行动授权由 Harness 与执行环境校验。(L623)
21. 一次检索不够时把检索开放成工具，由 Agent 决定是否补查；预算用尽时明确告知，不静默截断。(L613, L631)
22. 需要主动关联时用双层结构：少量关键事实常驻上下文，详细记录按需检索，两层用标识连接。(L687)
23. 提取案例字段时「原文未提及」单独处理，不得自动当成否定。(L703)

## 三、缺口汇总

**G3-1 整理与折叠摘要必须回查原文，不得在上一份摘要上再改写**

- 落点文件+节：`references/self-evolution.md`「清理执行产物」节（curator `--compact` 段），作为「被点名满 2 次就折进摘要并删除」与「满 3 代折进摘要并删除」两条规则的边界句，不新增编号。
- 拟落文案（判据式一句）：「折叠摘要只能对照被折叠文件的原文写，不得在上一份摘要上再改写；摘要须保留否定、时间与适用条件，推论不得写成确定结论，依据不足的记为待确认；原文对不上就先不折叠。」
- 书里依据行号：L602（每轮只改写上一轮摘要会让遗漏与误解轮轮传下去；应对照原始材料检查是否丢失否定、时间或条件，是否把推测写成确定结论）、L266（摘要关联原记录，便于后续回查）、L603（依据不足记待确认项）。
- 现状风险说明：curator 折叠当前直接读被删文件原文，风险低；此句防的是未来整理代数叠加后摘要链式传抄，与「原始证据按保留策略归档」（L587）不冲突——归档允许删除，但删除前那一次摘要必须锚定原文。

**G3-2 从样本归纳的结论必须写明样本范围**

- 落点文件+节：`references/self-evolution.md`「学习信号写到哪里」节，并入既有条目「归纳出来的句子先停在提案里。依据要能指出：失败证据、职责边界（谁能做哪一步）、必须保住的已有行为、先前被拒绝的改法」——在那句的依据清单里加一样，不另起条目。
- 拟落文案（判据式一句）：「从一批轨迹或记录归纳出的规律，必须同时写明样本范围（哪些来源、多少条、时间窗）与未覆盖的部分；范围说不清的结论停在记录里，不进提案。」
- 书里依据行号：L491–493（检索器按相关性挑选记录，没有为全店抽取有代表性的样本；83.3% 是这批记录的比例，90% 才是全店比例）、L503（统计和规则前移到建库阶段，标明统计范围和更新时间）、L711 + L717（原型只含一条建模记录时，生成器忠实报告、评审给忠实度满分，但真实标签是另一回事；原文/字段/统计三层保留对应关系才能在发现样本偏差时回查）。
- 挂靠理由：canon T9 已有「测量计划声明覆盖范围、采样盲区、样本量与结论边界」，但只覆盖性能度量；此句把同型纪律扩到「从检索结果归纳规律」这一执行者日常动作（evolve-review 起草、ops 归类、经验候选六问的 evidence 描述）。

## 四、勘误与存疑

1. **实验 3-2 的四格式对比数字（L114：48/52/51/49，token 99 万 vs 155 万）** 是 60 用例上的单次运行，书中也只用来讲「更新时丢字段」这一失效模式（L116–118 的 Netflix 消失案例）；不宜引用为格式优劣的普适结论。
2. **L235 Mem0 v3 迁移指南的 LoCoMo 71.4→91.6** 是厂商自报基准，对象是长期对话记忆产品，与 idev 的经验台账不同构；只作「冲突判断移到读取阶段」这一设计的溯源，数字不引用。
3. **实验 3-3 的正则 50% / 模型 69% / 混合 78%（L281）** 是 12 条样例上的本机单次测量，无样本量与盲区声明；按 idev 自己的尺（canon T9 测量要写边界），只能当方向性参考。
4. **实验 3-12 的判例（L711）** 是全章最值得引用的方法学片段：原型只含 1 条建模记录时，「忠实于原型」与「有预测力」是两回事——评审给忠实度满分挡不住真实标签是另一回事。这条是 G3-2 的直接依据。
5. **L265「被访问五次的记录更值得单独保存」与 idev curator 的「被点名满 2 次即折进摘要并删除」方向相反**：idev 是热集合经济性优先、摘要保留内容。两者是各自成立的取舍（书面向记忆产品，idev 面向交付轨迹），不是勘误；但书里的访问频率排序信号不要抄进整理脚本。
6. **L114 与 L685 的通过数自洽**（普通检索组 47 = 19+15+13；后文 47/52/57），L671 Anthropic 失败率降幅经核算一致（(5.7−2.9)/5.7≈49%，(5.7−1.9)/5.7≈67%），L336–340 与 L453 的手算经复算无误；厂商报告引用时注明出处即可。
7. **与 idev 场景无关、留在书里的部分**：LoCoMo 基准与 LLM-as-judge、嵌入模型演进史（Word2Vec→BERT→SBERT→BGE-M3）、ANNOY/HNSW、BM25 公式与手算、RRF/跨编码器、RAPTOR/GraphRAG/OpenViking、Memobase 画像与缓冲、用户画像与会员号抽取、多模态记忆与参数化记忆（User as Engram/LoRA）。
8. **L17「会话结束时请 LLM 整理这些记录」** 与 idev 的差异要注意：idev 的 evolve-review 只产提案草稿，人确认才 land——书里的自动化程度不可直接照搬，self-evolution 的「无自动 land」边界优先。
