# 《深入理解 AI Agent》第 8 章「模型后训练」精读笔记
> 源：/tmp/ai-agent-book/book/chapter8.md，共 960 行。多Agent精读批。

## 一、本章主张

1. 后训练方案先诊断再选：读不懂领域材料→补语料（Mid-training）；能理解但工具参数总错→示范（SFT）；偶尔成功但走弯路→奖励（RL）；不同问题对应不同数据与目标函数 (L5, L400–411)。
2. 数据和环境比算法更重要：掌握 PPO/GRPO 基本机制后，主力应投入语料覆盖、示范质量、环境反馈与奖励设计 (L9)。
3. 四环节各自的学习信号：预训练/Mid-training 监督大量文本 token，SFT 只监督示范输出 token（loss masking），RL 评价策略自己生成的轨迹 (L17–26, L50, L54)。
4. loss masking 是 SFT 的关键工程：系统指令、用户问题、工具返回是上下文不是监督目标；把订单内容标作助手输出会教模型自己续写本该环境提供的信息 (L54)。
5. 先 SFT 后 RL 的常见用途是先稳定输出协议：格式不可解析时奖励无法细分任务能力 (L68)。
6. 起点检查用 Pass@1 与 Pass@k：Pass@1 低而 Pass@k 明显上升说明成功路径已存在可被放大；合理预算下仍少成功则先补知识/格式 (L70–76)。
7. 全零奖励组学不出东西（GRPO 组内优势为 0）：先补示范、中间反馈提高采样命中，再扩 rollout (L78)。
8. 有限 SFT 示范易记住表面映射（J/Q/K=10），规则变化时退化；RL 在分布外更好——SFT 记忆、RL 泛化 (L84, L487–497)。
9. 后训练会改变「何时行动」：示范反复呈现的探索顺序会被学进参数；读→改的转折点是两种收益的取舍 (L100)。
10. 在线交互三类学习机会：尝试示范外的做法、利用验证比生成容易的任务、在策略实际到达的状态上学习（协变量漂移）(L102–106)。
11. RL 环境工程顺序：任务蓝图→可重置环境→结果验证→训练/评估隔离→真实交互校准；环境建设成本常超训练本身 (L597)。
12. 模拟器必须校准：总返回正确文档的搜索模拟器教不出识别噪声；「合成交互—真实任务评估—修正模拟器」闭环 (L587)；只会说「已修改」却查不出状态变化的环境会奖励会说话的策略 (L589)。
13. 训练/评估可共享生成器与验证代码，但任务实例必须分集合；验收测试、隐藏状态、参考解法留在验证器一侧 (L595)。
14. 奖励优先可验证（RLVR）；验证器覆盖范围决定训练在优化哪些要求——每个未经验证的评分项都可能让模型沿新代理指标优化 (L661, L689)。
15. Reward hacking 与 reward seeking：模型按自己推测的评分方式行动、自选易通过的检查然后收工；验收条件应从用户目标出发覆盖真实交付物 (L667)。
16. 两条人工轨迹先行验证器：甲真办、乙只说办了，若同分则先查评分器读了什么——小反例暴露代理指标，省去整批训练后才发现 (L669)。
17. 路径约束（RLVP）「奖励结果、惩罚路径」：可观测动作触发的违规扣分只摊到违规轮的动作 token，同一次成功中的合规动作不吃罚分 (L693–706)。
18. 在轨蒸馏让学生在「自己实际走到的状态」上获得教师逐 token 监督：一次昂贵环境交互产生 T 个位置的信号，而非一个成败分 (L728–748)。
19. 特权信息只进教师分支（OPSD）：标准答案进训练侧构造教师前缀、不进部署输入；教师输出 stop-gradient (L779–793)。
20. 第七章评估材料直接映射训练用法：端到端任务→RL 采样与奖励；轨迹前缀→DPO 偏好对/在轨蒸馏输入；失败位置→过程评价标签与路径惩罚规则；Rubric 得分→多维奖励 (L799–808)。
21. 「过早结束」修复须双向评估：只降过早结束率会让已完成的任务也迟迟不收尾——两组任务（未完成组+已完成组）分开测 (L824)。
22. 识别两种能力的差别（DPO 案例结论）：在两段现成回复中认得何时该停，与自己写回复时仍一味再查，是两回事；「说出继续验证」与「拿到验证结果」是两步 (L834)。
23. 精确复制错误的定位沿传递链：原始字节→工具返回→序列化→上下文→模型输出→解码→参数解析→工具匹配，找第一个意外差异；输入侧完整而差异首现于生成处才进训练数据 (L854–856)。
24. 诊断卡三件套：失败前模型真正看得到的输入 + 至少一个可接受动作 + 一个表面相似却不应照做的对照 (L868)。
25. 采样与训练数值一致性是训练启动前核心检查：更新前比较两侧 log probability，监控概率比/KL/裁剪比例 (L546–563)。
26. 验收「从反馈学会判断」要换场景再考：同一决策换新条件（新金额、新约束）分别测，两题一律同动作提示只记住了表面动作；再回放旧版能办好的任务防遗忘 (L894–896)。

## 三、缺口汇总

**G4 验证材料隔离的可核对化**（sediment.md「留下」清单补一行判据）
- 拟落文案：留下的复现还须与起草证据「题目面不相交」——不是仅路径不同，而是任务实例本身未在起草中出现过（同模板换实例可接受）；同实例换路径跑出的第二份结果不算第二份证据。挂靠 sediment.md 既有「至少两份结果文件，路径不同，内容也不同」，作为「内容也不同」的实例级释义，不新增编号。
- 书里依据：L595（训练/评估共享生成器与验证代码，具体任务划分为独立集合；按任务模板或业务类型划分）、L812（用于训练的任务要与留出评估任务分开）、L382（集合相同即清单吻合也无法判断第三条样本是否用过——证据的边界）。

## 四、勘误与存疑

1. L76「等到首次成功平均需要 1/p 次尝试」假定独立固定成功率，与 L109（第三章同书）自述的「共享状态、缓存或相同故障会使多次运行相关」相抵触——书内两处口径不完全一致，工程上按保守侧理解。
2. L360 CoT 蒸馏实验（23 条轨迹微调 1.5B，1→2 题，p=1.0）结论诚实：样本过小不显著，但正文行文容易让读者把「学生答对 2 题」当成方法有效的证据——读书时以配对检验结论为准。
3. L467 AdaptThink 训练「原计划 3140 步、异常中止、停在 410 步」，所报 MATH500/GSM8K/AIME 数字是中途验证值——直接引用这些数字作决策依据不可靠。
4. L493「允许 10 次验证的一组提高 5.99 个百分点」与「只验证 1 次的提高 0.48」的对照缺少计算预算的对齐说明（验证次数本身消耗采样），方向性参考。
5. 与 idev 场景无关而留书：预训练/Mid-training/SFT/RL/PPO/GRPO/DPO 全部算法与公式细节、LoRA 配置、经典 RL 与 MDP 背景、语音/多语言/机器人（VLA）实验、训练-推理数值一致性、NGU 追加采样、DreamGym/ZeroSearch 模拟器实现。idev 明令「不训练参数、不按分数改写 Skill」（self-evolution.md），本章主体属模型层，故绝大多数「不落」。
