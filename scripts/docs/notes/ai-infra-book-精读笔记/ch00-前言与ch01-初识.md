## 〇、前言主张（并入本章总论）

前言是全书方法论的定调：编程抽象从操作系统上移到模型上下文（L11）；「从约束推导设计」——先明确任务与质量要求，再列计算、存储、通信和依赖，逐一纳入约束以排除不可行方案（L21）；数据搬移五问（搬什么、搬多少、搬几次、经过哪里、谁必须等它，L61）是贯穿各层的分析线索；量化估算先行（back-of-the-envelope，L15–17）。前言还给出一个对 idev 直接有用的证据：AI 模型做性能估算同样会系统性地漏约束——漏 KV 读取、漏容量合计、漏带宽供给、漏卡间通信、漏串行等待，漏一项结论可偏几倍到几个数量级（L19）；对应的纪律是「估算不必一开始就精确，但必须知道自己算进了什么，还有什么没有算进去」（L21）。以下判据对照把前言与第 1 章合并处理。

## 一、本章主张

1. 编程抽象正从操作系统迁移到模型上下文，模型成为 LLM 时代的"操作系统"、AI Infra 成为"计算机体系结构"（前言 L9–11）。
2. 全书方法论＝从约束推导设计：先明确任务与质量要求，再列计算/存储/通信/依赖，检查容量、带宽与等待，再谈分工与组织（前言 L21）。
3. 数据搬移五问是逐层可复用的分析骨架：搬什么、搬多少、搬几次、经过哪里、谁必须等它（前言 L61；ch1 L361）。
4. 数量级估算先行（Jeff Dean 式纸笔估算），几步计算即可判断方向是否值得继续、先解决哪个问题（前言 L15–17；ch1 L109）。
5. AI 做数量级估算会漏决定结果的基本约束（KV 缓存、容量合计、带宽持续供给、卡间通信、串行往返），漏一项结论偏几倍到几个数量级（前言 L19）。
6. 估算不必精确，但必须列出已计入项与已知未计入项（前言 L21）。
7. 先按第一性原理算出硬件允许的上限，再看系统离上限多远——下界/实测之比（MFU/MBU）回答"设计离物理极限多远"（前言 L25；ch1 L170、L365）。
8. 跨层理解是效率来源：最懂 Infra 的人做算法、最懂算法的人做数据；系统效率要求能反向推动模型架构本身（前言 L47–53）。
9. 负载种类少且事先已知时，可以打破通用平台的抽象边界做跨层联合优化（ch1 L27、L438）。
10. 一次请求沿六层分工下移；先分清谁负责执行，才能知道一份数据放在哪里、传给谁（ch1 L29–57）。
11. 外部请求只有一小段文字，内部搬移的数据（权重、状态、中间张量）大得多（ch1 L69）。
12. 数量级延迟表先识别操作，再比较它们在串行等待中的代价；某部分在原总时间中占比越大，缩短它对整体改善越大（ch1 L130–148）。
13. Amdahl 定律适用于任何只加速部分环节的完整流程：局部提速要放回完整任务衡量（ch1 L142–154）。
14. 四类关键数字分别进入估算：容量（能否放下）、计算吞吐（F/Π）、带宽（R/β）、延迟；保存一次与读取多次分开计（ch1 L160–181）。
15. 容量检查是三项相加：权重＋状态＋工作区 ≤ 可用容量，且多卡须逐卡核算（ch1 L217–223、L448）。
16. 读取与计算能否重叠，决定耗时取 max 还是相加（ch1 L281–287）。
17. 优化应对准时间下界最大的项：本例权重读取下界约为矩阵计算的 148 倍，提算力不缩短总时间（ch1 L277–293）。
18. 批内复用提高吞吐，但每个请求仍经历排队与整批执行；吞吐与单请求延迟必须同时报告（ch1 L299–305、L454）。
19. 实测与下界的差距二分归因：理论模型漏项（修正估算）或实现开销（可去掉），靠每次只改一个条件的测量区分（ch1 L365）。
20. 需求与硬件的变化最终都体现为"比例的改变"，比例一变原先合理的分工不再合算（ch1 L369、L442）。
21. 沿用旧设计前先检查它依赖的比例（前提）是否仍成立；上一代场景成熟的系统照搬新负载会失败（ch1 L440、L452）。
22. 大判断（如提前投万卡互联）须把所依赖的趋势、资源与代价讲清楚——看清眼前负载与正在变化的条件（前言 L33–35）。

## 三、缺口汇总

**G1　数据流量化五问（搬什么/搬多少/搬几次/经过哪里/谁必须等它）**
- 落点：conventions/canon.md §5 A6 扩句（或 deliver/SKILL.md arch 自查第 5 步补一行）。
- 拟落文案：「方案涉及数据在层 / 服务 / 存储间流动，或带性能主张时，design.md 须按五问给数量级估算：每段搬什么、单次多少量、累计几次、经过哪条路径（对应什么带宽 / 配额）、哪些步骤必须串行等它；算不出的段标 UNPROVEN，禁止只写『应该更快』。」
- 书里依据：前言 L61、ch1 L361（五问收束全章估算）、L69（外部小内部大）、L85（三种流量频率/数据量/依赖不同）。

**G2　性能类验收同时报总量指标与个体指标**
- 落点：deliver/references/req-quality.md §1 SMART 指标补一行示例（最小改动；不进 canon）。
- 拟落文案：「性能类目标须同时给总量指标（吞吐 / 完成量）与个体指标（单请求 / 单用户 P95 延迟），只给其一视为待拷问项——批内复用可推高吞吐而个体等待变长。」
- 书里依据：ch1 L301–305（吞吐 383 token/s 与 TPOT 26.5→40.5ms 同报）、L454（谬误：吞吐提高≠用户等待缩短）。

**G3　优化先对上界，差距二分归因**
- 落点：conventions/canon.md §3 T9 DO 扩句（并入既有条目，不新增编号）。
- 拟落文案：「优化前先按资源与工作量推出可达上 / 下界，实测与界之差按二分归因——估算漏项（补项修正估算）或实现开销（定位后消除），靠每次只改一个条件的测量区分；『比旧实现快 X%』没有上界对照不算结论。」
- 书里依据：ch1 L365（MBU 33%→补测拆出主机开销，差距三倍大部分是可去掉的系统开销）、L450（谬误：快三成≠成功）、前言 L25（close to physical limits）。

**G4　沿用既有做法须核对成立前提**
- 落点：conventions/canon.md §5 A7 扩句。
- 拟落文案：「A7 沿用的每个现有做法写明其成立前提（当时的负载量级 / 环境条件），本票条件下前提已变的不直接沿用，改为改造或进被拒方案。」
- 书里依据：ch1 L440（比例变后旧方法需重新计算合算性）、L452（误区：上一代成熟的系统直接用于新负载）。

**G5　数量级估算附已计入/未计入清单**
- 落点：deliver/references/req-quality.md §5「写清假设与范围」句内补强（并入既有条目）。
- 拟落文案：「数量级估算随附两行清单：已计入项、已知未计入项；未计入项中足以改变结论的列为待补测，不静默忽略。」
- 书里依据：前言 L19（AI 估算漏约束清单）、L21（必须知道算进了什么、没算什么）。

## 四、勘误与存疑

1. 数字自洽性抽验通过：Amdahl 算例（20%/30%/70%/80% 编码占比 → 1.19/1.32/2.27/2.78 倍，L150–152）、20 次寻道 201ms 算例（L138）、读取下界 70GB/3350GB/s≈20.90ms 与 148 倍比（L274–277）、B_*≈147.7（L307–313）、批吞吐 47.9→383 token/s（L301）均可复算。
2. 前言 L19 提及「GPT-6 Astra、Claude Fable 5.1」为 2026 写作时点的模型名，属时效性内容；方法论不受影响，拟落文案不引用这些名字。
3. Jeff Dean 延迟表为 2009 年环境（书已自我声明，L111）；若引用应注明年代，不宜直接当现行数字。
4. ch1 L484 脚注自承补测「关闭逐步日志的影响无法与前缀缓存等条件完全分开」——书对实验边界的诚实标注可作 G3 文案中"单条件变化测量"的正面样本，也提示该组数字只能作趋势证据。
5. 存疑不落章：全书把「模型上下文」类比操作系统、把 MFU/MBU 当通用尺，均限于 AI Infra 域；提炼时只取其"先算再选、差距归因"骨架，不引入域内指标名。
