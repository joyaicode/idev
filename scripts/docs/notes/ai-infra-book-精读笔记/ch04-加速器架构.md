## 一、本章主张

1. 评价一项局部改进，要看整个任务能缩短多少时间——同一矩阵单元翻倍，占 60% 时总加速 1.43，占 10% 时只有 1.05 (L3, L106–112)。
2. 权重复用使计算量增长快于访问量，算术强度随行数上升且有极限 (L55–63)；带宽容量的收益随 batch 递减 (L63)。
3. 每个部件要回答三问：数据离计算单元多远，能够复用多少次，下一步何时可以读取 (L11)。
4. 缓冲与计算单元是同一份芯片面积预算的两面：缩缓冲增重读可能抵消新增乘加器的收益，为极少复用的数据配过大缓冲同样浪费 (L114–116)。
5. 功率密度 = 功耗比 / 面积比；总功耗下降而散热压力未必减小 (L138–150)。
6. 带宽只决定一步多快，不改变一步耗多少能量；数据复用首先是能耗问题，其次才是带宽问题 (L179)。
7. 单请求 decode 的能量几乎全部消耗在搬移上（权重读取占 90%）；降低能量只有两条路：让字节从更近层次取来，或让同一字节服务更多 token (L165–173)。
8. 峰值算力是物理极限但非任何条件下可达：功率封顶时持续频率 = b/e 或 (b/e)^(1/3)，衡量利用率应以持续算力为分母 (L215–221)。
9. 有效带宽 ≤ min(接口带宽, N·s/L)：Little 定律——依赖链上的每次访问承受完整延迟，队列再深也填不满 (L451–463)。
10. 容量、带宽、延迟分别限制什么：容量决定能否驻留，带宽决定传输时间，延迟 + 在途并发决定能否维持带宽 (L439–441, L483)。
11. 双缓冲用额外空间换加载与计算的时间重叠；槽位数以「最慢单元连续工作」为目标求最少，第四个槽不缩短完成时间 (L521–574)。
12. 分组、增槽、直接交接各省不同的时间：分组让向量单元提前开始，双槽让相邻组重叠，直接通路减少交接流量；超过必要后继续加槽收益为零 (L600–612)。
13. 矩阵加速后瓶颈向指数 / 共享内存转移——提高一种资源只减少等待，直到另一种资源成为瓶颈；稳态吞吐由最慢单元决定 (L307–327)。
14. 传输时间 = α + V/R：固定开销与字节数各自主导不同规模；小于转折点 V* = αR 时合并传输省启动开销，大于时省字节 / 提带宽 (L699–723)。
15. 先画出每种方案经过链路的数据，再比较总量——计算放在权重所在一侧，链路上只传输入与结果 (L658–674)。
16. 预测与实测有差距要先拆解：口径修正（逻辑请求 ≠ DRAM 流量）与实现开销（kernel 启动、提交、同步）是两类，先修正口径再去掉开销，两步都不能少 (L1056–1060)。
17. 「忙了多久」与「工作时执行得多快」要分开：S/T = (S/A)×(A/T)；两个 40% 利用率的优化方向完全不同 (L1089–1097)。
18. 能耗由功率与时间共同决定：功率增 28% 而每步能耗反降 28%，因时间缩短 (L1117)；利用率减半则速度翻白的单位成本不变 (L1115)。
19. 专用化的回本量 = F0/Δc，且必须在模型寿命内完成；模型寿命减半或利用率减半都直接抬回本规模 (L1125–1143)。
20. 容量有阶梯效应：剩余空间不足以容纳一条新请求的全部状态时，多出的内存并不增加并发 (L405)。
21. 硬件效率与软件责任一起比较：每个专用化机制都同时定义「硬件节省什么」与「软件必须安排什么」(L910–916)。

## 三、缺口汇总

本章硬件与 kernel 层内容绝大多数「不落」——idev 的判据落在需求评审 / 拆解 / 架构 / 编码 / 测试 / 排障，芯片微架构、HBM 堆叠、功耗物理、同步指令不在任何阶段的裁定范围内。真正可迁移的是「容量规划」「瓶颈归因」「测量口径」三条思维线。对照后真缺口仅 1 条：

| # | 落点文件 + 节 | 拟落文案（判据式一句） | 书里依据行号 |
|---|---|---|---|
| G5 | conventions/canon.md T9（并入「测量方法须可信」句） | 性能与预测有差距时，先分「口径差」（模型口径漏了缓存命中、固定开销等未计项）与「实现差」（可去掉的额外工作）两类，先修正口径再计开销，两类不得混算成一笔。 | L1056–1060, L1081–1087 |

「不落」归因明细（代表性）：
- 芯片面积 / 功耗 / 光罩 / HBM 堆 / 功率封顶 (L102–221)：硬件物理约束，无对应生命周期阶段。
- 矩阵块补零 / 专家分派均衡 / kernel 选择 (L241–263)：算子库与编译器域。
- 双缓冲槽位 / fence / 同步层级 (L521–648)：GPU / 异构编程域；T10 只取其「唤醒后重查条件」同构精神，已载。
- 专用架构 (TPU/Groq/Cerebras/ROM) (L874–958)：芯片选型域；其回本判据由 T9 寿命上限覆盖。
- Roofline / 执行时间模型 (L986–1013)：性能工程方法，A6「瓶颈可追溯到 SLI/SLO」已载其「先算再比」精神。

## 四、勘误与存疑

- 数字自洽性抽查通过：能耗分账 15.137 GB × 31.76 pJ ≈ 0.481 J，合计 0.534 J、权重占 90% (L168–173)；0.60 pJ/FLOP 预算 = (700−106) W / 989.4 TFLOP/s (L210)；HBM 堆带宽 1024 × 9.6 / 8 ≈ 1229 GB/s 与 1.23 TB/s 一致 (L191)；在途事务 128 × 128 B / 500 ns ≈ 32.8 GB/s (L471)；Roofline 转折 M* = I*d/(d−2I*) ≈ 178.1 (L1007–1013)；开销转折 V* = αR = 2μs × 450 GB/s = 900 KB ≈ 879 KiB (L719–721)；回本量 2×10⁷ / (0.5/10⁶) = 4×10¹³ token，年产出 100 × 10⁴ × 0.5 × 3.15×10⁷ ≈ 1.58×10¹³，需 254 台 (L1133–1141)。均与正文结论一致。
- 存疑（不可核验的 2026 素材）：OpenTallas 掩模 ROM 项目 (L920–958, 笔者自述项目，属设计构想而非已验证产品)；HGX B200「180 GB / 8 TB/s」与 Blackwell 简报「192 GB / 7.7 TB/s」两口径并存 (L199, 正文已自行标注取用口径)；LogicFolding 论文（ChinaXiv 2026）的 NPU 降压 66% 数据 (L128–136)；Rubin 指数吞吐 4×、TMA 更新专家地址 (L769)；M5 Neural Accelerator 与 Metal 4 Tensor API (L860)。这些按当前知识无法核实，笔记只取其「量化推导方法」，不引用其数字作事实依据。
- L207 功率封顶算例中「扣除后留给计算的是 594 W」用了 HBM2 行的 31.76 pJ/byte（28 nm 工艺能耗模型）估算 HBM3 满带宽功率，正文自己声明了这是量级估算 (L163)；引用时不可当作精确分账。
- L945「上下文增长到 32K，每条请求的 KV 读取增至四倍，权重与 KV 交点便从约 12.5 条降至约 3.13 条」：交点 B=W/(K) 中 K 增至四倍，B* = 12.5/4 = 3.125，自洽。
- L98 句「910B/910C 分开控制 AIC 与 AIV，950 又用 CV 通路」与 L811、L817 同一事实在三处重复陈述（不同小节各自服务论证），非矛盾。
