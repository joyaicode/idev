## 一、本章主张

1. 平均请求率 × 平均工作量不足以确定资源需求；到达顺序与请求组成改变短时间内的资源压力 (L3–5, L75, L701)。
2. prefill 与 decode 使用同一份权重但资源性质不同：输入行多时偏算力受限，低并发 decode 偏内存带宽受限 (L19)。
3. 只把总 token 数相加，会丢失这些 token 属于哪个阶段、何时能够执行的信息 (L21)。
4. 评估系统先写出「什么算任务完成」，再决定统计什么指标 (L29)。
5. 把某段时间缩短，只会直接改变包含这段时间的指标——减少排队改善 TTFT，不会自动缩短已开始生成后的 token 间隔 (L38)。
6. 只看平均值会掩盖较慢的一部分请求；p95 等百分位单独描述较慢部分 (L57)。
7. 等待期间的状态占用按空间 × 时间计账（byte·s）；稳定时仅等待任务的平均占用约为 λM0τ (L59–65)。
8. 工具等待期间上下文仍要保留；工具执行时间越长，状态保留越久，系统能同时处理的请求越少 (L65, L248)。
9. 成功任务成本 = 全部尝试（含失败生成、工具测试、环境运行）的成本 / 成功任务数；零成功的 batch 只记消耗与失败原因，不能估计成功成本 (L71, L703)。
10. 先前空闲的计算时间无法留到现在使用——全局均值掩盖积压 (L75, L115)。
11. 排队既可能来自处理速度不足，也可能来自已有请求的状态尚未释放：状态池填满后，即使计算单元空闲，新请求也要等 (L137–139)。
12. 缓存复用减少重算，却没有把旧上下文从后续计算中删除；可复用前缀长度取决于改动发生在哪里，不取决于改了多少字 (L159, L167)。
13. 是否值得增加生成计算（延长思考、多采样），判据是正确率相对提升能否超过成本相对增长（p2/p1 > c2/c1）(L175–181)。
14. 局部加速的收益取决于被加速段占总时间的比例（Amdahl）：首轮占 47.5% 减半只省 23.8% (L228–230)。
15. 并行缩短关键路径，同时让更多分支的状态并发占用内存——时间收益与状态代价同时发生 (L232–246)。
16. 每类数据的保留期限取决于最后一次使用它的操作：某层激活在该层反向用完后释放，优化器动量须跨多次更新保留 (L404)。
17. 6ND 粗算必须逐项修正（漏掉注意力二次项、多算了不做完整矩阵乘法的参数）；只有修正后的下界才能用来衡量利用率 (L458)。
18. 已生成的样本数决定生成开销，最终进入更新的样本数决定训练 batch，两者数量未必相同 (L486–494)。
19. 拟合只保证曲线贴近拟合点；预测力必须用排除在拟合之外的留出样本检验 (L577–589)。
20. 计算最优（固定训练预算下）与全生命周期最优是不同目标函数；实际训练投入超出计算最优一至两个数量级，不表示拟合错了 (L625, L707)。
21. 训练预算与服务调用量共同决定模型选择：成本交点 Q* = ΔC0/Δc，预期调用量低于交点时额外训练成本尚未收回 (L675–681)。
22. 负载描述须保留到达时间、输入输出长度联合分布、工具依赖、分支与复用间隔等执行过程字段，不能只留总量 (L77, L691–693)。
23. 任务的完成标准必须具体到可执行的验证；返回值正确性与输入不变是两种不同性质的检查，通过其一不代表另一 (L220)。
24. 答案检查应区分接口格式正确与内容正确：格式对的回答可能算错，数值对的回答可能缺字段；两类错误分开才能判断该调生成、输出约束还是解题过程 (L185)。

## 四、勘误与存疑

- 数字自洽性抽查通过：例题 3-1 积压递推（1879.87 步/s × 60 s ≈ 112,792，/5591.33 ≈ 20.17 s）(L115)；CED 算例 20P+20min(P,128)=166,400 ≈ 327,680 的 50.8% (L258)；Jev 输入折算 0.000081×(10⁶/0.042)≈1929 token (L276)；成本交点 0.00129 GPU 秒 × 2.048×10⁸ ≈ 73.5 GPU 小时 (L597)；p95 最近秩法 ⌈0.95×4⌉=4 即最大值 (L57)。均与正文结论一致。
- 存疑（不可外部核验的 2026 素材）：Jev / TypeSafe AI 与 RLCD (L266–278)、DeepSeek V4 / V4.1 Flash CED (L256)、ServeGen NSDI 2026 (L79)、Qwen3-Image-2512 (L328) 等按当前知识无法核实。本笔记只取其方法论判据，不引用其数字作事实依据；若后续引用，须当教学算例并标注来源为本书。
- L44/L46：TTFT 定义为「请求到达 t_a 到首个 token 返回 t_1」，而 reasoning 模型「首个内部 token 出现时用户未必看到答案」——正文已自行区分（另记首个有用输出），无矛盾，但引用 TTFT 判据时须注意口径是哪一个。
- L99 流体队列「窗口内均匀到达、处理率固定」是教学近似，正文自己声明了「请求组成改变后该固定值不能当各时间窗的带宽上界」(L113)；引用该模型时不可省略这一边界声明。
- L220「两组检查对应两种不同的程序性质」：返回值正确 / 输入不变 / 无别名三项检查的区分是本章「可执行验证」的最佳佐证，G4 的判据即由此提炼。
