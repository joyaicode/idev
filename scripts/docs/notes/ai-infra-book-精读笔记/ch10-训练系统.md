# 《深入理解 AI Infra》第 10 章「训练系统」精读笔记

> 源：/tmp/ai-infra-book/manuscripts/10-训练系统.md，共 977 行。多Agent精读批。
> 方法论对齐：本章把「容量约束（能否开始）」与「时间约束（能否按期）」连成一份从任务倒推资源的完整权衡账，其推导链条（状态生命周期→关键路径→长期附加成本→完成期限）与 idev 的 A4/A6（数据与恢复目标、容量与失败域）同构。判据只落「该不该做、做在哪层」。

## 一、本章主张

1. 全参数训练状态约为 BF16 权重的 8 倍（每参数 16 bytes：权重 2+梯度 2+FP32 主权重 4+两矩 8）；能推理不等于能训练，容量是第一道门 (L5, L65–79)。
2. 显存峰值取决于同一时刻驻留的状态+激活+临时缓冲，而非任何单项；容量优化只有两个方向——减少张量大小，或缩短需同时保留的时间 (L88–94)。
3. 分片数翻倍，常驻状态减半，峰值不减半（小实验：18→9 MiB，峰值只 39→30 MiB，执行期其他张量仍占 21 MiB）——「分片数×每片大小」的除法在峰值上不成立 (L205)。
4. 微批次求平均的分母决定每个 token 对梯度的贡献：按 token 平均、按回答平均、累二次除，三个不同结果（0.32/0.30/0.04）——目标函数的实现细节改变训练语义，是正确性问题不是性能问题 (L313–321)。
5. 比较任何调度都要看两根轴：完成时间（气泡）与显存驻留（激活保存多久）；没有调度在两轴同时占优——1F1B 换来峰值降 62%，时间上反而慢 3%；峰值不够不是变慢，是根本跑不了 (L330, L360)。
6. 压缩气泡的三种扩展（交错/零气泡/双向）各以另一资源为代价（通信次数/激活驻留/参数量翻倍）；且收益随 micro-batch 数增大而递减，代价不随 m 缩小 (L362, L408)。
7. 通信完成的时刻（而非通信处理时长）决定它是否延长训练步：三个小桶总处理时间更长（4.59>4.55 ms）却因各自落进空隙而更快——同理，消除已重叠的通信，收益上限就是暴露的那段 (L412–414, L436)。
8. 梯度桶大小在「早发送」与「少启动」之间权衡；dX 与 dW 的执行顺序重新分配通信窗口——排序即调度资源 (L412, L424)。
9. 路由不均→容量因子是「丢 token」与「补零行」的交换：c=1.0 丢 25%，c=1.5 零丢但 33% 是补零；容量规则是显式声明的不均处理规则，不是隐式默认 (L448–471)。
10. 相同 token 总数下序列长度不均使注意力配对数最多增 56%（8192 拆 7168+1024 vs 4096+4096）；比较调度方案须固定长度分布/掩码/损失权重，才能把调度收益与任务变化分开 (L477–487)。
11. 输入准备是多级流水：GPU 收到的字节量小（0.37 MB/s）不等于准备过程快（CPU 准备进程数会先成瓶颈）；预取队列只能缓冲波动，长期供不应求队列必被取空 (L497–499)。
12. checkpoint 的可用性由「提交完成时刻」决定，不由「API 返回时刻」决定：同一份前台暂停 1s，写带宽 7 GB/s 时故障重做 30s，20 GB/s 时只重做 10s；元数据提交（48ms）前终止，只能选上一份完整的 (L541–553)。
13. 最优保存周期 τ*=√(2c/λ) 平衡「保存成本」与「故障重做成本」：卡数翻倍→故障率翻倍→最优间隔缩 1/√2；曲线平缓，便于选可操作的整数值 (L557–586)。
14. 损失尖峰的回滚与硬件故障在保存周期模型里同价——把 λ_spike 与 λ_hw 相加；尖峰越频繁，保存周期几乎只由数值稳定性决定 (L618–625)。
15. 同步数据并行的步时间由最慢卡决定（期望最大值 μ+k(N)σ，N=1024 时多等 3.25σ）；慢卡的三种响应（等待/重分配/驱逐）各有条件：驱逐代价 τ/2+r（约 8 步），偶发抖动不值得，持续多步才值得——响应方式跟着持续性走 (L604–616)。
16. 生成→验证→学习三阶段的有效吞吐是 min(r_l, q·min(r_g, r_v))：优先扩容最慢阶段，加错阶段不动瓶颈 (L649–655)。
17. 训推一致性是正确性约束：logprob 误用重算值代替行为策略记录值（−3.25 vs −3），参数没变，样本权重却虚增 28%；路由重放记录离散 ID 让生成与训练走同一路径——跨引擎数值差异必须显式对账，不能默默混用 (L705, L743–757)。
18. 异步收益要扣过期样本：异步更快要求保留率 q>11/15；q=0.7 时周期更短、有效吞吐反而更低——进度数字必须按「有效产出」计，不按「批次处理量」计 (L727–733)。
19. 一阶完成时间模型 T_finish=T_0+⌈D/b⌉·t_s(1+L) 把容量/关键路径/恢复/停顿连成一份账；预算反推（48 卡余量 14.4 s/步）落到执行过程，两方案在 30 天期限上一淘汰一入选，数字给决策收口 (L769–810)。
20. 加速器替换的价值由原有等待占比决定（T'/T=1−f+f/r）：暴露通信仅 0.14% 时带宽减半几乎无影响，计算效率降 10 个百分点即超期——钱花在被等待时间最长的资源上 (L818–831)。

## 三、缺口汇总

**G10-1 统计口径是契约的一部分**
- 落点：conventions/canon.md §3 T13（契约语义变即换名）DO 句尾挂靠；同时在 experts.md `arch` 行「统一语言词表」已覆盖概念名，此条补「口径」维度（并入 T13 之「语义」定义，不新增编号）。
- 拟落文案：「对外报告的统计数字（吞吐/成功率/进度）必须写明口径：分子分母各取什么、按什么单位平均——口径变即语义变，沿用旧名而改口径＝改了契约。」
- 书里依据：L313–321（按 token 平均 0.32、按回答平均 0.30、累二次除 0.04，同数据三种口径）；L727–733（异步吞吐按有效样本计，q=0.7 时批次更快而有效产出更低）；L785–789（C_effective 分母为「满足质量与时限的请求数」，提前退出的 Agent 不计入）。

**G10-2 恢复状态清单按「丢什么会改变行为」枚举**
- 落点：conventions/canon.md §5 A4「数据真相之源、派生/副本…恢复目标」句（并入该句）。
- 拟落文案：「恢复状态清单的完整性判据：逐项问『丢了这一项，恢复后的执行会与不中断时不一致吗』——会者必须入快照；清单外的隐式状态（缓冲残余、随机状态、进度位置）是最常见的漏项。」
- 书里依据：L511–527（权重+一阶矩+二阶矩+步数+学习率状态+随机状态+数据读取位置；打包器丢 2000 个残余 token 即改变下一条序列的前缀/注意力关系/标签）；L501–507（预取进度 108 vs 训练进度 100，恢复直接跳到 109 会跳过 8 个 batch）；L515（权重相同而矩状态不同，下一次参数更新便不同）。

**G10-3 跨端/跨引擎数值必须带来源标记，禁止静默混用**
- 落点：conventions/coding-tables.md §2 C23（多步调用依赖隐式状态）行挂靠——跨端概率/ID 属「后步依赖前步留下的隐式状态才能正确」的分布式版本；或并入 canon §2 信号表「新增跨服务调用链…无关联标识贯穿」行（已有 T11 命中）。
- 拟落文案：「同一数值在生成端与训练端（或任意两端）分别计算时，必须记录其来源与版本（谁算的、何时、哪份权重），使用处显式对账；直接以一端重算值顶替另一端记录值而不标记，视作 F2 幻觉依赖。」
- 书里依据：L705（logprob −3 记录值 vs −3.25 重算值，参数未变而权重虚增 28%）；L743–757（MoE 离散路由对数值差异敏感，0.301→0.302 即换专家；路由重放须记样本+token 位置+层号，且 ID 记录随打包/切分变换共同移动，错位即用错专家）；L707（不同注意力实现/归约次序/batch 形状/精度让同权重同前缀 logprob 不同）。
