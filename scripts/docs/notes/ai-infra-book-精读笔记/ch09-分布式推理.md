# 《深入理解 AI Infra》第 9 章「分布式推理」精读笔记

> 源：/tmp/ai-infra-book/manuscripts/09-分布式推理.md，共 927 行。多Agent精读批。
> 方法论对齐：本章通篇是「从约束推导设计」的数据搬移五问（搬什么/搬多少/搬几次/经过哪里/谁必须等它），与 idev 的权衡记录（T12）同构；以下只提炼「该不该做、做在哪层」的判据，不抄目录、不摘段落。

## 一、本章主张

1. 上下文变长后状态可能比权重还大（batch 32 时 KV 43.5 GB ≈ 权重的 2.7 倍），状态放哪里、如何交接与计算分工同等重要 (L3)。
2. 资源稳定条件是 λd_r<n_r：占用率打满后突发永久积压，只有增加资源才能消化，排队论不给免费午餐 (L43–49)。
3. 同构集群上 PD 分离不提升吞吐（整数划分反而闲置一池），换的是延迟稳定；分块 prefill 通常是更先的选择 (L175, L179)。
4. 异构分离的收益来自硬件本身的差异，角色对调吞吐不到正确分工的一半——分离不是通用加速，是资源特长匹配 (L200)。
5. 请求组成改变最优配比：前缀命中把资源推向 D，输出变短推向 P；配比是负载的函数，不是一次定死的常数 (L216–228)。
6. 状态交接期间两端同时占用内存（双缓冲），分块确认可提前释放、缩短双驻留；完成标记只规定「先写完、后使用」的顺序，不搬数据 (L140, L144)。
7. 换状态表示（GQA→紧凑 MLA）把交接字节减半、链路项翻倍，但 D 侧新增计算随 batch 增长——省字节的代价可能是瓶颈位置移动，需按新转折点重推 (L127–134, L206)。
8. 专家放 CPU 还是 GPU 由每个专家收到的输入行数决定：低复用时避免搬 36 MiB 权重比算力差异更有价值，交点由 kernel/带宽定 (L254–256, L276)。
9. 决定完成时刻的是最忙的那张卡/最长的那条等待，不是平均值——汇总类操作的天性 (L352–356, L477–481)。
10. 均衡策略先判瓶颈类型再选方向：读取受限追复用、计算受限追分散，两者是相反目标，盲选会同时得罪两边 (L366)。
11. 修改专家选择规则（top-k）会改变模型行为，与资源均衡是两件事，必须分开评价——均衡手段不得伪装成透明的性能优化 (L426)。
12. 专家副本回本要算最少批数：同服务器 3 批、跨服务器 23 批；热点持续短于回本周期时复制是净损失，副本策略预测的是热点还会持续多久 (L434–437, L445)。
13. 缓存容量要覆盖复用间隔（C≥rT）；容量越大命中率提高越慢（超半数块永不再用），写入侧还要受寿命（SSD 1 DWPD）与带宽的准入约束——缓存是三方权衡不是越大越好 (L523–539, L589)。
14. 保存后取回与重算的切换有解析条件 T_write+kT_read<kT_recompute：链路带宽低于 KV 产生速率 r 时取回比重算慢，复用越多损失越大 (L551–559)。
15. 缺页时比较「继续等待」与「重新计算」各需多久：等待一旦超过整段重算时间就该放弃等待；恢复后还必须隔离或修复坏页，否则下一个请求撞同一堵墙 (L605)。
16. 路由比较的是完成时间 T_first=max(Q,R)+C 而非缓存命中标志；且优化目标（目标请求响应时间 vs 全部任务完成时间）必须在决策前声明——两者会给出相反的路由 (L609, L658)。
17. 启动积压按 λT_s 累积，排空速率由净消化能力 μ−λ 决定；净消化≤0 的方案积压永不消退，「就绪」与「恢复」是两个时刻 (L678–684)。
18. 在线迁移的收敛条件是复制速率超过状态增长速率（平行即永不追上）；最终交接点必须同时确定状态版本与执行权 (L698–704)。
19. 搬移接近链路物理下界后，剩余差距全是软件准备——更快链路解决不了，只能重构软件（提前建通信组、预捕获执行图、让准备与传输重叠）(L710–712)。
20. 输出已返回不等于 KV 已保存：恢复用已记录 token 补算可重建相同前缀，token 级 WAL 须在对外确认之前可靠落盘；恢复语义分「继续哪条序列」（输出记录）与「从哪里补算」（状态快照）两类，分开确认 (L716–726)。
21. 直接交接与经池中转的搬移次数差一倍，池的价值要用后续复用兑换；无复用负载下中转纯多付传输与等待 (L744–746, L768)。
22. 部署方案的判据是合计账：共改变了多少计算量与等待时间、积压多久消退；瓶颈在 D 时加 P 不消化积压，瓶颈在共享通道时加计算副本只会让更多请求等取回 (L801, L803)。

## 三、缺口汇总

**G9-1 缓存/复用键完整性**
- 落点：conventions/canon.md §3 T10 DO 之「② 派生与副本」（并入该句，不新增编号）。
- 拟落文案：「缓存与复用的键必须由生成该结果的全部输入维度（版本、位置、格式）决定；『内容相同』不等于可复用——键漏一维不会报错，只会静默复用错数据。」
- 书里依据：L497（模型与 adapter 版本、token 序列、位置索引、状态格式参与缓存标识；同 token 配不同 adapter 投影出不同 K/V；同后缀接不同前文上下文不同）。

**G9-2 恢复等待的上限＝重做成本**
- 落点：conventions/canon.md §3 T10 DO「恢复目标：可接受丢失窗口/恢复时长」句（挂靠该句）。
- 拟落文案：「恢复路径上的等待以重做成本为上限：等待取回/恢复一旦超过重做所需时间，即切换到重做路径，禁止无条件等待。」
- 书里依据：L605（已等 1s > 整段重算 0.856s；无条件等待的请求 60s 观察窗内未完成，允许放弃后靠重算得到结果）；L551–559（保存取回 vs 重算的解析切换条件，链路低于产生速率 r 时取回比重算慢）。

**G9-3 恢复/扩容要过「排空期限」检查**
- 落点：conventions/canon.md §5 A6「容量与失败域」（挂靠故障余量句）。
- 拟落文案：「恢复/扩容方案要过排空检查：恢复时长按『积压清零时刻』计而非『服务就绪时刻』——就绪后的净消化能力（服务率−到达率）为正且满足期限；净消化≤0 的方案排空时间为无穷，不可行。」
- 书里依据：L678–684（T_drain=λT_s/(μ−λ)；3.02 请求/s 方案积压持续增长，永不排空）；L775–778（按 60s 期限反推 μ≥4.2；效率九折即从余量 8% 变成错过目标——期限检查必须带敏感性）。

## 四、勘误与存疑

1. 记法歧义：L206「一次 decode 调用服务 B 条请求，就多 2.05B GFLOPs」——「2.05B」应读作 2.05×B（B 为批内请求数），易误读为「2.05 billion GFLOPs」；建议写 2.05·B。
2. 数字抽查一致：L57 与 L185 表（0.856+1.764=2.62 GPU·s；4/0.856≈4.67；4/0.878≈4.55；3.02 vs 4.51 倍）、L43「batch 32 时 KV 43.5 GB」（按 9216 token×144 KiB×32 复算吻合）、L127/L134（MLA 展开态 4.77 MiB 为紧凑态 71 倍；紧凑态为 GQA 的 0.48 倍）均通过。
3. 溯源层级提醒：H20 无 NVIDIA 官方数据表，BF16 算力/带宽取自 MegaScale-Infer 论文表 3（L856 已自披露）；DeepSeek V4-Flash RTX 5090 配置、Kimi K2 主存需求依据本书 experiments（[^capacity] L868），非厂商规格——引用时注意二级来源。
4. 边界备注：L559「临界带宽 1.41 GB/s 恰为 KV 产生速率 r」的等价，只在「重算成本与 KV 字节数成正比」假设下成立；换模型/表示需按 L557 重推（书已自注状态大小只进 T_write 与 T_read）。
5. 对照备注：任务书说恢复/重试语义对照 coding.md 的「R 档」——经核 coding.md 的 R1–R7 是重构满足条件，重试护栏真源在 canon T10（幂等/退避/预算）与 T11（重试分类/传播 deadline）；本章恢复三目标语义按 T10 失败语义对照即可，不动 R 档。
