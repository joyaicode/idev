## 三、真缺口

**零缺口。** 本书提炼出的通用工程原则（自动化、单一事实、依赖显式声明）均已由 T7 / T11 承载或属构建工具自身职责，没有需要落到既有编号上的新条目。

## 四、重点候选裁定（防后人重复发现）

1. **「构建必须显式声明依赖」不另立。** 这是 make / 构建系统的固有语义，不是编码或架构规范；把构建系统的依赖声明原则写进 canon 会越界到工具链，且不同构建系统（make / gradle / bazel / npm）语义不同，无法给出一致的可执行判据。
2. **「自动化构建 / 一次命令出产物」不另立。** 已由 T11 与仓库既有 `selfcheck.sh` / `check-feature.sh` 机制承载。
3. **隐含规则与模式规则不另立。** 是 Makefile 语法特性，不是通用原则。

## 五、不建议落的内容

- Makefile 语法与函数清单：构建工具用法，不进真源。
- 隐含规则一览表与搜索算法：make 实现细节，不进真源。
- 函数库文件更新规则：特定构建场景，不进真源。
- 各版本 make 差异与兼容性说明：工具版本事实，不进真源。
