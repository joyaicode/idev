## 三、真缺口

### 1. 变量 / 字段遮蔽（内层同名声明遮蔽外层，读写作用于错误对象）

**书中依据**：第 1 章 1.1「变量」——「注意检查，是定义新局部变量，还是修改全局变量。该方式容易造成错误」（L152）；「注意重新赋值与定义新同名变量的区别」（L185），并给出 `s, y := "hello", 20`（同一层次代码块，重新赋值）与 `{ s, z := 1000, 30 }`（不在同一层次代码块，定义新同名变量）两种形态与不同地址输出（L186–L192）。第 3 章 3.3「返回值」——「命名返回参数可被同名局部变量遮蔽，此时需要显式返回」（L894），示例 `func add(x, y int) (z int) { { var z = x + y; return z } }` 必须显式 `return z`，否则 `return` 报「z is shadowed during return」。第 4 章 4.4「Struct」——「外层同名字段会遮蔽嵌入字段成员，相同层次的同名字段也会让编译器无所适从。解决方法是使用显式字段名」（L1567），示例 `User` 里 `name string // 遮蔽 Resource.name`（L1579）。

**论据**：现有 C# 无一条覆盖「内层作用域声明与外部同名的变量 / 字段（遮蔽），导致后续读写作用于内层对象而非外层对象」这一形状。C4 管「入参名与出参名相同但语义不同」（命名一致性），不管「同名遮蔽导致状态修改丢失 / 读取错误对象」；C35 管「同一表达式里多次读写同一变量且顺序未定义」，方向是求值顺序而非作用域遮蔽。这是跨语言可推广的形状：Go `:=` 在嵌套块定义同名变量遮蔽外层（`go vet` 无此检查，靠人注意）、Java 局部变量遮蔽字段、Python 函数内赋值遮蔽外层（UnboundLocalError）、JS `let`/`var` 遮蔽与提升、C/C++ 块作用域遮蔽。书中明言「该方式容易造成错误」「必须显式返回」「让编译器无所适从」——这是需要显式编码 / 命名的护栏。

**建议落点**：`conventions/coding-tables.md` §2 末尾新增 C40（最小 diff，接在 C39 后）。
