### 3. 创建型、结构型、行为型模式层

沿用《设计模式之禅 + HeadFirst》报告的 P1–P19 / C27 裁定，GoF 未推翻任何一条：

- 创建型：Abstract Factory → P6 反向约束；Builder → P14；Factory Method → P1/P2；Prototype → 低频，语言级拷贝；Singleton → T14 全局可变状态准入。
- 结构型：Adapter → P3；Bridge → P5+T3；Composite → P13；Decorator → P7；Facade → T3 深模块窄入口；Flyweight → T9 先测量 + T10 派生 / 副本 / 失效；Proxy → P10。
- 行为型：Chain → P9；Command → P8；Interpreter → T1 业务系统不自建语言 / 框架；Iterator → 语言内建；Mediator → 低频，错用即 F1；Memento → P11；Observer → T10/A4 失败语义与一致性；State → P5；Strategy → P4/P5；Template Method → P12+C27；Visitor → 低频，元素结构稳定且操作多变才值得讨论。
- 后半部新增精读重点：
  - State L10133–L10463：显式状态对象、状态转换归属、表驱动与 State 对象的取舍，归 P5（分支 / 表驱动）与 T14（状态可变性准入）。State 原子重绑只是实现策略，不跨语言立规。
  - Strategy L10464–L10790：算法族、可选策略、共享无状态对象、接口参数与耦合权衡，归 P4/P5/T14/C23。客户必须知道策略差异的反例由 P6/F1 承载。
  - Template Method L10791–L10969：算法骨架不变、步骤可变，归 P12；覆写纪律归 C27。GoF 的 hook / protected / final / Do- 前缀属于特定语言与低频框架实现细节，见下节。
  - Visitor L10970–L11452：新增操作易、新增元素难、双分派、遍历归属与破坏封装，未改变“低频不落”的裁定。

## 三、真缺口

**无。** GoF 相对既有两本模式书没有产生需要新增编号或改既有编号的产品级真缺口。

原因有三：

1. **原则层已经被更严的 idev 规则吸收。**“对接口编程”被 P6 收紧为“一种实现写具体类型”；“组合优于继承”已由 C27 + P4/P5 执行；“封装变化”被 T1/T3/T4/T7 和 P 表场景化，且 P6/F1 防止为想象中的变化付抽象税。
2. **23 个模式已被场景表收编。** 真源不复制 GoF 名录，而是按产品里真实会出现的约束落 P1–P19；低频模式不落，误用由 F1 拦。
3. **GoF 独有细节多是实现层或低频框架层。** State 的原子重绑、Strategy 的无状态共享、Template 的 hook 语义、Visitor 的双分派、C++ 访问控制 / 友元 / 析构，都不满足“当前 Go / Java / TS / Vue 产品仓通用且高频”的入真源条件。

## 四、重点裁定：Template Method 的 hook 细节不落（防后人重复发现）

GoF 最具体的一段新内容是 Template Method 的扩展契约：

- L10888–L10902：模板方法通过抽象操作 / 钩子操作扩展子类；必须让子类编写者知道哪些必须重定义、哪些可选扩展。
- L10908–L10924：子类直接覆写父类操作容易忘记调用继承行为；把扩展点收拢到父类模板方法调用的钩子，由父类控制扩展方式。
- L10925–L10933：C++ 里原语操作可 protected、模板方法可 non-virtual；可给须重定义操作加 `Do-` 前缀。

裁定：**不新增、不改 C27/P12。**

- P12 已经回答“算法骨架跟类型走”的场景准入；当前工程更常用组合 / SPI / 表驱动，Template 属低频路径。
- C27 已经扫继承结构：is-a 成立、层级 ≤2、覆写不弱化基类行为、前置 / 后置契约守约、尽量不覆写基类已实现方法。这覆盖 GoF 担心的“子类乱改流程、忘记继承行为”。
- T5 已要求名字能表达契约和变换方向，`Do-` 前缀只是某个 C++ 框架的命名约定，不足以跨语言立规。
- protected / non-virtual / final 属语言实现细节；Go、Java、TS/Vue 各自惯用形式不同。把它写进公共表会变成低频 API 细则，违反最小 diff 与不抄实现目录的边界。
