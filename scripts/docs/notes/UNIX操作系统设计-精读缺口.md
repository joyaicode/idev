> 源文本：`scripts/docs/notes/UNIX操作系统设计-全文.txt`（Maurice J. Bach《The Design of the UNIX Operating System》英文原版，485 页、484 页带文本层，经 macOS PDFKit 逐页提取）。本报告为第 110 本精读，也是本批 109 本源书的最后一本；对照 `conventions/canon.md`、`conventions/coding-tables.md` 裁定真缺口。

## 三、真缺口

### 1. 等待 / 唤醒契约（落 T10 DO）

**书中依据**：第 2 章 L1662–L1715 说明中断处理上下文不能睡眠；进程睡在事件上，唤醒后先进入 ready-to-run，`while-sleep` 循环保证被调度后重查条件，且多个等待者可能同时醒来又睡回去。第 6 章 L7670–L7808 进一步说明多个事件可能映射同一地址，唤醒只使进程可被调度，不保证事件条件仍成立。第 12 章 L16770–L16817 说明等待信号量成功后还必须重验设备号/块号是否仍是自己要的缓冲区；L16835–L16848 说明先查状态再等待的竞态要靠循环重查兜住。

**为什么是缺口**：T10 原文已有锁排序、临界区最小化、单线程先行与竞争条件测试，但没有说清三件通用契约：① 条件等待必须写在循环里，唤醒后重查条件；② 阻塞返回或条件抢占失败后，必须重验资源标识 / 关键字段仍匹配，不匹配则重来，防止地址/句柄复用造成 ABA；③ 中断、事件循环回调、信号处理等不可阻塞上下文不得睡眠或等锁，只能标记 / 入队并交给可阻塞上下文处理。现代 async、事件循环、线程池与分布式等待都会复现这三类错误。

**已落地**：T10 `DO` 与 §4「加锁 / 并发」已补「条件等待 / 唤醒 / 异步回调返回后循环重查条件与资源身份；不可阻塞上下文只能标记 / 入队」。

### 2. 缓存写回的持久化语义（落 T10 DO）

**书中依据**：第 3 章 L2548–L2607 说明 delayed-write 可减少磁盘流量并提升吞吐，但内核不立即落盘，系统在崩溃时可能留下不一致数据；用户调用 write 后不知道数据何时真正到磁盘，`fflush` 只把用户态缓冲交给内核，也不等于持久化。

**为什么是缺口**：T10 原文已有真相之源、派生/副本、失效策略与一致性等级，但没有要求把「对外可见点」「持久化点」「崩溃窗口」与 `flush/sync` 语义写清。缓存、写缓冲、异步持久化一旦只写成「性能优化」，调用方就容易把写入缓存误当成完成持久化；这是跨存储、前端状态缓存、消息系统与文件系统的通用契约。

**已落地**：T10 `DO` 与 §4「加锁 / 并发」已补「缓存写回写清对外可见点、持久化点、崩溃窗口与 `flush`/`sync` 语义；写入缓存不等于完成持久化」。

### 3. 最小授权边界与提权可回退（落 T4 DO）

**书中依据**：第 7 章 L9631–L9650 说明 `login` 以 root 有效用户完成认证后，把真实/有效用户恢复为登录目标用户；`mkdir` 以 root 权限完成目录创建，再把属主和权限改回真实用户。L9633–L9636 说明保存的用户 ID 用于恢复先前的有效用户，形成可回退路径。

**为什么是缺口**：T4 原文管依赖方向、显式契约与语义依赖，C31 管密钥与敏感数据，C19 管资源获取/释放，但没有覆盖「借来的身份/权限只用于单一必要动作，动作后立即恢复，并把提权/降权与审计点写进契约」。现代服务里的临时凭证、代理身份、sudo/assume-role、批处理代登录都会复现这类授权边界问题。

**已落地**：T4 `DO` 已补「权限提升走最小授权边界：只借必要权限完成单一动作，动作后立即恢复；提权/降权路径与审计点写进契约」。

### 4. 资源水位迟滞控制（落 T10 DO）

**书中依据**：第 9 章 L12402–L12412 说明内核在空闲页低于低水位时唤醒页偷取进程，直到空闲页超过高水位；高/低水位避免单阈值附近反复换入换出造成 thrashing，并降低页偷取进程运行频率。

**为什么是缺口**：T10 原文已有资源上限、并发与锁排序，T9 管先度量再优化，但均未要求控制类资源（缓存淘汰、扩缩容、连接池、队列消费、换入换出）使用迟滞区间。单阈值会让系统在临界值附近反复扩缩或淘汰，形成抖动；水位边界和恢复条件应显式成为契约。

**已落地**：T10 `DO` 已补「资源水位控制须有迟滞区间（高/低水位或等价机制），避免单阈值在临界值附近反复扩缩、淘汰或换入换出」。

## 四、重点候选裁定（防后人重复发现）

1. **进程状态机不另立，也不落 T14。** 显式状态与非法迁移应由 T3/T4 的边界契约、C23 的显式状态传递、C33 的状态机不变式承载；T14 管的是可变共享状态的准入与纯值默认，不是状态机建模。
2. **等待公平性 / 饥饿不另立。** 本书调度与唤醒说明公平性是真实问题，但工程上先由 T10 的等待契约、T9 的度量与 T12 的权衡记录决定目标与代价；把它写成通用「必须公平」会掩盖负载差异和调度策略选择。
3. **ABA / 资源身份复用不另立。** 已并入缺口 1 的「阻塞返回后重验资源标识 / 关键字段」；单独立条会拆散同一等待契约。
4. **锁粒度 / 争用权衡不另立。** L16859–L16877 说明同一驱动可用一把粗锁或按设备拆锁，粗锁更易理解、细锁可能更快但有交互风险；这由 T10 的并发权衡、T9 的基线度量与 T12 的记录权衡承载。L16917–L16936 的非线性扩展同理。
5. **中断不能阻塞不单独立条。** 已并入缺口 1；它是等待契约在不可阻塞上下文上的边界。
6. **调度优先级 + CPU 衰减不另立。** 是 T9「先正确清晰，再度量再优化」的具体实例。
7. **换出 vs 按需分页 + 驻留要求防抖动不另立。** 容量与度量仍由 T9/T10 承载；其中的通用缺口已并入第 4 条水位迟滞控制。
8. **IPC_NOWAIT / 条件 P 防死锁不另立。** 是 T10 等待、幂等、顺序与死锁权衡的具体实例。
9. **主从 vs 信号量、非线性扩展不另立。** 是 T9/T10/T12 的权衡与度量边界。
10. **透明分布式文件系统 / RPC vs 远程系统调用不另立。** 已由 A4 的真相之源、失败语义与一致性等级，加 T10 的异步与缓存权衡承载；透明性不能吞掉网络分区、超时和幂等语义。
11. **资源成对释放、失败向上传播、fsck 观测。** 分别已由 C19、C38、T11 承载。
