## 四、重点候选裁定（防后人重复发现）

1. **微性能调优 / 基准测试方法论不另立。** 「先度量再优化、测真实代码」已由 T9 与 §2 信号「无基线数字 → T9」承载；再加基准测试工具（Benchmark.js/jsPerf）会变成工具选型而非规范。
2. **回调信任问题（过早/过晚/次数/吞错）不另立。** 其本质是「异步调用要可观测、快速失败、不吞错」，已由 T8/T10/T11 承载；Promise 是语言机制。
3. **强制类型转换（显式/隐式）的可读性规则不另立。** 属语言机制；「可读性/求值顺序显式」已由 C24/C35/T5 承载。
4. **Web Worker / SIMD / asm.js 不另立。** 程序级性能机制，属语言/平台能力；「并发与优化权衡」由 T9/T10 承载。
5. **尾调用优化（TCO）不另立。** 语言/引擎优化机制；「收敛显式化」已由 C20 承载。
