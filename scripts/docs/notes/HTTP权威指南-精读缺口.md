## 一、精读范围

全书 21 章 + 8 附录读完，主区间如下（行号指 `HTTP权威指南-全文.txt`）：

- **第一部分 HTTP：Web 的基础（第 1–4 章）**：HTTP 概览、URL/URN、HTTP 报文（方法/状态码/首部）、连接管理（串行/持久/管道化连接、关闭容限、Content-Length 定界、幂等性与重试）。
- **第二部分 HTTP 结构（第 5–10 章）**：Web 服务器（单线程/多线程/复用 I/O 结构、docroot 映射）、代理、缓存（命中/未命中/再验证/新鲜度/条件请求）、网关/隧道/中继、机器人/蜘蛛、HTTP-NG。
- **第三部分 识别、认证与安全（第 11–14 章）**：客户端识别、基本/摘要认证、SSL/TLS 与数字证书。
- **第四部分 实体、编码和国际化（第 15–17 章）**：内容结构、国际化（字符集/语言标签）、内容协商与转码（Accept 系列首部、质量值）。
- **第五部分 内容发布与分发（第 18–21 章）**：虚拟托管、内容发布、重定向与负载均衡、日志与使用跟踪。
- **附录 A–H**：URI 方案、状态码、首部字段、MIME 类型、Base-64、认证方案、语言标签、字符编码。

重点复核段落：第 4 章 4.7.3「连接关闭容限、重试以及幂等性」（L4587–L4634，幂等定义与「一定不能自动重试非幂等方法」）、第 4 章 4.7.2「Content-Length 及截尾操作」（L4560–L4585）、第 7 章缓存再验证与条件请求（L6976–L7053、L7469–L7535）、第 17 章内容协商（L16598 起）、第 5 章服务器 I/O 结构（L5200–L5260）。

## 二、对照结论

### 1. 主体原则已被真源覆盖

| 书中主题 | idev 承载 | 结论 |
|---|---|---|
| 幂等性：事务执行一次还是很多次结果相同即为幂等；GET/HEAD/PUT/DELETE 幂等、POST 非幂等（4.7.3「如果一个事务，不管是执行一次还是很多次，得到的结果都相同，这个事务就是幂等的」L4608） | T10（失败语义「重试是否幂等、至少/至多一次」；DON'T「无幂等的重试」） | 承载 |
| 非幂等操作禁止自动重试，重试需人工确认或显式去重（4.7.3「一定不能自动重试非幂等方法或序列」L4613、「大多数浏览器都会在重载一个缓存的 POST 响应时提供一个对话框」L4616） | T10（DON'T「无幂等的重试」）/ C21（命令/查询分离） | 承载 |
| 非幂等请求不能管道化并发发送，须等待前一条响应（4.7.3「要发送一条非幂等请求，就需要等待来自前一条请求的响应状态」L4611） | T10（并发控制）/ C21 | 承载 |
| 乐观并发/丢失更新：条件请求（If-None-Match / ETag、If-Modified-Since）在更新前校验版本，防覆盖他人修改（第 7 章 L7469–L7535） | T10（「跨系统事务的并发编辑须明确离线并发策略：乐观（版本号/修改时戳）还是悲观（独占锁）」） | 承载 |
| 安全方法：GET 无副作用可反复执行，POST 有副作用（4.7.3「GET 一个静态的 HTML 页面，可以反复执行多次，也不会有什么变化」L4599） | C21（查询=不改状态、可安全重复调用；命令=改状态） | 承载 |
| 缓存必须有失效策略：新鲜度检测 + 再验证，不能无限缓存（第 7 章「这些『新鲜度检测』被称为 HTTP 再验证」L6978） | T10（DON'T「无失效策略的缓存」）/ T9（性能优化先测量） | 承载 |
| 连接管理：持久连接/连接池复用，不逐请求新建连接（第 4 章「持久连接是怎样消除 TCP 连接时延」L4490） | T11（「外部 HTTP/下游调用默认走持久连接与连接池复用，不逐请求新建连接」） | 承载 |
| 连接关闭容限：客户端必须做好连接任意时刻关闭、重发未完成请求的准备（4.7.3「HTTP 应用程序要做好正确处理非预期关闭的准备」L4591） | T11（外部依赖调用必带超时、快速失败）/ T10（重试是否幂等） | 承载 |
| Content-Length 精确性：每条响应应有精确长度，不依赖连接关闭来定界（4.7.2「每条 HTTP 响应都应该有精确的 Content-Length 首部」L4562） | C18（跨进程交换数据用显式定义的交换格式）/ C23（每步产出显式化） | 承载 |
| 状态码/错误分类：4xx 客户端错误、5xx 服务器错误，失败不吞掉（第 3 章 3.4 L368–L373） | C7（该失败就抛或 4xx/5xx）/ C38（失败向上传播） | 承载 |

## 四、重点候选裁定（防后人重复发现）

1. **幂等性（4.7.3）不单列。** T10 已承载（失败语义「重试是否幂等、至少/至多一次」+ DON'T「无幂等的重试」）。HTTP 的幂等定义（「执行一次还是很多次结果相同」）是 T10 该条的具体实例，不另立。
2. **非幂等操作禁止自动重试（4.7.3）不单列。** T10 DON'T「无幂等的重试」已承载；浏览器对 POST 重载弹确认框是 C21（命令/查询分离）的具体体现。
3. **非幂等请求不能管道化并发（4.7.3）不单列。** T10（并发控制）已承载；「有副作用的操作串行等待」是「重试是否幂等 + 并发控制」的推论。
4. **乐观并发/丢失更新（第 7 章条件请求）不单列。** T10「离线并发策略：乐观（版本号/修改时戳）还是悲观（独占锁）」已承载；If-None-Match/ETag 是「版本号」的具体协议形态。
5. **安全方法（4.7.3）不单列。** C21（查询可安全重复调用）已承载；GET 无副作用 vs POST 有副作用是 C21 的协议实例。
6. **缓存失效策略（第 7 章）不单列。** T10 DON'T「无失效策略的缓存」已承载；再验证/新鲜度是「失效策略」的具体机制。
7. **连接管理与关闭容限（第 4 章）不单列。** T11（持久连接/连接池/超时/快速失败）已承载。
8. **Content-Length 精确定界（4.7.2）不单列。** C18/C23 已承载（显式交换格式、产出显式化）；「不依赖隐式终止定界」是显式化的协议实例。
9. **状态码/错误分类（第 3 章）不单列。** C7/C38 已承载（失败就抛或 4xx/5xx、失败向上传播）。
10. **内容协商（第 17 章）不单列。** 协议课内容（Accept 首部/质量值），不进真源。
