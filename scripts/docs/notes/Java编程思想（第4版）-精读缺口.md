## 三、真缺口

### 构造器 / 初始化期间调用可覆写方法（部分构造状态执行子类版本）

**书中依据**：第 8 章「多态」§8.3.3「构造器内部的多态方法的行为」（约 PDF p184–212）。「如果在一个构造器的内部调用正在构造的对象的动态绑定方法，就要用到那个方法的被覆盖后的定义。然而，这个调用的效果可能相当难于预料，因为被覆盖的方法在对象被完全构造之前就会被调用」；示例中 `Glyph` 构造器调用 `draw()`，被 `RoundGlyph` 覆盖的 `draw()` 在 `radius` 尚未初始化时读到 0。书的准则：「用尽可能简单的方法使对象进入正常状态；如果可以的话，避免调用其他方法」「在构造器内唯一能够安全调用的那些方法是基类中的 `final` 方法」。

**落点**（已落地，`C32` 接在 `coding-tables.md` §2 末尾，§3.5 范围同步 `C1–C32`）：构造器 / 初始化中调用可覆写（可被子类 override 的 virtual）方法，子类字段未初始化即执行子类版本，读到默认值（0 / null / 空）——初始化期间只调 `final` / `private` / 本类明确不可覆写的行为；确需初始化逻辑，抽到 `final` 方法或显式 `init` 流程，不在构造器里触碰子类可覆写行为。

**效果**：把 C27 从「继承只用于 is-a、覆写守约」补到「初始化顺序也守约」。C27 管的是「该不该继承、覆写符不符合契约」，没管「构造器在对象半成品状态调用可覆写方法」这一初始化时序隐患——后者正是「对象在无关点才爆雷」的典型来源，与 T8「快速失败、失败不破坏状态」同向。

### 2. 测量方法须可信：预热、相对比较、优先剖析器

**书中依据**：第 17 章 17.10.3「微基准测试的危险」（约 PDF p544）。「编写微基准测试时，必须当心，不能做太多假设，并将测试窄化」；「确保测试运行足够长时间以产生有意义的数据，某些 Java HotSpot 技术只有在程序运行一段时间之后才会踢爆问题」；「不应该过于关心这些绝对数字，将其看作一种容器类型与另一种之间的性能比较」；「剖析器可以把性能分析工作做得比你好」。

**落点**（已落地）：[conventions/canon.md](../../../conventions/canon.md) T9「先正确清晰，再度量再优化」的 DO 增补一句：测量方法须可信——先预热、运行足够长时间以触发运行时优化（JIT/缓存等）；比较相对而非绝对数字；优先用剖析器定位热点，不为微基准自证。

**效果**：把 T9 从「要求基线数字与测量方法」补成「要求测量方法本身可信」。T9 现管「无基线不优化」，但没管「基线是手写微基准自证出来的、被 JIT 预热与绝对数字误导」——这正是「优化后测出假提升、撤销了真优化」的隐患。补这一句后，T9 的度量要求覆盖到测量方法论的可靠性，不新增编号、门禁或第二套测试框架。

## 四、重点候选裁定（防后人重复发现）

1. **`==` vs `equals` 不另立编号。** 第 3 章与全书反复强调「身份用 `==`、值比较用 `equals`」，但这是 Java 语言语义，Go / Python / TS 的 `==` 语义不同，不落多语言仓；`java.md` Qodana 表已按仓承载「用 `==` 比较对象内容」这一条。多语言仓只承载跨语言原则（值相等 / 身份相等写进契约见 T12）。
2. **操作符优先级不另立。** 第 3 章「忘掉优先权，在不是很清楚的时候使用圆括号」是通用可读性建议，已被 T3「码如文字」与 C24「业务 / 语法分层」覆盖；单独立一条是重复。
3. **向下转型 / instanceof 链不另立。** 第 14 章「如果程序中编写了许多的 instanceof 表达式，就说明你……」已被 P5（按类型分派收一处）与 C11（角色推断搬回类型方法）完整承载。
4. **受检 / 运行时异常分类不落。** 第 12 章受检异常机制是 Java 特有取舍，Go / Python / TS 无对应机制；「异常语义清晰、不滥用异常、不让程序沿正常路径继续」的原则已由 T8 / F4 承载（与《Effective Java》第 58/59 条裁定一致）。
5. **泛型类型擦除 / 通配符 / 自限定不落。** 第 15 章是 Java 5 泛型语法细节，属「语法课」而非「护栏」，`coding-tables.md` §3.6 明令归学习向 Skill；可提炼的跨语言原则（类型安全、命名、领域类型）已分别落到 T5 / C25。
6. **并发线程机制（Runnable / Executor / 锁）不落。** 第 21 章大部分是 Java 并发库用法；「共享可变状态危险、并发不可确定性」的纪律已由 T14 / T10 承载（与《Effective Java》第 66–73 条裁定一致）。
7. **「对象即服务提供者」不另立。** 第 1 章这一表述是 T3「深模块：接口小、内部厚」的通俗说法，已被承载。
