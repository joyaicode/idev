## 四、重点候选裁定（防后人重复发现）

1. **命名空间 / 模块模式不另立。** 命名空间是弱封装手段，现代模块系统（ES module / CommonJS）已替代；其要解决的「边界与命名冲突」由 T4/T5/T3 承载，不把历史库的命名空间写法固化成规则。
2. **类继承模拟（Crockford / Base / Prototype 库）不另立。** 属历史兼容层的实现细节；现代 JavaScript 的 class/prototype 语义是语言事实，不抄进产品仓。
3. **Unobtrusive JavaScript 不另立为独立条目。** 其本质是「内容/表现/行为分离」，已由 T4（依赖方向）与 C11（Mapping 只做形状）承载；再加一条会与既有条目重复。
4. **单元测试框架选型（JSUnit/J3Unit）不另立。** 测试维度的可执行要求已由 C26/C28/C29/C30 与 verify 阶段页承载；具体框架是工具选择，非规范。
5. **DOM 树导航 / 事件冒泡 / JS+CSS 技巧不落。** 纯教程内容，无工程缺口。

## 五、不建议落的内容

- 浏览器错误控制台与调试插件（Firebug/Opera/Safari）对比：工具教程。
- JSUnit/J3Unit 断言 API 目录：测试框架细节，已被 C26/C28/C29/C30 的维度要求覆盖。
- 书中具体案例（课程表、命名空间库、事件监听示例）：只作理解材料。
