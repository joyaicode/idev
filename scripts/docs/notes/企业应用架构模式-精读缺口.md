### 2. 候选裁定（防后人重复发现）

1. **特殊情况（Special Case / 空对象）不落。** 书中 L1049–L1054 主张「返回一个特殊情况子类而非空值，避免判空代码」。这与 P15「禁止 Null Object / 空省略」正面冲突——P15 要求查无结果按契约返回业务空集或抛错，禁返回 null，也禁空对象假装成功。本仓 T8（快速失败，禁静默兜底）与 C2（`default` 只承载显式合法缺省）同向。书中的空对象会掩盖「这里本不该缺值」这一事实，故不落。
2. **元数据映射（代码生成 vs 反射）不落成通用规则。** 书中 L794 起的元数据映射是 O/R 框架实现细节；本仓 T1/T8/P6/C13 已要求「配置必须有现有使用方、默认只写在显式配置」。把映射外置成元数据会鼓励无使用方的配置面膨胀，与 T1 冲突。
3. **插件（运行时配置）不落成默认架构。** 书中 L1054 起主张「配置时而非编译时连接类」。本仓 P5（Strategy 一处查表）、P6（只有一种实现写具体类型）、C13（配置默认只写在显式配置）已承载「按环境换实现」；把业务规则默认外置成插件会重蹈 T1 的「预留扩展点」。
4. **分布对象不落绝对规则。** 书中第 7 章「第一定律：不要分布你的对象」+ 远程外观/DTO（L3192–L3344，L908–L922）主张进程边界用粗粒度接口。§4「拆成微服务/拆库」已写「先粗粒度，边界拿不准就在单块内用模块画出来，稳定后再拆」；T4 管依赖方向，T11 管跨服务调用链。远程外观/DTO 是「先粗粒度」在进程边界的具体化，不另立。
5. **注册表（Registry）不落。** 书中 L1023 起虽承认注册表是全局数据、须「有罪推定」，但 T14 已管全局/静态可写字段的准入理由，再立一条会重复。
6. **记录集隐式接口不落。** 书中 L1063 起对隐式接口（`aReservation["passenger"]`）持反对态度，主张显式接口；C25 已要求领域概念建显式类型。不另立。
7. **继承映射三选一（单表/类表/具体表）不落。** 这是关系映射的机制选择，C27 已管继承守约（is-a 才继承、层级 ≤2、覆写收窄规则）；具体表/类表/单表的选择随 ORM 工具与查询模式变，不写成通用编码条。

## 三、真缺口

### 1. 跨系统事务的并发编辑要有离线并发策略（乐观版本号 / 悲观锁）

**书中依据**：第 5 章 5.5.4「业务事务和系统事务」（L2913–L2947）与第 16 章「离线并发模式」（L13072–L14202）。业务事务（用户一次编辑跨越多次请求）常常要拆成一系列短的系统事务，「只能自己为跨系统事务的业务事务提供 ACID 支持——我们称之为离线并发问题」（L2932–L2934）；「业务事务的 ACID 属性中最麻烦的是隔离性，没有隔离性就没有一致性」（L2947）。第 16 章给出两条路径：乐观离线锁「最常见的实现方式是为每条记录关联一个版本号……一个拿着旧版本号的会话无法获得乐观离线锁」（L13123–L13126）；悲观离线锁「假设会话冲突的可能性很大，从而对系统并发性进行限制」（L13115）。第 5 章 5.6 明确「处理离线并发问题的首选是使用乐观离线锁」（L2968）。

**现状**：T10 的「一致性等级」管的是分布式副本强/最终一致，§4「加锁/并发」管的是进程内线程锁，A4「一致性等级」同向；三者都没有覆盖「多个用户跨系统事务并发编辑同一记录」这一层——即更新丢失与不一致读发生在**业务事务**而非系统事务层面。

**落点**：[conventions/canon.md](../../conventions/canon.md) A4「数据真相之源、派生/副本、失败语义、一致性等级、Schema 演进」增补一项「离线并发策略（乐观版本号 / 悲观锁）」；或 T10 五项增补第六项「离线并发」。要求：凡有用户跨请求编辑共享记录、且业务事务无法压进单个系统事务的场景，`arch` 阶段 MUST 明确乐观（版本号/修改时戳）还是悲观（独占锁）策略，并写清冲突时的失败语义（回滚重试 / 提示谁在何时改过）。

**效果**：把「一致性」从分布式副本层扩展到「跨事务并发编辑」层，避免多用户编辑同一记录时静默丢失更新——这正是 T10「数据系统的问题几乎都出在五项没想清」里漏掉的一项。

**落地状态（已提交）**：本缺口已在 commit `f400181`（feat: land six engineering books deep-read guidance）落地，三处同时闭合——T10 DO（`跨系统事务的并发编辑须明确离线并发策略：乐观（版本号/修改时戳）还是悲观（独占锁），并写清冲突时的失败语义`）、§4 念头表「加锁/并发」（`跨业务事务并发编辑须写清乐观/悲观离线并发策略与冲突失败语义`）、A4 架构出门（`一致性等级（含跨系统事务并发编辑的离线并发策略）`）。`deep-read-audit.py` 与 `trigger-check.py` 均 PASS。
