## 三、真缺口

### 1. 表达式依赖隐式优先级 / 求值顺序，同一表达式多次读写同一变量

**书中依据**：第 2 章 2.2「运算符优先级有 15 个之多，因此记住它们并不是一件容易的事」（L876）；第 3 章 3.7「C 语言中只有四个运算符（`&&`、`||`、`?:`、`,`）存在规定的求值顺序……其他所有运算符对其操作数求值的顺序是未定义的」（L2067–L2078）；反例 `while (i < n) y[i] = x[i++];`「假设 y[i] 的地址将在 i 的自增操作执行之前被求值，这一点并没有任何保证」（L2090–L2093）。

**论据**：现有 C# 无一条覆盖「表达式依赖隐式优先级 / 求值顺序，读代码需查表才能确定含义」或「同一表达式里多次读写同一变量且顺序未定义」。这是跨语言可推广的形状（C/C++/Go/Java/JS 的 `a + b * c`、`f() + g()` 副作用、`y[i] = x[i++]`），且与 C23（多步调用间隐式状态）不同：C23 管「调用先后依赖隐式状态」，本条管「单个表达式内部的优先级与求值顺序」。

**建议落点**：`conventions/coding-tables.md` §2 末尾新增 C35（最小 diff，接在 C34 后）。

### 2. 条件 / 布尔上下文里赋值与比较混用（`=` 写成 `==` 或反之）

**书中依据**：第 1 章 1.1「由于程序员在比较字符和变量 c 时，误将比较运算符 `==` 写成了赋值运算符 `=`」（L503–L504）；「很多其他语言都使用 `=` 作为比较运算符，因此很容易误将赋值运算符 `=` 写成比较运算符 `==`」（L543）；纠正写法是显式比较 `if ((x = y) != 0)`（L518–L520）。

**论据**：现有 C# 无一条覆盖「条件 / 布尔上下文里 `=` 与 `==` 混用」这一形状。C2 管「`if (有值) 带上; else 省略`」的缺省分支，不管「赋值与比较符号混用」。这是 C/Go/JS（宽松相等）家族的经典陷阱，且书中明言「作为程序员不能指望靠编译器来提醒，毕竟警告消息可以被忽略」（L527）。

**建议落点**：`conventions/coding-tables.md` §2 末尾新增 C36（最小 diff，接在 C35 后）。

### 3. 整数运算可能溢出（signed 溢出未定义 / 静默回绕）

**书中依据**：第 3 章 3.9「当两个操作数都是有符号整数时，『溢出』就有可能发生，而『溢出』的结果是未定义的。当一个运算的结果发生『溢出』时，作出任何假设都是不安全的」（L2163–L2166）；反例 `if (a + b < 0) complain();` 不能检测溢出（L2170–L2175）；正确做法是边界检查 `if (a > INT_MAX - b) complain();`（L2228–L2230）。

**论据**：现有 C# 无一条覆盖「整数运算溢出」这一形状。C20 管「迭代 / 递归收敛依赖隐式状态变化」，C33 管「循环不变式」，都不管「算术运算的溢出与静默回绕」。这是跨语言可推广的形状（C 的 signed 溢出是 UB、Go/Java 静默回绕、Python 无界），且书中明言「作出任何假设都是不安全的」。

**建议落点**：`conventions/coding-tables.md` §2 末尾新增 C37（最小 diff，接在 C36 后）。
