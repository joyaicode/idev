## 四、重点候选裁定（防后人重复发现）

1. **「定义语言安全子集」不另立为独立条目。** 本书核心是“只写精华、弃糟粕”，其可执行落点是“避免静默兜底、避免隐式全局、只用共同支持的子集”，已分别由 T8/T14/F4/C16 承载；把“子集”本身立成通用规则会与 T1（先砍偶然复杂度）冲突，也难在多语言仓落地。
2. **`==` vs `===` 不另立。** 属 JavaScript 专有类型强制转换陷阱；其“避免隐式转换导致静默错误”的风险由 T8/F4 从更根本处管住，不把单语言运算符偏好抄进多语言真源。
3. **`with`/`eval`/`continue`/`void`/类型包装对象/位运算/`++`/`--` 不另立。** 均为 JavaScript 专有反模式或历史包袱；多语言规范不逐条固化单语言语法偏好，其“让作用域/类型/求值不可静态分析”的风险由 F2（幻觉依赖）与 T5（不猜 API）承载。
4. **JSLint 具体规则不另立。** 静态分析兜底已由 §3.7/§3.8 增强扫描与 C14 承载；具体 lint 选项是工具选择，非规范。
5. **继承的四种模式（伪类/原型式/函数化/部件）不另立。** 属语言机制；对象建模取舍由 T3/T4 与 P1–P19（场景→模式）承载。
6. **代码风格的具体排版（4 空格缩进、空格位置、每行一条语句）不另立。** 风格一致性由 T5/T2/F3 承载，具体排版是团队偏好，不固化成通用规则。
