- 信任边界与安全区数据检查 → T4（边界与依赖方向）、T8（入口失败语义）、A4（数据真相与一致性）、C31（敏感信息与密钥）组合承载；「多层消毒」不能作为普适命令，边界归属由架构决策决定。

**缺口集中在：**条件分派中 `switch` / `case` 的未列值处理。现有 T8 是快速失败总纲，C2 只写了 `if (有值) 带上; else 省略/默认` 的形状；P5 只回答「何时用 Strategy / 查表」，没有回答「default 分支能不能把未列值伪装成合法值」。这会让一个本该失败的未知枚举 / 未知命令进入正常路径，且比缺少 default 更隐蔽。

## 三、真缺口

### 缺口 A｜case/default 未列值不得伪装成合法缺省（C2 气味与纠正列增补）

**①出处：**第 14 章条件语句（全文提取件 L9720–L9736；L9858–L9889）。

**②论据：**「保证覆盖全部情况。最后用一个 else语句处理那些你未曾想到的错误信息」（L9720–L9721）；「若用缺省语句只用合法的缺省……这种做法有时虽很诱人，但却不足取。要这样你就没有利用 case语句的好处，并且失去利用缺省语句检查错误的能力」（L9858–L9863）；「用缺省语句检查错误。如果缺省语句不用作处理一些操作，也不支持某些情况，就把诊断信息放在里面」（L9868–L9872）；「或者最坏的情形，但结果是错误的却好像是正确的，直到检查到了为止……如果有进入 case语句的值不合法的，修改对应情况的语句，以便使缺省能真正检查错误」（L9885–L9889）。

**③建议落点：**coding-tables.md §2 C2「气味信号」和「纠正」列最小增补，不新增编号、不动 §3.5。

增补前：

`| C2 | if (有值) 带上; else 省略/默认 | 必要约束改为立刻抛错 / 400。禁止猜配置默认值、空对象 |`

增补后：

`| C2 | if (有值) 带上; else 省略/默认；case/default 把未列值当合法缺省 | 必要约束改为立刻抛错 / 400；default 只承载显式合法缺省，否则报未知值。禁止猜配置默认值、空对象 |`

**④与最相近条目的区别：**T8 给的是「非法输入快速失败」总纲，但没有点名 `switch` / `case` 的未列分支形状；现有 C2 只覆盖 `if/else` 的可选值补默认，不覆盖枚举 / 命令 / 类型分派中的 default；C7 管 `catch` 后吞失败，C13 管配置默认值，P5 管「何时换 Strategy / 查表」，都不管 default 的语义。本缺口补的是分派结构的未知值：default 只有两种合法用途——显式契约中的合法缺省，或报告未知值；不能顺手当成“其它都这么处理”的正常分支。

**落地状态（已提交）**：本缺口已在 commit `bef5291`（feat: land self-evolution and book distillation updates）落地——`conventions/coding-tables.md` §2 C2「气味信号」增补「`case/default` 把未列值当合法缺省」，「纠正」列增补「`default` 只承载显式合法缺省，否则报未知值」。`deep-read-audit.py` 与 `trigger-check.py` 均 PASS。

## 四、不建议落的（防后人重复发现）

- **语言级断言机制（预处理宏、开发期打开 / 生产期剥离、断言内不放可执行代码）**：Go 无 `assert`，Python `-O` 会剥离，TS / Java 需另建机制；原则层已由 T6 + C26 + F5 + domain-modeling.md 不变量断言承载。关键假设优先落测试与入口校验，不硬造跨语言断言机制。
- **「防火墙 / 手术室」的多重消毒流程**：边界检查归属是架构决策，不是每层都重复校验。T4 定边界与依赖，T8 定失败语义，A4 定数据真相，C31 定敏感数据；一刀切“多层消毒”会造成重复校验和规则漂移。
- **异常情况开发期报警、生产期日志可恢复**：T8 的降级三件套（范围 / 日志 / 指标）与 T11 可观测性已承载，且要求更完整。
- **检查最近修改过的子程序、怀疑历史出错子程序**：rootcause-guards 已把 `change` 列为一等证据类型，关键判断要求双证据；debug-repro 要求红绿切换。作为启发式不立规约，避免把“最近改过”当成免证根因。
- **80/20 错误集中、多次出错子程序应重写**：§3.2 已有“代码根本不能运作先隔离，再决定重构或重写”的判据；R7 管停止与回退。书中的比例是历史统计，不是可执行阈值。
- **测试心态：期望测试发现错误**：心理建议；T6 / F5 / C26 已把可执行部分（断言来源、非自证、一测一方向）落死。
- **PDL、布局、自说明子程序的机械格式规则**：工具 / 格式化层；C5 与底线 4 保留意图层，不复制排版规范。
- **goto / return / 递归 / 布尔表达式化简 / 循环控制变量技巧**：语言与工具层；原则由 C9、C1、圈复杂度 ≤10 与编译器 / linter 承载。
- **第 28–30 章代码调整技术目录**（字符串、循环、数据类型、缓存、强度削减等）：T9 已锁“先基线、测热点、小步、无提升撤销”；复制目录会违反 coding.md 不抄手法目录的边界。
- **项目管理、评审角色分配、检查表运营、性格与士气**：属流程 / 组织 / 心理叙事；现有 review 工作流、A 系列与 T12 已承载可工程化部分。
