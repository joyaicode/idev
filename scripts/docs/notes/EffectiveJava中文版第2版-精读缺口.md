## 三、真缺口

### 1. 对外暴露可变引用前先做保护性拷贝

**书中依据**：第 39 条「必要时进行保护性拷贝」（L6500–L6600 区间）、第 76 条「保护性地编写 readObject 方法」（L9600–L9700 区间）。「如果类具有从客户端得到或者返回到客户端的可变组件，类就必须保护性地拷贝这些组件」；「保护性拷贝是在检查参数有效性之前进行的，并且没有使用 clone 方法」；「对于 final 域，保护性拷贝是不可能的」。

**落点**（已于 12ab1c4 落地）：[conventions/canon.md](../../../conventions/canon.md) T14「可变性默认纯值」的 DO 增补一句：确需对外暴露可变引用（返回可变域、接受可变参数、存储外部传入的可变引用）时，先做保护性拷贝，拷贝在参数校验之前；拷贝后的对象由本类独占，外部无法通过别名篡改内部状态。

**效果**：把 T14 从「默认不可变」补成「边界处防别名攻击」。T14 现管「该不该引入可变状态」，但没管「可变状态已经存在、必须跨边界传递」时怎么办——这正是别名（aliasing）漏洞的来源：内部可变对象被外部引用篡改，破坏不变量。补这一句后，T14 覆盖从「准入」到「边界传递」的完整生命周期。

### 2. 失败的方法调用保持对象原状态（失败原子性）

**书中依据**：第 64 条「努力使失败保持原子性」（L8800–L8900 区间）。「失败的方法调用应该使对象保持在被调用之前的状态」；不可变对象天然满足；可变对象的常见手段是「在执行操作之前检查参数有效性」，或「先做临时拷贝再修改」。

**落点**（已于 12ab1c4 落地）：[conventions/canon.md](../../../conventions/canon.md) T8「快速失败，禁静默兜底」的 DO 增补一句：失败的方法调用应使对象保持在被调用之前的状态（失败原子性）——先校验后修改，或先做临时拷贝；抛异常时不允许对象停留在半修改状态。

**效果**：把 T8 从「快速失败」补成「失败不破坏状态」。T8 现管「非法输入立刻抛错」，但没管「抛错之前对象已经被改了一半」——这正是「抛异常但对象已处于半修改状态、将来在无关点才爆雷」的隐患。补这一句后，T8 的快速失败与状态一致性合并为一条可执行规则。

### 3. 抛出与抽象相对应的异常（异常翻译）

**书中依据**：第 61 条「抛出与抽象相对应的异常」（L8200–L8300 区间）。「如果方法抛出的异常与它执行的任务没有明显的联系，这种情形会让人不知所措」；「更高层的实现应该捕获低层的异常，同时抛出一种可以按照高层抽象进行解释的异常」，并保留原始异常作为 cause。

**落点**（已于 12ab1c4 落地）：[conventions/canon.md](../../../conventions/canon.md) T3「深模块：接口小、内部厚」的 DO 增补一句：对外抛出的异常类型与当前抽象对应，底层异常翻译成高层异常并保留 cause，不把下游实现细节（异常类型、内部错误码）泄露给调用方。

**效果**：把 T3 的信息隐藏从「调用方不必知道下游协议」补成「调用方不必知道底层异常类型」。T3 现管接口形状，没管异常面——异常是接口契约的一部分，底层异常直接穿透会破坏抽象边界。补这一句后，T3 的公开面最小化覆盖到异常这一契约维度。

## 四、重点候选裁定（防后人重复发现）

1. **错误细节消息含硬数据不另立。** 第 63 条要求异常细节消息「包含所有对该异常有贡献的参数和域的值（下界、上界、实际值），而非冗长描述」。T11 已要求「结构化日志、指标、告警条件」，且「跨服务调用链用同一关联标识贯穿并写入结构化日志」；「硬数据进日志」是结构化日志的内容要求，单独立一条会与 T11 的日志要求重叠。若后续真实排障发现「日志有关联标识但缺失败硬数据」，再按 T11 增补，不预先立。
2. **命名惯例不另立。** 第 56 条「遵守普遍接受的命名惯例」（类名名词、方法名动词、布尔 is/has 前缀、常量全大写）已被 T5「命名即设计」完整承载（T5 已含 `_ms` 量纲、`is_`/`has_` 布尔、`min_`/`max_` 边界、`get*` 成本暗示）。再立一条是重复。
3. **谨慎优化不另立。** 第 55 条「先有正确清晰的程序，再设法让它快」已被 T9「先正确清晰，再度量再优化」完整承载（含基线、目标、测量、无提升即撤销）。
4. **泛型 / 枚举 / 注解 / 序列化语言特性不落。** 第 5、6、11 章是 Java 5 语言特性与类库用法（原生态类型、通配符、EnumSet/EnumMap、注解、序列化代理），属「语法课」而非「护栏」，`coding-tables.md` §3.6 明令归学习向 Skill。多语言仓不承载单一语言特性；其中可提炼的跨语言原则（类型安全、命名、保护性拷贝）已分别落到 T5 / C25 / T14。
5. **受检 / 运行时异常分类不落。** 第 58、59 条是 Java 受检异常机制的取舍，Go/Python/TS 无对应机制，不落多语言仓；「异常语义清晰、不滥用异常」的原则已由 T8 承载。
6. **线程安全文档化不单独立条。** 第 70 条「文档化线程安全属性」已被 T12「契约变了文档同轮更新」与 T14「可变共享状态准入」承载；文档化线程安全是这两条的实例，不另立。
7. **不依赖线程调度器不落。** 第 72 条「不依赖线程调度器达到正确性或性能」是并发可移植性建议，与 T10「数据系统是权衡」的并发纪律重叠，且无独立可机检形状，不立。
