## 三、缺口汇总（AG1–AG13，按落点归组）

### conventions/evidence.md

**AG1 改指令/规则前先定位失败层**（ch01 L395；排查递进段并入）
改提示词、规则或 Skill 文案之前，先指出失败在哪一层——没说清（指令理解）、没看到（信息可达）、还是没接住（运行机制）；三层改法不同，不许先换提示词碰运气。

**AG2 自身轨迹摘要的事实档**（ch02 L1066；信任表新增一行）
从轨迹摘要、压缩产物或整理后 memory 里读出的事实性内容，要在原始证据里对得上才算数；两份摘要互相矛盾时并列存疑并回查原文，不择一采纳。

### conventions/canon.md

**AG3 权限检查沉到受信数据层**（ch05 L765–771；T4 DO 补句）
同一资源的授权检查不写在易被 Agent 重写的业务代码里，而沉到所有读写必经的受信数据访问层；生成代码出错也应被权限检查拦住。

**AG4 断言不得弱化为「事件发生过」**（ch05 L646/L658；F5「观察到」补形态）
断言弱化为「工具/检查被调用过」而不断言其性质与结果（先查后退、结果允许、最终状态），视为自证式测试的变体，当轮重写。

### references/self-evolution.md

**AG5 门禁收紧要附误拦对照**（ch01 L549；提案路径「依据」面）
收紧或新增门禁、规则的提案，要附一条不该拦的任务在收紧后仍能通过的对照；只证明拦得住，不证明收得对。

**AG6 摘要只对照原文写**（ch03 L602/L266；「清理执行产物」节边界句）
折叠摘要只能对照被折叠文件的原文写，不得在上一份摘要上再改写；摘要须保留否定、时间与适用条件，推论不得写成确定结论。

**AG7 从样本归纳必须写明样本范围**（ch03 L491–493/L711；「依据要能指出」清单加一项）
从一批轨迹或记录归纳出的规律，必须同时写明样本范围（哪些来源、多少条、时间窗）与未覆盖的部分；范围说不清的结论停在记录里，不进提案。

**AG8 等待约定的留痕与事后对照**（ch09 L315–317；「学习信号」末补一句，弱）
委派或巡检里写了等待约定的，约定本身进留痕；事后拿实际发生的事对照，才算可归因偏差进学习信号。

### references/agents.md

**AG9 执行者 description 按路由条件写**（ch02 L804；「再派一个执行者」节补句）
执行者定义文件的 description 写成路由条件——先写承接哪些步骤、不承接什么、由谁在什么信号下调用，不写成能力罗列。

**AG10 约束变更后旧结果不能只改参数套用**（ch06 L369–377；「这一轮之外到达的事」节补句）
用户中途改了条件后，先前跑出的结果只能当参考：条件影响到的取数或执行步骤从那一步重跑，不在旧结果上只改参数。

**AG11 轮末消耗总账**（ch10 L592–594；波次说明补一句）
同一波分片被取消或失败时，已跑完的片的留痕和耗时仍进 delegation timeline——预算按「曾发生」计，不按「被采用」计。

### references/agent-accuracy.md

**AG12 幂等键与外部副作用**（ch04 L429–435；「工具不改口」节补句）
会向外部产生副作用的命令，首次执行就生成幂等键并随重试沿用；键过期或对端不记得后，把这次当作新请求重新走确认，不直接重发。

**AG13 写状态与验证状态分开报**（ch04 L387–389/L457；「工具不改口」节补句）
本命令同时有写入与验证时，输出必须分开报两个状态：操作完成＝动作已发生；验证通过＝产物符合预期。写入成功但验证失败，不得报成一个笼统的成败值。

### verify/ 域

**AG14 断言放过什么（第 5 问）**（ch07 L191/L669 + ch08 L830/L866；plan-schema.md「case 可信度四查」补一问）
这条断言放过什么：写出能骗过该断言的最省事行为（全批通过、只动一个字段、只报完成不执行）；写不出反例的断言说明只覆盖了正路径。

**AG15 双向用例**（ch08 L824/L868/L894–896；verify SKILL.md plan 步补句）
修一类行为时，cases[] 须同时含「该出问题的情形」与「本应保持原样的情形」各至少一条；单向铺 case 的 plan 在 report 记 `单向风险`。

**AG16 判分口径分离**（ch07 L493/L469；rootcause-guards.md「决策步」补句）
决策步的 accept/forbid 只依 before 里当时可见的证据判；把只有事后才知道的信息写进 accept，check 拒绝时打 WARN 同 prefix 缺席同级。

### 其余（sediment / rootcause）

**AG17 验证材料实例级隔离**（ch08 L595/L812/L382；sediment.md「留下」清单补释义）
留下的复现还须与起草证据「题目面不相交」——同实例换路径跑出的第二份结果不算第二份证据。

**AG18 复现失败传递链分段**（ch08 L854/L856；agent-accuracy「根因：二分」维度表补一行）
工具参数/字符串级不一致 → 沿「文件原始字节→工具返回→序列化→上下文→生成→解码→解析→匹配」链找第一处意外差异，修复落在差异首次出现的那一层。

## 四、勘误与存疑（采信时注意）

- 实验 2-10 的 total_tokens 口径中途变更（累计输入→最近一轮输入），引用数字须先确认口径
- 实验 2-3 的 Hit% 按请求计数会掩盖按 token 计的 3 倍差距；多个实验样本量 n=1~5，只当方向性观察
- 第 10 章多处实验数字有归因陷阱：4 倍 token 混入协作组、缓存命中未测到、「单 Agent 等预算不输多 Agent」的反流行结论
- 后记「先改 Harness 留难题给训练」的时效论证（业务等不起下一轮训练）可作 evolve 提案依据引用
