## 四、重点候选裁定（防后人重复发现）

1. **eval / with「欺骗词法」不另立。** 本书明言它们是坏实践；但这是 JavaScript 专有反模式，idev 是多语言规范，不把单语言语法反模式固化成通用条目。其「让作用域不可静态分析」的风险已由 F2（幻觉依赖：不读源码就调用）与 T5（不猜 API）从更根本处管住。
2. **变量提升（hoisting）陷阱不另立。** 属语言机制；「先声明后使用」的纪律已由 T5（命名即设计）与可读性条目承载，不把 JS 提升规则抄进真源。
3. **this 绑定规则不另立。** 属语言机制；「this 指向不明导致误用」的风险由 T5（读源码/契约）与 F2 承载。
4. **原型继承 / Object.create / class 语法不另立。** 属语言机制；对象建模的取舍由 T3/T4 与 P1–P19（场景→模式）承载。
5. **IIFE / 模块模式的具体写法不另立。** 现代 ES module 已替代；其「边界与公开面」由 T3/T4 承载。

## 五、不建议落的内容

- eval/with 的逐条反模式清单：JavaScript 专有，不进多语言真源。
- 模块模式（IIFE/UMD/ES module）的历史实现目录：已被 T3/T4 承载。
- 书中具体案例（闭包机器人、循环 setTimeout、this 绑定示例）：只作理解材料。
