## 三、真缺口

### 1. 上下文关系模式显式选定

**书中依据**：Ch13-14 笔记 14-24/14-25（书行 11107–11150）。BOUNDED CONTEXT 关系模式两目的——协调多团队演化中的接触面、把现有关系用模式术语描述清楚再逐步收敛；每个限界上下文有名称并纳入统一语言。

**落点**：`conventions/domain-modeling.md`「限界上下文（可检查）」节新增：上下文间关系显式选定一种模式（SHARED KERNEL / CUSTOMER-SUPPLIER / SEPARATE WAY / OPEN HOST SERVICE / ANTICORRUPTION LAYER）并写进 arch 方案；每个限界上下文有名称、进术语表。

**效果**：把「划边界」从「按业务能力切」补到「划完还要显式选定上下文间关系模式」，避免边界划了但关系未定、演化中接触面失控。

### 2. 防腐层纪律

**书中依据**：Ch13-14 笔记 14-34～14-41（书行 11367–11520）。隔离层声明、FACADE、ADAPTER、Translator；转换成本直线上升时不得破坏模型完整性。

**落点**：`conventions/domain-modeling.md`「限界上下文（可检查）」节新增：集成外部 / 遗留模型走防腐层——FACADE 严格按对方系统模型编写、不改其模型，转换器隔离双向转换；模型完整性优先于省转换成本。

**效果**：把「集成外部模型」从「能通就行」补到「防腐层隔离、模型完整性优先」，防止外部模型的腐化渗透进领域模型。

### 3. 聚合不变量断言化

**书中依据**：Ch10-12 笔记 10-10/10-11（书行 8227–8274）。契约式设计断言只描述状态不描述过程、易分析易测；固定规则是严格定义的完整性规则，语言不支持就写成自动单元测试。

**落点**：`conventions/domain-modeling.md`「聚合根（可检查）」节新增：聚合不变量（固定规则）表述为断言——前置条件、后置条件、聚合整体的固定规则；语言不支持就写成自动单元测试（设前置 → 执行 → 查后置）。

**效果**：把聚合从「根实体 + 事务边界」补到「不变量显式断言化」，让完整性规则可分析、可测，不被过程式代码淹没。

### 4. P18 规格（SPECIFICATION）

**书中依据**：Ch8-9 笔记 9-26/9-27（书行 7236–7303，定义 7295–7297；三用途 7356–7359）；Ch10-12 笔记 10-27/10-28（书行 8755–8832，组合闭包）。SPECIFICATION 是「为特殊目的创建谓词形式的显式 VALUE OBJECT」，验证 / 选择 / 生成三种用途。

**落点**：`conventions/coding-tables.md` §1 表 P17 行后新增 `P18`：布尔业务规则长成巨型条件方法，或被上移应用层留下纯数据对象 → **Specification**：谓词形式的显式 VALUE OBJECT，可组合；规则内联进被约束对象、挪出领域层。

**效果**：把「业务规则」从「条件方法」补到「可组合的显式值对象」，与 VALUE OBJECT、ASSERTION 并列为声明式设计三模式。

### 5. P19 闭合操作（CLOSURE OF OPERATION）

**书中依据**：Ch10-12 笔记 10-21/10-22（书行 8571–8641：引出 8597–8600、模式陈述 8618–8626、VALUE OBJECT 优先 8627–8631、半个闭合 8634–8638）、10-28 组合闭包（8767–8832）、Share Pie 示例（9266–9270）。闭合性质简化理解、可链式组合；VALUE OBJECT 优先；「半个闭合操作」在多出的类型是基本类型 / 基础库类时同样减轻思考负担。

**落点**：`conventions/coding-tables.md` §1 表 P18 行后新增 `P19`：组合 / 推导操作的参数、返回类型拖入外来概念 → **闭合操作**：返回类型与参数类型（含实现者）相同，优先 VALUE OBJECT；凑不成全闭合时，多出的类型须是基本类型 / 基础库类；为消除依赖把接口削成只剩基本类型。

**效果**：把「组合 / 推导」从「参数返回类型随意」补到「闭合优先」，让推导操作可链式、可预测，不为消依赖削成贫血接口。

### 6. 借术语不改义

**书中依据**：Ch13-14 笔记 14-10（书行 10770–10776：假同源定义、Charge 例、embarazada 例）、14-2/14-6（10565、10573–10574、10679–10680：术语在模型上下文内总具有相同的意义）；Ch8-9 笔记 8-15（书行 6524–6532：「贷款投资」并非银行业术语）。

**落点**：`conventions/domain-modeling.md`「术语表模板」节 C15 对齐行后新增一句：借入他域术语整义移植——连同源域定义一起进表；同名异物 = 假同源，按术语漂移同级拒过；要改义先登记新定义，必要时换词。

**效果**：把「术语统一」从「同串对齐」补到「借入术语整义移植、假同源拒过」，防止跨域借词只借了字面没借定义。

### 7. 核心域识别与优先

**书中依据**：Ch15-17 笔记 15-1（书行 12422：「自主开发的软件的最大价值来自于对 CORE DOMAIN 的完全控制」）、15-3（12453–12455、12540–12542：通用子领域只增复杂度、不捕捉专门知识，可购买 / 外包）、15-3.1（12610–12614：精力优先投入核心域）、15-3.2（12674–12676：优先级上先完成 CORE DOMAIN）、15-8（13130–13140：SEGREGATED CORE 第一步识别核心子领域）。

**落点**：`conventions/domain-modeling.md` 新增「核心域与通用子领域（可检查）」节：arch 方案识别核心域（CORE DOMAIN）与通用子领域（GENERIC SUBDOMAIN）——写清哪部分是自主开发的核心价值（竞争优势所在）、哪部分是支持性通用部分（无专有知识，可购买 / 外包 / 复用）；精力优先投入核心域，不为通用子领域开发「万能」模型。

**效果**：把「本质问题一句话」（A1）与「砍偶然复杂度」（T1）补到「核心域 vs 通用子领域」的战略区分——把精力投向核心、支持性部分可购买 / 外包，不为通用子领域造「万能」模型。

### 8. A8 大比例结构与演化秩序

**书中依据**：Ch15-17 笔记 16-1（书行 13420–13422、13450–13452：大比例结构是一种语言，用高级概念为系统建立模式；大部分只是表达设计的另一种方式）、16-2（13510–13513、13525–13535：过早固定的架构随需求更改和理解深入使项目束手束脚；结构应随理解加深演化，不因「架构已定」拒绝调整）、17-4（15190–15200：战略设计更要简约，精简到只包含能显著提高设计清晰度的内容）。

**落点**：`conventions/canon.md` §5 A8 行增补「大比例结构（全局组织原则）只在能显著提高设计清晰度时引入，不过早固定、随理解演化（EVOLVING ORDER），不因“架构已定”拒绝调整」。

**效果**：把 A8 从「触发重新设计的条件」补到「全局组织原则只在显著提高清晰度时引入、不过早固定」这一非对称——A8 管「何时重设计」，本条管「大比例结构何时该引入、何时该拒绝过早固定」。
