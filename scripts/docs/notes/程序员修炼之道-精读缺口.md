## 三、真缺口

### 1. 估算先找参照物，进度随真实增量复估

**书中依据**：tip 18 / 19（L2588–L2734）。估算前先理解精度与范围；单位要传达不确定性；先问做过类似事情的人；项目进度不是开头一次定死，而是在每轮真实增量后提炼。

**落点**：[deliver/references/req-quality.md](../../../deliver/references/req-quality.md) 新增 §5「估算与进度迭代」。要求初始估算写参照物与假设；时间单位表达不确定性；每轮增量后用实际完成量重估剩余范围与迭代数。

**效果**：把“工作量可评估”从一次性故事点判断，补成可复估的交付过程，减少开局拍死进度和事后无法解释偏差。

### 2. 架构阶段先分析工作流并发与调用顺序

**书中依据**：tip 39–41（L5020–L5228）。时间耦合包括并发与次序；先分析工作流找出可并行与必须串行的边；接口不应依赖隐式调用顺序；对象在可调用时刻应保持有效状态。

**落点**：[deliver/SKILL.md](../../../deliver/SKILL.md) arch 步骤 5。多步骤业务流程或服务协作先分析工作流：标出必须串行的边；可并行事项不得因实现顺序变成隐式调用顺序；对象在任一可调用时刻保持有效状态。

**效果**：把 T3 / T4 / T10 / C23 的既有原则前移到架构方案阶段，避免把时间耦合留到编码或测试期才暴露。

### 3. 复现型测试先证明能红

**书中依据**：tip 64（L7460–L7605）。为特定 bug 写测试后，应故意触发 bug，确认测试会报警；这保证测试在真实回归出现时能抓住它。

**落点**：[verify/SKILL.md](../../../verify/SKILL.md) run 步骤 2。新纳入的复现型 / 回归型 case 首次 run 时，用已知坏输入或可回滚的最小还原缺陷证明目标断言能红一次；红灯日志进 evidence，恢复后同一 case 跑绿才写 PASS。普通既绿功能测试不强求破坏验证。

**效果**：只提高回归测试灵敏度，不引入第二套测试框架、破坏员角色或覆盖率门禁。

## 四、重点候选裁定（防后人重复发现）

1. **函数级合约 / 前条件 / 后条件 / 不变量不另立。** T8 已管非法输入快速失败；T13 已管契约语义变即换名；C23 已管多步隐式状态；C27 已管继承覆写时前置条件只能放宽、返回只能收窄；`domain-modeling.md` 已要求聚合不变量用断言或测试表达。再加“每个函数必须 DBC”会变成泛化口号，和语言 / 框架能力纠缠，误报大于收益。
2. **配置 / 元数据优先不落成通用规则。** 书中“抽象进代码，细节进元数据”适用于特定高变配置域；本仓 T1 / T8 / P6 / C13 已要求配置必须有现有使用方、默认只写在显式配置，P5 / P18 也已提供查表和 Specification。把业务规则默认外置成元数据，会直接鼓励无使用方的开关和配置面膨胀。
3. **独立项目破坏员不落。** 书中的破坏员是组织级实践；本仓只需要复现型 case 的断言红一次。引入专门角色会偏离当前最小流程，也不适合单人多角色场景。
4. **“总是为并发设计”不落绝对规则。** 本轮只在多步骤流程 / 服务协作的 arch 方案中要求工作流分析。真正引入并发仍走 T10 五项权衡与 T14 可变性准入，避免把所有小工具都推向并发复杂度。
5. **黑板模式不默认落。** 黑板适用于独立代理共享不规则知识流的特定场景。T4 / A5 / A8 已能承载边界与协作权衡；作为默认架构模式会引入不必要的共享状态和调度复杂度。
6. **纯文本、shell、编辑器、源码控制不另立。** 这些已由仓库文件形态、脚本体系、git 工作流和 `docs/SKILL.md` 内建；把工具习惯写成规约会重复环境事实。
7. **文档即代码不另立。** `docs/SKILL.md` 已要求文档内建、单一权威、同轮更新；本书 tip 67 / 68 的原则已被承载。
8. **项目组织与沟通技巧不落编码表。** 围绕功能组织团队、WISDOM 沟通模型、温和超出期望属于组织和产品判断；可执行部分由需求基线、grilling、trace 与 changelog 承载。
