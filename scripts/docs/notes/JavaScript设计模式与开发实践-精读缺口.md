### 4. JavaScript 语言特性不落真源

动态类型、鸭子类型（关注 HAS-A 非 IS-A）、原型委托继承、函数一等公民、this/call/apply、闭包与高阶函数，均为语言事实与理解材料，不构成可执行的工程缺口。

## 三、真缺口

**零缺口。** 本书 16 个设计模式、4 条设计原则与 11 条重构手法均已由 `coding-tables.md` P1–P19 / C1–C39 / R1–R7 与 `canon.md` T1–T14 承载；JavaScript 特有内容为语言事实，不落真源。

## 四、重点候选裁定（防后人重复发现）

1. **惰性单例 / 懒初始化不另立。** 惰性初始化是可变状态的一种引入方式，T14 已要求「引入可变状态只认共享实体或度量瓶颈两个准入理由」；单例本身归 P1/P6。再加「惰性」会变成性能微优化口号。
2. **享元模式的内部/外部状态分离不另立。** 其本质是「不可变共享 + 可变外部状态」，已由 T14（纯值优先）与 T10（数据系统权衡）承载；JavaScript 对象池是具体实现，非通用规则。
3. **好莱坞原则（别调用我们，我们调用你）不另立。** 控制反转已由 T4（依赖方向：业务核心不依赖框架）与 P4（多例 SPI/Strategy）承载。
4. **鸭子类型接口检查（typeof/instanceof 手写）不另立。** 属语言级类型检查手段；T5（读源码/契约不猜字段）与 F2（幻觉依赖）已管住「不读契约就调用」的更根本问题。
5. **表驱动状态机不另立。** P5 已给「Go：表驱动 `map[Kind]func`；Vue/TS：对象字面量查表」的落点；状态机是它的一个实例。
6. **「少用三目运算符」不落硬规则。** 三目运算符本身不坏，坏的是嵌套与隐晦；C9（嵌套 ≤2）与 T5（布尔谓词命名）已覆盖其真正风险。
