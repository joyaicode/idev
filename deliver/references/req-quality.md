# 需求质量判据（INVEST / SMART / 验收量化）

`req-review` 与 `req` 阶段的**判据补强**。这些是给 grilling 拷问用的可检查标准，**不替代 grilling**：边界不清、有冲突、方案分叉仍先跑完整 grilling 轮次（见 [deliver/SKILL.md](../SKILL.md) 硬规则 2a）。本页只回答「拷问到什么程度算够、验收写成什么样算可证伪」。

密封基线仍是尺。本页判据服务于「把需求写成可拷问、可证伪」，不引入分数、不做通过率评估。

---

## 1. SMART 成功指标（req-review 起草 goal 时）

每个业务目标至少一条可量化指标，格式：

```
指标名 | 当前值 | 目标值 | 测量方法
```

- ✅ `列表首屏耗时 | 2.4s | ≤1s | Chrome Performance 面板 P95`
- ❌ `提升性能`（无当前值、无目标值、无测量法）
- ❌ `用户体验更好`（不可测量）

无法给测量方法的"目标"是待拷问项，写进 `grill.md`，不写进 baseline `items`。

---

## 2. INVEST 用户故事判据（req 拆解 slice 时）

每条 slice / 用户故事过下表；不满足的维度 → `open_questions`（只问理解）或 `baseline-conflict`（想加义务时停）。

| 维度 | 通过标准 | 可测量判定 |
|------|----------|------------|
| **I**ndependent | 无依赖或依赖可管理 | slice 依赖图无环 |
| **N**egotiable | 细节可协商 | 有"可调整空间"说明，非写死实现 |
| **V**aluable | 对用户有直接价值 | 能对应 goal 里某条 SMART 指标 |
| **E**stimable | 工作量可评估 | 能说出触及模块 / 影响面（接 arch case_intents） |
| **S**mall | 单轮可完成 | 故事点 ≤ 5；> 8 必拆（见 §4） |
| **T**estable | 验收可自动化 | 有对应 verify case 意图（挂 `baseline_item_id`） |

INVEST 不满足**不等于**改基线——只回退到拷问理解，答案不得写成新 must（守 deliver 硬规则 4）。

---

## 3. 验收标准量化规则

验收标准必须可被 verify case 红/绿切换：

- ✅ `输入 X → 输出 Y（具体值 / 具体状态）`
- ❌ `输出：合理的结果`（模糊）
- ❌ `输出：用户友好 / 体验流畅 / 性能良好`（主观，不可测）

含主观词（合理 / 友好 / 流畅 / 尽量 / 大概）的验收 = 待拷问项，拷问到可证伪再密封。

---

## 4. 需求反模式（拒过并拷问，不默许）

| 反模式 | 信号 | 处理 |
|--------|------|------|
| 故事过大 | 故事点 > 8 / 一条 slice 跨多个能力 | 拒过，拆成多条 slice（每条挂各自 `baseline_item_id`） |
| 验收模糊 | 含主观词、无具体值 | 拒过，拷问到 §3 可证伪格式 |
| 需求冲突 | 与已密封 item / CONTEXT / ADR 矛盾 | 拒过，写成 `grill.md` 的问句；冲突不得默许（deliver `req-review` 硬规则） |
| 解决方案冒充需求 | goal 里写"用 Redis 缓存"而非"首屏≤1s" | 拒过，剥回业务痛点（方案归 arch） |

---

## 5. 估算、承诺与进度迭代（req 拆解与增量复估）

- 初始估算先找参照物：做过同类事的人、历史票、同类系统或可测量数据；写清假设与范围。找不到参照物就标 `UNPROVEN`，不编单点数字。
- 预估不是承诺。被要求承诺结果或日期时，只承诺自己可掌控的具体行动；依赖他人的最终结果不隐性背书，也不用“试试看”制造暗示性承诺。
- 时间单位要传达不确定性：短粒度用天，中期用周，长期用月或里程碑；报乐观 / 标称 / 悲观、区间或条件句（“若 X，则…”），不用高精度数字伪装确定。
- 进度不在项目开头一次定死。每轮真实增量完成后，用实际完成量重估剩余范围和迭代数；偏差原因写进本轮记录，作为下一次复估输入。
- 预估与已定 deadline 冲突时，当轮说明不能达成，并列出缩范围、替代方案或需要的决策；预计错过承诺或日期时，立即报告风险、原因、剩余范围和可选项，不等截止日才暴露。

## 出门（接 gates.md）

- **req-review**：goal 有 SMART 指标；验收无主观词；无 §4 反模式未清。
- **req**：每条 slice 过 INVEST；> 8 点已拆；未新增基线外义务。

判据命中不写分数、不算通过率；只回答"这条能不能被 verify 红绿切换"。不能 → 继续拷问，不密封。
